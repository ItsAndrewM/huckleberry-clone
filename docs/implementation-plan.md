# Baby tracker — implementation plan

Implements spec **v0.10 (approved 6 October 2026)**. Section references (§n) and acceptance criteria (AC n) point at the spec. This plan follows the spec's delivery order (§12) and splits each milestone into tasks small enough to review as single PRs.

---

## 0. Decisions this plan makes

These either fill gaps in the spec or pick between options it leaves open. Each one says why. Anything here can be overturned in review before M1 starts.

| # | Decision | Why |
|---|---|---|
| D1 | **All API routes live under `/api/*`.** WebSocket at `/api/ws`. | The spec's API paths (`/today`, `/days/:date`) collide with the obvious SPA routes. A prefix also lets Static Assets serve the SPA and send only `/api/*` to the Worker first (`run_worker_first: ["/api/*"]`). |
| D2 | **Every mutation runs as one synchronous function inside `ctx.storage.transactionSync()`.** Effect `http-api` handles decoding, encoding and errors at the edge; the core reads, checks invariants, and writes without any `await`. | The invariants in §3 rely on the Durable Object serializing writes. A synchronous transaction cannot interleave with another request, whatever the HTTP layer does with promises. It also keeps the core testable without Effect. The spike confirms `@effect/sql-sqlite-do` does not get in the way. If it does, fall back to `ctx.storage.sql` with a thin typed helper. |
| D3 | **Feed components (segments, portions) are versioned through their parent feed.** Any change to a segment or portion increments `feeds.version`. `PATCH /segments/:id` and `/portions/:id` take the feed's version. `PUT /api/feeds/:id` (M3.4) replaces a finished feed's sides and bottles in one save under its version: the parts it replaces stay as deleted rows, and its D9 check skips the feed's own old sides, so a switch can move earlier in one save. | §8 gives `nursing_segments` and `bottle_portions` no `version` column, but §3 requires every edit to be version-checked. AC 13 (two phones switch side at the same moment) also needs one version for the whole feed. A per-component version would let two segment edits race against the session-bound recompute. |
| D4 | **Add `source` (`app` / `import`) and `source_ref` to every tracking table, with a partial unique index on `(source, source_ref) WHERE source = 'import'`.** M2 was dropped (10 Oct 2026), so every row is `source = 'app'`. The tables through `0006-growth` keep the columns, so a raw-row export stays uniform. Tables added later may leave them out. | §10 requires idempotent re-import "with source row id", but §8 has no column for it. |
| D5 | **The Durable Object resolves identity.** The Worker verifies the Access JWT in `Cf-Access-Jwt-Assertion` with `jose`: RS256 only, issuer = the team domain, audience = the app's AUD tag, keys from `<team>/cdn-cgi/access/certs`. It uses `ctx.access` instead when the runtime provides it, which `vite dev`, `vite preview` and `wrangler dev` do through `access.dev`. It then deletes any client-sent `x-bt-*` headers, sets `x-bt-email` from the verified identity, and forwards to the single household DO (`getByName("household")`). The DO looks up `caregivers` by email and checks `active` on every request. | §8 puts `caregivers` in the DO, so the Worker cannot map email to caregiver without a round trip. Doing the lookup in the DO keeps the per-request `active` check (AC 10) in one place. The JWT check is needed because Workers with Static Assets never receive `ctx.access`: the assets router does not forward it (Cloudflare docs; confirmed in the spike). |
| D6 | **Disable a caregiver with an admin script, not UI.** `pnpm admin caregiver:disable <email>` sends an HTTPS request to `/api/admin/*` with a Cloudflare Access service token kept on Andrew's machine. The Worker accepts `/api/admin/*` only when the verified JWT's `common_name` equals that service token's Client ID, never a caregiver identity, and forwards it to a DO admin RPC method. Service-token JWTs carry the Client ID as `common_name` and an empty `sub` (confirmed in S5). On disable, the DO closes that caregiver's tagged sockets with code 4401 (confirmed in the spike). `pnpm admin caregiver:enable <email>` undoes a disable (decided 9 Oct 2026): the seed runs once, so nothing else could. `pnpm admin caregiver:set-email <current> <new>` moves a caregiver to another email, keeping their id and entries, for a mistyped seed or a new Google account (decided 10 Oct 2026). | The spec requires the capability but describes no UI. With two users, an admin screen is not worth building. |
| D7 | **`today` and `last24h` are invalidated by every mutation.** For other periods the server works out the affected keys with `affectedPeriods(oldInterval, newInterval, tz)` from `packages/domain`. | This is always correct and cheap at this data volume. Working out exactly when Today is affected is error-prone and saves nothing. |
| D8 | **`supplement_logs.local_date` is recomputed for every row in the same transaction as a household timezone change.** Editing `occurred_at` also recomputes it. | `local_date` is stored, so a timezone correction would otherwise leave the duplicate check and daily status using stale dates. |
| D9 | **No two non-deleted nursing segments may overlap, across all feeds** (one child, one breast-at-a-time). Overlap with sleep, diapers, and so on is allowed. | §3 says to "reject overlapping segments" without saying in what scope. |
| D10 | **Restore re-runs every invariant.** A restore that would break an invariant, such as a second active sleep or an overlap, returns 409 with the conflicting record. Where a partial unique index stands behind a check, as `feeds_one_active` does for the active feed, the check runs first, so a violation is a defect, answered with a logged 500 and nothing written (decided in M1.7). A restore also re-runs the birth-date check a new entry gets, so an entry dated before the birth date stays deleted, refused with `before_birth` (M3.5, decided 12 Oct 2026). | Soft-deleted rows are excluded from the checks, so bringing one back can create a conflict. |
| D11 | **Ambiguous local times (DST fall-back) in manual entry show a two-choice "1:30 (first) / 1:30 (second)" picker. Nonexistent times (spring-forward) are rejected with a message.** No other DST UI. | §5 requires explicit offset selection for repeated times but defers the grid labels. This is the smallest form-level version. |
| D12 | **Tooling:** pnpm workspaces, TypeScript strict, oxlint (lint, with the anti-slop and `@gamesheet-inc/oxlint-plugin` rules) and oxfmt (format), Vitest, `@cloudflare/vitest-plugin` for Worker/DO tests, Playwright (WebKit + Chromium, iPhone viewport) for E2E. Time zones via `@date-fns/tz` and `date-fns`, inside `packages/domain` only. | These are conventional, fast, and run in CI without devices. |
| D13 | **Prefill values come from the server** in `GET /api/today`: last bottle amounts and milk mix and last nursing side. Today's doses of each supplement come as `doses` (M3.3). | Prefill then follows whichever parent logged last, and the client needs no local storage. |

## 3. Cross-cutting foundations (built in M1, used everywhere)

### 3.1 `packages/domain`

Pure functions. Each takes `now` and `tz` as arguments; nothing reads the clock or the device timezone.

- `time/` — `Instant` (epoch ms, UTC), `LocalDate`, `zonedDayBounds(date, tz)`, `localDateOf(instant, tz)`, `isoWeekBounds`, `monthBounds`, `isoWeekDates(week)` (seven dates, Monday first; M3.6), `monthDates(month)` (the 1st to the last; M3.6), `resolveLocal(dateTime, tz) → {kind: 'ok'|'ambiguous'|'nonexistent', ...}` (D11), `startOfDate(date, tz)` (the first instant of a local date, which isn't always 00:00), `canonicalTimeZone(name)` (seed script, Settings). Functions that take a date, week, month or zone string throw `RangeError` when it isn't real; `canonicalTimeZone` returns `null` instead, and `isLocalDate`, `isIsoWeek` and `isYearMonth` return a boolean, so callers can test a string without catching. ISO weeks are worked out in plain UTC arithmetic (M3.10). Playwright's clock replaces the global `Date`, which breaks `TZDate`, a `Date` subclass, so in the E2E specs date-fns read the page's own zone and refused every week outside UTC. A phone's own `Date` was never affected.
- `interval/` — half-open `[start, end)` intervals: `overlaps`, `contains`, `splitByDays(interval, tz)`, `clipTo(period)`.
- `timer/` — `nursingElapsed(segments, now)` (sum of closed + open), `sleepElapsed(session, now)`, `formatElapsed`.
- `feed/` — `feedSummary(feed, now)` → left/right/total seconds, breast-milk/formula/total mL. `sessionBounds(components)`.
- `sleep/` — `SLEEP_KINDS` (nap, night) and `sleepKindAt(startedAt, tz)`: a sleep that starts from 19:00 to 06:59 on the household's clock is a night, any other a nap. The phone labels each new sleep with it, and the label is stored, so the past never relabels itself (M3.1).
- `aggregate/` — `totalsIn(period, entries, now)` totals any period's `{ feeds, diapers, sleeps }` (M3.1): a local day (`zonedDayBounds`) or the last 24 hours (`last24hPeriod`, which has no end). `totalsByDay(dates, tz, entries, now)` totals each day of a week or a month, and `sumTotals(days)` adds them into the period's totals, so a table of days always adds up to its total (M3.6). `feedTouches(period, feed, now)` says whether a feed touches a period through one of its parts: a segment that overlaps it (a running one up to now) or starts in it, or a bottle in it (M3.6). `sleepTouches(period, sleep, now)` does the same for a sleep (M3.1). The cumulative series is `trends/`'s `runningTotals` (M3.10). Doses aren't totalled: each period lists its doses, and Today's Supplements card reads today's (M3.3). Nursing and sleep are allocated by interval overlap with the period, a sleep's into nap and night time by its label. Bottles are allocated by portion time. Feeds and sleeps are counted by their start, and a period's longest sleep is the longest that started in it, counted whole, so a week's or a month's is the longest of its days' (M3.1).
- `validate/` — positive volume (≤ 1 decimal, finite), positive duration, end > start, not before birth, `notInFuture(instant, serverNow, toleranceMs = 5 min)`, ounces ∈ [0, 16).
- `units/` — g ↔ lb+oz, cm ↔ in using the exact constants. Values are stored at full precision and rounded for display only. Bottle volumes convert between mL and US fl oz and are stored to 0.1 mL.
- `growth/` — `girlsLms(metric, ageDays) → {L, M, S} | null` from the bundled WHO tables, days 0–730 (M4.1), `ageInDays(measuredOn, birthDate)` (whole calendar days between two local dates: chronological age, decided 10 Oct 2026) and `ageInMonthsAndDays(measuredOn, birthDate)` (calendar months, then days, or `null` before the birth date: M4.5's table), `zScoreLMS(value, lms)` with WHO's restricted application beyond ±3 SD, `percentile(z)` (the normal CDF, 0–100), and `zScoreFor` and `percentileFor(metric, sex, ageDays, value) → number | 'unavailable'`, which take weight in grams and lengths in cm (M4.2, `docs/percentiles.md`), and `valueAtPercentile(metric, sex, ageDays, percentile)`, `percentileFor`'s inverse, which draws WHO's 3rd, 15th, 50th, 85th and 97th curves in the same units (M4.5).
- `calendar/` — `layoutDay(input, scale)` lays a day out for History (M3.7). It draws one row per real hour inside the household's day bounds: fewer when the clocks go forward, and more when they go back a whole hour or more, with each repeated hour marked; on Lord Howe's half-hour changes one row runs 90 minutes, giving 23 rows going forward and 24 going back. History gives it a feed as one block, from its first part to its last, with each side as a band inside it. Blocks sit in lanes (half-open, stable sort by start, end, then id) and are cut at the day's edges. Markers that would overlap gather into one. Everything is in steps of `scale.stepMs`: a block is at least `minBlockSteps` tall and a marker `pointSteps`. `slotIn(row, fraction, now)` gives the quarter hour a tap lands on, or nothing after now. `onWallClock(day)` moves a day onto the household's wall clock for History's Week view (M3.8), so every column has the same 24 rows: on a day the clocks change, both passes of a repeated hour share its rows, a skipped hour stays empty, a side whose clock goes back as it ends is drawn from its start, and a feed's block still covers each of its sides. History lays a day's sleeps out in a second pass, as blocks with no bands, for a column of their own beside the hours, so a feed never shares its lanes with a sleep (M3.2).
- `invalidation/` — `affectedPeriods(old: Interval | null, new: Interval | null, tz) → PeriodKey[]` (D7): the day, week and month keys. A point event is `{start: t, end: t}`.
- `trends/` — `dayStatus(day, today, birthDate)` says whether a day counts toward an average: it has ended, isn't before her birth, and has a feed, a diaper or a sleep (M3.1), which is any of their totals above zero. Otherwise it's today (so far), a finished day with nothing logged ("No entries"), a day before her birth, or one still to come. `averageDay(days, today, birthDate)` averages the days that count and says how many, or `null` when none do; on a day that counts, a missing kind is a real zero. `runningTotals(period, entries, now)` climbs through a day for feeds started, nursing seconds, bottle mL, diapers and sleep seconds: a step for each feed, bottle and diaper, a slope while a side is nursed or she sleeps, rounded down once for each side and once each for the naps and the night. Its last point is exactly `totalsIn`'s total (M3.10, M3.2).

`pnpm coverage` (in CI) holds this package at 100 % statement, branch, function and line coverage. It is small, and most correctness lives here.

### 3.2 `packages/contracts`

- Effect Schemas for every request/response, plus `ApiError = Unauthorized | InvalidInput{fieldErrors} | NotFound | Conflict{code, current} | RateLimited | ServiceUnavailable`. M1.3 builds the shared pieces: `Instant` (integer epoch ms in 2000–2099), `LocalDate`, `IsoWeek` and `YearMonth` (years 1999–2100), `TimeZone`, the errors and the query keys. Each endpoint's schemas come with the task that builds it. M1.6 adds `Version` (an integer from 1) and `VersionedAction` (`{actionId, version}`), the body of every delete and restore. A conflict is declared per record type, with `Conflict<Self>()(identifier, codes, current)`. The identifier names its schema in `docs/api.json`, and every conflict still says `Conflict` on the wire. `fieldErrors` is a list of `{path, issue}`, where `issue` is a domain `ValidationIssue` or `invalid`.
- M3.4 adds `FeedEdit`, the body of `PUT /api/feeds/:id`: `NewFeed`'s sides and bottles with the feed's `version`.
- Stable conflict codes: `FEED_ALREADY_ACTIVE`, `SLEEP_ALREADY_ACTIVE`, `SLEEP_OVERLAP`, `SEGMENT_OVERLAP`, `STALE_VERSION`, `SUPPLEMENT_DUPLICATE_DAY`, `FEED_EMPTY`, `ACTION_REPLAY_MISMATCH`.
- Query-key builders, shared by the server's `changed` list and the client's invalidation: `['me']`, `['today']`, `['last24h']`, `['day', '2026-10-06']`, `['week', '2026-W41']`, `['month', '2026-10']`, `['growth']`, `['deleted']`. The day, week and month keys are `@bt/domain`'s `PeriodKey`.
- Today's `recent` is `RecentEntries` (M1.11): it skips any entry the app can't read, such as a kind added after the app was built, as the socket's `changed` keys do. An installed app running older code then still shows Today.
- `OpenAPI` generated from the http-api definition and checked into `docs/api.json` as a review aid. `pnpm api:docs` writes it, and a test fails while it's stale. The http-api definition starts in M1.5, with `GET /api/me`.

### 3.3 Durable Object core

- **Migrations:** numbered SQL files applied in the DO constructor inside `blockConcurrencyWhile`, tracked in a `_migrations` table. A household whose ledger names a migration differently from the code, at the same position, refuses to start. Migration 0001 creates the household, caregivers, child and receipts tables. Each feature then adds its own numbered migration with its tables, D4 columns, partial unique indexes and `*_at` indexes (decided 8 Oct 2026, since §8 isn't in the repo). Interval tables also get a composite index on `(started_at, ended_at)` for the day-intersection query `started_at < :end AND (ended_at IS NULL OR ended_at > :start)`. Feeds, whose bottles are points that can sit at a session's end, select with `ended_at >= :start` instead and keep only those with a live part in the period (`feedTouches`, M3.6), while an interval-only table such as sleeps keeps `>`.
- **Seed:** an admin script (`pnpm admin household:seed`) creates the household (name, timezone), two caregivers, and the child profile with name, birth date, sex = female, and gestational age = 281 days. It seeds once; running it again changes nothing. Local runs seed a made-up household from `env.local` in `wrangler.jsonc`. Nothing in source holds production child values; they are passed as script arguments.
- **Mutation pipeline:** `decode → identity (caregiver active) → transactionSync(receipt lookup by actionId; if found return the stored response, otherwise run core, compute changed keys, and insert the receipt) → respond → broadcast {changed} to every open socket`, the caller's own included, so a parent's other devices hear the change too (decided 9 Oct 2026). Each receipt stores its route (`METHOD /path`) and a hash of the route and the canonical request body. An `actionId` that comes back on another route gets 400 `InvalidInput` on `actionId`. A hit with the same hash returns the stored response. A hit with a different hash means the parent edited the form after a save whose response was lost. That returns 409 `ACTION_REPLAY_MISMATCH` with the saved record, and the UI says "This was already saved as you first entered it." and offers to apply the new values as an edit (M1.13: "Save my changes" for a diaper, and for a bottle that is its own feed; since M3.4 also for a past feed, through `PUT /api/feeds/:id`, while a started feed or a bottle added to a running feed says it was saved as first entered). Rotating the `actionId` on edit is wrong, because it would create a duplicate if the first save had committed. A receipt hit with the same hash also rebroadcasts its stored `changed` keys, so a retry repairs a broadcast lost when the original request died after commit. A hit with a different hash, or on another route, broadcasts nothing. The receipt is written in the same transaction as the mutation, so a crash between them cannot leave a mutation without its receipt.
- **Clock:** core functions take `now`, and the DO reads `Date.now()` where a request or alarm comes in. Tests pin it with Vitest's fake `Date`, which reaches the DO in the test pool.
- **Receipts:** stored with the serialized response and its `changed` keys. They are pruned with a DO alarm, rescheduled every 6 h, that deletes rows older than 24 h. The client's retry window for one `actionId` is **12 h**, half the retention: a form draft older than that, or an entry kept on the phone (M5.6) whose `actionId` was first kept that long ago, gets a fresh `actionId`, whose own 12 h start then, and asks the parent to confirm before saving ("This wasn't saved before you signed in, {weekday and time}. Save it now?", or for a kept entry "This wasn't saved, {weekday and time}. Save it now?"). Retention is always longer than the retry window, so a pruned receipt can never be replayed.
- **Audit:** `created_by/at` is set on insert. `updated_by/at` are set on every update, including soft delete and restore. `version + 1` applies to the tables that have a `version` column, which include the household and the child from M1.15. Edits to `nursing_segments` and `bottle_portions` increment the parent `feeds.version` instead (D3).

### 3.4 Web client foundations

- `api/client.ts`: Effect's `HttpApiClient`, built from the contract's `Api`, so each endpoint's path, payload and errors come from `contracts` (M1.10). It always sends `redirect: 'manual'` and `credentials: 'same-origin'`, and maps outcomes to `AuthRequired` (opaqueredirect), `Offline` (TypeError, no response), `ServiceUnavailable` (a 503: retry, don't sign in again), or the endpoint's own typed `ApiError`.
- `api/connectivity.ts`: one store with the states `online | offline | auth-required`, fed by fetch outcomes, `online`/`offline` events, and socket state. It also remembers when the household last answered a request or spoke on the socket, which No connection shows as "Updated 9:42 PM" (M5.4). That time is held back to when a query on screen fell behind (invalidated, or its fetch failed) until the household answers it again, so it never runs ahead of what's shown. A household 401 and the socket's 4401 also mean signed out, and offline wins over auth-required, since signing in needs the network (M1.10). It drives the "No connection" bar and the "Sign in to continue" banner. When a save fails because the sign-in expired, the sheet's own "Sign in" saves the entry to `sessionStorage` as `{route, sending, createdAt}` before navigating (M1.12; the banner's Sign in sits under an open sheet). "Sign in" does a top-level navigation to `/api/login?return=<current route>`. Access intercepts that request, runs Google sign-in, and sends the browser back to `/api/login`. The Worker handles `/api/login` once authenticated: it accepts `return` only if it is a same-origin path (otherwise `/`) and 302s there. The SPA loads at that route and takes the draft. Within the 12 h retry window (see Receipts) it re-sends it once with the same `actionId`; an older draft reopens its sheet and asks "Save it now?" before sending it under a new `actionId` (M1.12).
- TanStack Query: `staleTime` ≈ 5 s, `refetchOnWindowFocus`, `refetchOnReconnect`, and `networkMode: 'always'` so failures surface as our typed errors. `useMe` compares the email with the previous one and, on a change, drops every cached query but `me` (M1.10). When the household's time zone changes, by this phone's save or the other phone's, the phone invalidates every cached day, week and month, since each was cut by the old zone's midnights (M3.6).
- `api/live-connection.ts`, with `api/live.ts` (M1.10): connects on app start and reconnects with capped exponential backoff (1 s → 30 s, with jitter), at once when the browser comes back online. On `{changed}` it calls `invalidateQueries` for each key it can decode, skipping kinds it doesn't know. A message it can't read invalidates everything. After a reconnect it invalidates everything active. It sends the heartbeat (`ping`, which the household answers with `pong` without waking) every 30 s, and drops a socket whose ping is still unanswered at the next beat. A 4401 close stops it and signs out.
- Optimistic creates (M1.12): a diaper, a bottle, a past feed, a started feed and a bottle added to a running feed go into the `today` cache at once under a `pending:<actionId>` id, and today's totals move by `totalsIn`; the recent list shows "Saving…". ### 3.5 Shared timer engine (web + server)

- **Server:** timer state is rows (D2/D3). A feed's segments and a sleep each have their own store, since a sleep is one row and a segment is part of a feed. They share the domain's `Span`, its validation and `FUTURE_TOLERANCE_MS`, so a running side or sleep reaches 5 minutes past now in every overlap check, and the core's `errorAt` and `invalidUnless` (`core/fields.ts`, M3.1).
- **Client:** `useNow()` (M1.11) is a clock that ticks as each second begins, read through `useSyncExternalStore`. Elapsed time comes from the server's timestamps through `feedSummary` and `formatElapsed` for a running or paused feed; the time since the last feed counts from its `startedAt`. The clock only redraws. TanStack Query's `refetchOnWindowFocus` refetches on `visibilitychange → visible`; nothing there sends a mutation. `scripts/page-lifecycle.test.ts` (M1.12) fails on any `pagehide`, `beforeunload` or `visibilitychange` handler anywhere in `apps/web/src`. Switching to a saved new version when the app comes back (#61) subscribes to TanStack Query's `focusManager` rather than adding a handler, and sends nothing.
- Shared UI: the Nursing sheet's views (M1.12): start, with the last side tagged; running, with Switch, Pause, Add bottle and Finish; paused, with Resume; and the finish step, which corrects the stop time no earlier than the running side's start, where stopping at the start drops that side and asks "Delete this feed?" if nothing else is left. M1.11's feed card shows a running or paused feed.
- The shared lifecycle test suite (§6, AC 20) is `apps/worker/test/timer-lifecycle.test.ts` (M3.1). It runs a nursing feed and a sleep through the same cases: a start, Today counting up, a stop, one running at a time, 5 minutes of clock skew (AC 21), two phones' stops (AC 13) and a timer across midnight (AC 4, AC 12).

## 5. Key server flows (reference for M1.7 / M3.1)

**Switch side** — `POST /api/feeds/:id/switch {actionId, version, occurredAt}`, where `occurredAt` is the tap time

1. Look up the receipt; if present, return the stored response.
2. In the transaction: load the feed. If `version` ≠ the current version → 409 `STALE_VERSION` with the feed as it is now, deleted or not. A deleted or completed feed with the current version → 404.
3. Find the open segment (none if paused → 404, since the version was current: M1.6's order of refusals). Check `occurredAt` > segment start and ≤ now + 5 min.
4. Run the D9 overlap check on the new segment, which counts as reaching 5 minutes past now. Close the open segment at `occurredAt` and insert one for the other side there. Recompute session bounds. Increment `version`.
5. Store the receipt. Respond with the feed and `changed`. Broadcast.

Two simultaneous switches: the DO runs them one after the other. The second carries the old version and gets 409 (AC 13).

**Edit a whole feed** (M3.4) — `PUT /api/feeds/:id {actionId, version, segments, portions}`

1. Look up the receipt; if present, return the stored response.
2. Load the feed. A version that isn't current → 409 `STALE_VERSION` with the feed as it is now. A running, paused or deleted feed with the current version → 404: the Nursing sheet changes a running or paused feed.
3. Check the parts as a new feed's (each time, each side's end and length, no two sides at once), except that a time the feed already holds skips the time checks (the birth date and the future), since it passed them when it was saved. Run the D9 check against every other feed's sides.
4. Mark the feed's live sides and bottles deleted, insert the ones sent, recompute its bounds and increment `version`.
5. Store the receipt. Respond with the feed and `changed`, which covers its days before and after. Broadcast.

**Start sleep while one is active** → 409 `SLEEP_ALREADY_ACTIVE` with the session → the UI offers "Wake at …" (with stop-time correction) or Cancel.

**Edit segment time across midnight** → validate ordering and overlap, recompute feed bounds, then `changed` = today, last24h and `affectedPeriods` of the feed's session before and after the edit, which covers both segment intervals. AC 7 and 18 check both days.
