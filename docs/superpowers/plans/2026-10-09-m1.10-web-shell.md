# M1.10 Web Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (chosen by Andrew on 9 Oct 2026) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Both parents open the app to a calm shell. It has Today, History, Trends, Growth and Settings tabs, and light and dark themes that follow the phone or a choice in Settings. A "No connection" bar shows while offline, and a "Sign in to continue" banner when Access signs them out. A socket refetches whatever the other parent changes.

**Architecture:** `apps/web` gains four layers, each tested on its own:
- `src/api/`:
  - `connectApi` wraps Effect's `HttpApiClient`, built from the contract's `Api`, so every endpoint's path, payload and typed errors come from `@bt/contracts`.
  - It fetches with `redirect: "manual"` and `credentials: "same-origin"`. It reads Access's sign-in redirect as `AuthRequired`, a fetch that never reached the network as `Offline`, and a 503 as `ServiceUnavailable`.
  - Each outcome is a signal to `createConnectivity`, a small store that says `online`, `offline` or `auth-required`.
  - `startLive` keeps the household's socket open: a heartbeat, capped backoff, `changed` keys decoded one at a time, everything refetched after a reconnect, and a stop on 4401.
  - `createQueryClient` and `meQuery` hold TanStack Query's defaults and the signed-in caregiver.
- `src/theme/`: System, Light or Dark, kept per phone in `localStorage`. CSS tokens written with `light-dark()` follow the phone with no JavaScript. A choice sets `data-theme` on `<html>`, which a script in `index.html` applies before the first paint.
- `src/shell/` and `src/features/`: TanStack Router with code-based routes, the tab bar, the banners, the stubs, and the theme picker in Settings. They're built from shadcn components on Base UI (`src/components/ui/`) and Tailwind v4.
- `src/main.tsx` wires them together: one connectivity store, one API, one query client, one socket, one router.

## Decisions this plan makes (veto in review)

- **P1: The client is Effect's `HttpApiClient`, built from the contract's `Api`.** This is the first option in the M1.3 handoff ("build each call's error union from the http-api definition").
  - Every endpoint's method, path, payload encoding, success decoding and error union comes from `@bt/contracts`. M1.12's 13 feed endpoints then cost a line each: `api.request((client) => client.feeds.startFeed({ payload }))`.
  - `connectApi({ report, baseUrl?, fetch? })` returns `{ request }`. `request(call)` builds the client, runs `call`, classifies the failure (P2) and reports a signal (P3).
  - Fetches always go out with `redirect: "manual"` and `credentials: "same-origin"`, through `FetchHttpClient.RequestInit`. Tests inject `fetch` through `FetchHttpClient.Fetch`, so nothing needs `vi.mock`.
  - Cost: measured with esbuild, the client adds about 19 KB gzip over plain `fetch` plus Schema decoding. Effect Schema is needed either way to decode the contracts. See P14.
- **P2: What each outcome means.**

  | The response | Becomes | Why |
  |---|---|---|
  | status 0, an opaque redirect | `AuthRequired` | Access redirects a signed-out fetch to its cross-origin sign-in page (S3) |
  | a fetch that throws (`TransportError`) | `Offline` | It never reached the network (S3) |
  | 503 | `ServiceUnavailable` | The Worker answered while Cloudflare's keys or the household were out of reach: retry, don't sign in again (the M1.4 and M1.5 handoffs) |
  | a status the endpoint declares (401 `Unauthorized`, 400 `InvalidInput`, 409 `Conflict`, 404 `NotFound`) | that error, decoded | The contract's own types |
  | any other status, or a body that doesn't decode | `Unexpected { status }` | `status` is `null` when no response decoded |

  Effect reports an undeclared status as `DecodeError` and a declared one whose body doesn't decode as `StatusCodeError`; both carry the response.
- **P3: Connectivity is two facts shown as three states.**
  - The facts are the network (online or offline) and the session (valid or expired).
  - Offline wins over `auth-required`, because signing in needs the network. Coming back online shows "Sign in to continue" again if the session had expired.
  - The signals:

    | Signal | Sent by | Network | Session |
    |---|---|---|---|
    | `reached` | any answer from the household | online | valid |
    | `unreachable` | a fetch that threw | offline | unchanged |
    | `signed-out` | an opaque redirect, a household 401, a 4401 close | online | expired |
    | `online` | the browser's `online` event, a socket opening, any message from the household | online | unchanged |
    | `offline` | the browser's `offline` event | offline | unchanged |

  - Fetches own the session.
    - A refused upgrade reaches the browser only as a 1006 close (the M1.9 handoff), so the socket can't tell signed-out from offline. Letting its opening mark the session valid would make the state depend on which answered last.
    - The 4401 close is the one socket signal about the session.
  - A household 401 means an unknown or disabled caregiver. Signing in again, perhaps with the other Google account, is the only way out, so it's `signed-out` too.
- **P4: Query defaults.**
  - `staleTime` is 5 s, with `refetchOnWindowFocus` and `refetchOnReconnect`, as §3.4 says.
  - `networkMode: "always"`, so a failure surfaces as one of P2's errors instead of a paused query.
  - Queries retry only `ServiceUnavailable` and an `Unexpected` 5xx, up to 3 tries, with TanStack's default backoff. Offline, signed-out and 4xx answers don't retry: a reconnect, the next focus, or the socket's refetch-after-reconnect brings the data back.
- **P5: Another caregiver signing in on the same phone resets everything cached except `me`.** The cached data is dropped, and any screen on show refetches (`resetQueries`; Task 4's review found `removeQueries` left mounted screens on the last caregiver's data, or pending).
  - `meQuery`'s fetch compares the new email with the cached one, so no state lives outside the cache.
  - §3.4 said `queryClient.clear()`. That would also drop the fresh `me` and refetch it at once; keeping it avoids the extra request and an empty flash.
- **P6: The shell reads `me` on every page.** A stale session is then noticed wherever the parent is, and on every return to the app more than 5 s after the last fetch. Today reads the same query for the child's name, and there's one request for both.
- **P7: The live socket (`api/live.ts`, `api/live-connection.ts`), from §3.4 and the M1.9 handoff.**
  - **Opening:** it opens `SOCKET_PATH` on the page's own origin, `wss:` under `https:`.
  - **Retrying:** after the n-th failed attempt in a row it waits `min(30 s, 1 s × 2ⁿ)`, then takes up to half of that off at random. The count resets once a socket opens. The browser's `online` event reconnects at once (`wake`).
  - **Heartbeat:** it sends `ping` every 30 s. A ping still unanswered at the next beat abandons the socket and reconnects; the household answers in milliseconds, so two beats is a dead socket. The household doesn't need to hear that close.
  - **`changed` messages:** each key is decoded on its own, and a kind this app doesn't know is skipped. A message that isn't a readable `{"changed":[...]}` refetches everything, as the M1.3 handoff advises. The M1.9 handoff's "ignore anything else" means no other message types exist to handle.
  - **Refetching everything:** whenever a socket opens after a failed or dropped one, so changes missed meanwhile appear. That includes the first open after a boot while unreachable (Task 3's review: a `lost` flag replaced the plan's "first open" rule). A first open that follows no failure doesn't refetch, since the queries have just loaded.
  - **4401:** it stops for good and reports `signed-out`.
  - Its own changes come back too (M1.9's P1), costing one extra refetch per save.
- **P8: How the theme works.**
  - The choice is System, Light or Dark, kept per phone in `localStorage` under `bt.theme`. System removes the key.
  - Every colour token is `light-dark(light, dark)` under `color-scheme: light dark`, so System follows the phone live without JavaScript.
  - Light or Dark sets `data-theme` on `<html>`, which pins `color-scheme`.
  - A classic script in `index.html` applies a stored choice before the first paint, so a phone in Light mode set to Dark never flashes white at night. Task 5's E2E test proves it with the app's JavaScript blocked.
  - `dark:` matches both an explicit Dark and System on a dark phone, for shadcn's own `dark:` classes.
  - Tailwind's build (lightningcss, targeting Safari 16.4 and Chrome 111) lowers `light-dark()` to custom properties switched by `prefers-color-scheme` and `data-theme`, so the built app needs only iOS 16.4. Native `light-dark()` (Safari 17.5) matters only to the dev server (found in Task 1).
- **P9: The look: calm and night-friendly** (Andrew, 9 Oct 2026).
  - **Colours:** warm off-white and charcoal by day; warm near-black with off-white text at night (not pure white, to cut glare); one muted huckleberry violet as the accent.
  - **Type:** the system font (SF Pro on iPhone).
  - **Tap targets:** at least 44 px. The tab bar is 56 px tall, and `lg` buttons and toggles are 44 px.
  - **Contrast (WCAG):**

    | Pair | Light | Dark |
    |---|---|---|
    | text on background | 15.3 | 12.8 |
    | muted text on background | 6.3 | 7.4 |
    | muted text on muted | 5.8 | 6.3 |
    | accent on background | 6.7 | 9.0 |
    | text on accent | 6.7 | 8.6 |
    | destructive on background | 5.5 | 6.7 |

- **P10: shadcn, set up by hand from its `nova` style on Base UI** (`shadcn init -b base -p nova`, version 4.21.4).
  - `components.json` lets `pnpm dlx shadcn@4.21.4 add <component> -c apps/web` add more later. Each file it writes needs this plan's lint edits.
  - Class names merge through `cn` 0.4.0, shadcn's own package with no dependencies, which its generated files import directly.

    - no `"use client"`; `ComponentProps` imported from React
    - no `style` prop: ToggleGroup's `spacing` is dropped

## Review Focus

1. **Access signs a parent out while the app is open**, because the 730 h session ended or a sign-in was revoked. Expect "Sign in to continue", not "No connection" and not a blank screen. Signing in should return to the same page, signed in. Tested in Task 2 (status 0 is `AuthRequired`) and Task 6 (the round trip, on WebKit and Chromium).
2. **The phone loses its connection, perhaps after the session also expired.** Expect "No connection" while offline. Then expect "Sign in to continue" if the session is gone, otherwise nothing. Tested in Task 2 (offline wins, and the session survives a reconnect) and Task 6 (offline and back).
3. **The household is briefly unavailable**, for example a 503 while Cloudflare's keys are out of reach. Expect no sign-in prompt and a quiet retry. Tested in Task 2, Task 4 (the retry policy) and Task 6 (a 503, then the page loads).
4. **A socket dies without a close**, from a phone asleep in a pocket or a network switch. Expect the heartbeat to drop it within two beats and reconnect with capped backoff. Once back, everything refetches, so changes made meanwhile appear. Tested in Task 3 and Task 7.
5. **A caregiver is disabled with the app open, or the other parent signs in on the same phone.** On a disable (4401), expect the sign-in banner and no reconnect loop. On a new caregiver, expect nothing cached from the last one. Tested in Task 3 and Task 7 (4401), and Task 4 (a new caregiver).

### Task 1: Tailwind, the calm tokens, and the theme choice

> Changed in review (CodeRabbit, PR #15): `storedTheme` and `applyTheme` take a function that opens the storage, since reading `localStorage` throws when the browser blocks storage. A failed read means System, and a choice that can't be saved still marks the page. `index.html`'s script catches the same failure. `theme.test.ts` has six more tests (12), and `theme.spec.ts` has one more. The committed files are the reference.

**Files:**
- Modify: `pnpm-workspace.yaml`, `vitest.config.ts`, `apps/web/package.json`, `apps/web/vite.config.ts`, `apps/web/tsconfig.json`, `apps/web/index.html`, `apps/web/src/main.tsx`
- Create: `apps/web/vitest.config.ts`, `apps/web/src/index.css`, `apps/web/src/theme/theme.ts`

**Interfaces:**
- Produces, in `apps/web/src/theme/theme.ts`:
  - `THEMES = ["system", "light", "dark"] as const` and `type Theme = (typeof THEMES)[number]`
  - `THEME_KEY = "bt.theme"`, which the script in `index.html` also reads
  - `storedTheme(storage: Pick<Storage, "getItem" | "setItem" | "removeItem">): Theme`
  - `applyTheme(theme: Theme, storage, root: Pick<HTMLElement, "dataset">): void`

```ts
export type Theme = (typeof THEMES)[number]

export const THEME_KEY = "bt.theme"

type ThemeStorage = Pick<Storage, "getItem" | "setItem" | "removeItem">
type ThemeRoot = Pick<HTMLElement, "dataset">

const isChosen = (value: string | null): value is "light" | "dark" => value === "light" || value === "dark"

export const storedTheme = (storage: ThemeStorage): Theme => {
  const stored = storage.getItem(THEME_KEY)
  return isChosen(stored) ? stored : "system"
}

  if (theme === "system") {
    storage.removeItem(THEME_KEY)
    delete root.dataset.theme
    return
  }
  storage.setItem(THEME_KEY, theme)
  root.dataset.theme = theme
}
```

```ts
export type Connectivity = "online" | "offline" | "auth-required"

export type Signal = "reached" | "unreachable" | "signed-out" | "online" | "offline"

interface State {
  readonly network: "online" | "offline"
  readonly session: "valid" | "expired"
}

const NEXT = {
  reached: () => ({ network: "online", session: "valid" }),
  unreachable: (state) => ({ ...state, network: "offline" }),
  "signed-out": () => ({ network: "online", session: "expired" }),
  online: (state) => ({ ...state, network: "online" }),
  offline: (state) => ({ ...state, network: "offline" }),
} satisfies Record<Signal, (state: State) => State>

const connectivityOf = ({ network, session }: State): Connectivity => {
  if (network === "offline") return "offline"
  return session === "expired" ? "auth-required" : "online"
}

export interface ConnectivityStore {
  readonly current: () => Connectivity
  readonly subscribe: (listener: () => void) => () => void
  readonly report: (signal: Signal) => void
}

export const createConnectivity = (online: boolean): ConnectivityStore => {
  let state: State = { network: online ? "online" : "offline", session: "valid" }
  const listeners = new Set<() => void>()
  return {
    current: () => connectivityOf(state),
    subscribe: (listener) => {
      listeners.add(listener)
      return () => {
        listeners.delete(listener)
      }
    },
    report: (signal) => {
      const before = connectivityOf(state)
      state = NEXT[signal](state)
      if (connectivityOf(state) === before) return
      for (const listener of listeners) listener()
    },
  }
}

export const followBrowser = (store: ConnectivityStore, target: EventTarget) => {
  target.addEventListener("online", () => store.report("online"))
  target.addEventListener("offline", () => store.report("offline"))
}
```

```ts
import { ServiceUnavailable, Unauthorized } from "@bt/contracts"
import { Data, Schema } from "effect"
import { HttpClientError } from "effect/http"
import type { Signal } from "./connectivity.ts"

export class AuthRequired extends Data.TaggedError("AuthRequired") {}

export class Offline extends Data.TaggedError("Offline") {}

export class Unexpected extends Data.TaggedError("Unexpected")<{ readonly status: number | null }> {}

const OPAQUE_REDIRECT = 0
const SERVICE_UNAVAILABLE = 503

const statusOf = ({ reason }: HttpClientError.HttpClientError): number | null => {
  switch (reason._tag) {
    case "StatusCodeError":
    case "DecodeError":
    case "EmptyBodyError":
      return reason.response.status
    default:
      return null
  }
}

const fromHttpClient = (error: HttpClientError.HttpClientError) => {
  if (error.reason._tag === "TransportError") return new Offline()
  const status = statusOf(error)
  if (status === OPAQUE_REDIRECT) return new AuthRequired()
  if (status === SERVICE_UNAVAILABLE) return new ServiceUnavailable()
  return new Unexpected({ status })
}

export const classify = <E>(error: E | HttpClientError.HttpClientError | Schema.SchemaError) => {
  if (error instanceof HttpClientError.HttpClientError) return fromHttpClient(error)
  if (error instanceof Schema.SchemaError) return new Unexpected({ status: null })
  return error
}

export const signalOf = <E>(error: E | AuthRequired | Offline | Unexpected): Signal | null => {
  if (error instanceof AuthRequired || error instanceof Unauthorized) return "signed-out"
  if (error instanceof Offline) return "unreachable"
  if (error instanceof Unexpected && error.status === null) return null
  return "reached"
}
```

```ts
import { Api } from "@bt/contracts"
import { Effect, type Schema } from "effect"
import { FetchHttpClient, type HttpClientError } from "effect/http"
import { HttpApiClient } from "effect/http-api"
import type { Signal } from "./connectivity.ts"
import { classify, signalOf } from "./errors.ts"

export type ApiClient = HttpApiClient.ForApi<typeof Api>

export interface ApiOptions {
  readonly report: (signal: Signal) => void
  readonly baseUrl?: string
  readonly fetch?: typeof globalThis.fetch
}

const REQUEST_INIT: RequestInit = { redirect: "manual", credentials: "same-origin" }

export const connectApi = ({ report, baseUrl, fetch }: ApiOptions) => {
  const reportSignal = (signal: Signal | null) =>
    Effect.sync(() => {
      if (signal !== null) report(signal)
    })
  const request = <A, E>(
    call: (client: ApiClient) => Effect.Effect<A, E | HttpClientError.HttpClientError | Schema.SchemaError>,
  ): Promise<A> => {
    const program = HttpApiClient.make(Api, { baseUrl }).pipe(
      Effect.flatMap(call),
      Effect.mapError(classify),
      Effect.tap(() => reportSignal("reached")),
      Effect.tapError((error) => reportSignal(signalOf(error))),
      Effect.provide(FetchHttpClient.layer),
      Effect.provideService(FetchHttpClient.RequestInit, REQUEST_INIT),
    )
    return Effect.runPromise(
      fetch === undefined ? program : Effect.provideService(program, FetchHttpClient.Fetch, fetch),
    )
  }
  return { request }
}

export type HouseholdApi = ReturnType<typeof connectApi>
```

```ts
import { QueryKey, SOCKET_PATH } from "@bt/contracts"
import { Option, Schema } from "effect"
import type { Signal } from "./connectivity.ts"

export interface LiveSocket extends EventTarget {
  send(data: string): void
  close(): void
}

export interface LiveOptions {
  readonly open: () => LiveSocket
  readonly onChanged: (keys: ReadonlyArray<QueryKey>) => void
  readonly onStale: () => void
  readonly report: (signal: Signal) => void
  readonly random?: () => number
}

export const HEARTBEAT_MS = 30_000
const FIRST_RETRY_MS = 1_000
const LAST_RETRY_MS = 30_000

export const retryDelay = (attempt: number, random: () => number) =>
  Math.min(LAST_RETRY_MS, FIRST_RETRY_MS * 2 ** attempt) * (0.5 + random() / 2)

export const socketUrl = ({ protocol, host }: Pick<Location, "protocol" | "host">) =>
  `${protocol === "https:" ? "wss:" : "ws:"}//${host}${SOCKET_PATH}`

const decodeEnvelope = Schema.decodeUnknownOption(
  Schema.fromJsonString(Schema.Struct({ changed: Schema.Array(Schema.Unknown) })),
)
const decodeKey = Schema.decodeUnknownOption(QueryKey)

export const changedKeys = (data: string): Option.Option<ReadonlyArray<QueryKey>> =>
  Option.map(decodeEnvelope(data), ({ changed }) => changed.flatMap((key) => Option.toArray(decodeKey(key))))
```

```ts
import { CAREGIVER_DISABLED, HEARTBEAT } from "@bt/contracts"
import { Option } from "effect"
import { changedKeys, HEARTBEAT_MS, type LiveOptions, type LiveSocket, retryDelay } from "./live.ts"

export interface Live {
  readonly wake: () => void
  readonly stop: () => void
}

const closedForGood = (event: Event) => event instanceof CloseEvent && event.code === CAREGIVER_DISABLED.code

export const startLive = ({ open, onChanged, onStale, report, random = Math.random }: LiveOptions): Live => {
  let socket: LiveSocket | null = null
  let attempt = 0
  let opened = false
  let stopped = false
  let awaitingPong = false
  let retry: ReturnType<typeof setTimeout> | undefined
  let heartbeat: ReturnType<typeof setInterval> | undefined

  const drop = () => {
    clearInterval(heartbeat)
    socket = null
  }

  const reconnectLater = () => {
    if (stopped) return
    retry = setTimeout(connect, retryDelay(attempt, random))
    attempt += 1
  }

  const beat = (current: LiveSocket) => {
    if (!awaitingPong) {
      awaitingPong = true
      current.send(HEARTBEAT.ping)
      return
    }
    drop()
    current.close()
    reconnectLater()
  }

  const opens = (current: LiveSocket) => {
    attempt = 0
    awaitingPong = false
    report("online")
    if (opened) onStale()
    opened = true
    heartbeat = setInterval(() => beat(current), HEARTBEAT_MS)
  }

  const hears = (data: string) => {
    if (data === HEARTBEAT.pong) {
      awaitingPong = false
      return
    }
    Option.match(changedKeys(data), { onNone: onStale, onSome: onChanged })
  }

  const closes = (event: Event) => {
    drop()
    if (!closedForGood(event)) return reconnectLater()
    stopped = true
    report("signed-out")
  }

  function connect() {
    const current = open()
    socket = current
    current.addEventListener("open", () => socket === current && opens(current))
    current.addEventListener("message", (event) => {
      if (socket === current && event instanceof MessageEvent) hears(String(event.data))
    })
    current.addEventListener("close", (event) => socket === current && closes(event))
  }

  connect()
  return {
    wake: () => {
      if (stopped || socket !== null) return
      clearTimeout(retry)
      attempt = 0
      connect()
    },
    stop: () => {
      stopped = true
      clearTimeout(retry)
      const current = socket
      drop()
      current?.close()
    },
  }
}
```

```ts
import { type Me, queryKeys } from "@bt/contracts"
import { type QueryClient, queryOptions } from "@tanstack/react-query"
import type { HouseholdApi } from "./client.ts"

const forgetOtherCaregiver = (queryClient: QueryClient) =>
  queryClient.removeQueries({ predicate: (query) => query.queryKey[0] !== queryKeys.me[0] })

export const meQuery = (api: HouseholdApi, queryClient: QueryClient) =>
  queryOptions({
    queryKey: queryKeys.me,
    queryFn: async () => {
      const before = queryClient.getQueryData<Me>(queryKeys.me)
      const me = await api.request((client) => client.me.me())
      if (before !== undefined && before.caregiver.email !== me.caregiver.email) forgetOtherCaregiver(queryClient)
      return me
    },
  })
```
