**Goal:** Bundle WHO's expanded daily tables for girls (weight, length and head circumference for age, days 0 to 730) in `packages/domain`, with a `MANIFEST.json` whose sha256s CI checks. M4.2 then builds and validates the percentile engine on WHO's exact numbers.

**Architecture:**
- **The tables:** `packages/domain/data/who/` holds WHO's six girls' workbooks (a z-score and a percentile workbook per indicator) as JSON, days 0 to 730. Beside them, `lms-girls.json` holds the L, M and S per day that runtime code reads. `MANIFEST.json` names each WHO source and each bundled file, with their sha256s.
- **The refresh:** `pnpm who:tables` (`scripts/fetch-who-tables.ts`) downloads the workbooks, checks them and rewrites the folder. Its parsing and checks live in `scripts/who-tables.ts`, which Node tests reach. It runs by hand, never in CI.
- **The CI check:** `scripts/who-tables.test.ts`, in `pnpm test`, hashes every bundled file against the manifest and refuses files it doesn't list. It also rebuilds `lms-girls.json` from the committed z-score tables, to prove the two agree.
- **The lookup:** `girlsLms(metric, ageDays)` in `packages/domain/src/growth/who-lms.ts` answers WHO's L, M and S for a day, or `null`.

## Decisions this plan makes (veto in review)

- **P1: The sources are WHO's six expanded workbooks for girls.**
  - Weight-for-age, length/height-for-age and head-circumference-for-age, each as a z-score and a percentile workbook, from `cdn.who.int`, as WHO's standards pages linked them on 10 Oct 2026.
  - A dataset id is the workbook's file name, such as `wfa-girls-zscore-expanded-tables`. Its URL keeps WHO's `sfvrsn` version.
  - Each workbook has one row per day from 0 to 1856: L, M and S, then SD4neg to SD4 (z-scores) or P01 to P999 (percentiles).
- **P2: Days 0 to 730.**
  - The M4.1 row asks for them, and day 730 is also where WHO's length table turns into standing height. The median drops 0.67 cm from day 730 (86.4008 cm) to day 731 (85.7299 cm).
- **P3: Each value is WHO's published decimal.**
  - Excel stores doubles, so the workbooks hold `0.38090000000000002` and `3.7830000000000003E-2`. Read as a number and written back as JSON, each becomes the shortest decimal that round-trips: `0.3809` and `0.03783`, exactly WHO's published values. None has more than 5 decimals.
  - A cell must be a decimal number. An empty cell, which `Number("")` would read as 0, is refused.
- **P4: The files.**
  - **One JSON per workbook**, named after it: one array per column, keyed by WHO's heading, indexed by day. It is half the size of an object per day, and M4.2's tests read a column such as `P3` by name.
  - **WHO's first column** (`Day`, or `Age` in the weight and head-circumference percentile workbooks) must equal the row's index, and is then dropped.
  - **`lms-girls.json`, for runtime:** one `{"L","M","S"}` object per day for each indicator, from the z-score workbooks. It is 12.9 KiB gzip, against about 60 KiB for the six tables. One array per column would save 1.6 KiB, but the lookup would then check three arrays instead of one row.
  - **One runtime table serves both kinds:** the refresh refuses a percentile workbook whose L, M and S differ from its z-score workbook's.
- **P5: `MANIFEST.json`.**
  - `standard`, `days` (`first` 0, `last` 730), `sources` (each dataset, its URL, and the sha256 of the downloaded workbook) and `files` (each path, its sha256, and the datasets it came from).
  - It has no retrieval date, so a rerun on unchanged sources rewrites the folder byte for byte. Git records when.
- **P6: CI checks the bundle with a scripts test, `scripts/who-tables.test.ts`, which `pnpm test` runs.**
  - Each file matches its sha256, the folder holds only listed files, the sources match the refresh's list, and `lms-girls.json` equals what the committed z-score tables give.
  - A domain test couldn't hash the files, since `packages/domain` can't import `node:*`.
  - CI never downloads from WHO, so WHO's outages can't fail it.
- **P7: `pnpm who:tables` rebuilds the folder from WHO.**
  - It downloads the six workbooks and reads each first sheet with `unzip -p`. It checks the headings, days 0 to 730 in order and every cell, then writes the seven tables and the manifest.
  - It runs by hand, to refresh the tables or to check them against WHO: a clean `git status` after it means the bundle is WHO's. It never runs in CI.
- **P8: oxfmt ignores `packages/domain/data/who/**`.** It formats JSON, and a reformatted table would no longer match its sha256. Without the ignore, `pnpm lint` fails on the tables.
- **P9: The domain imports its JSON with `with { type: "json" }`.** Node requires the attribute, and `pnpm api:docs` loads the domain under plain Node, through `contracts`. TypeScript needs no new flag, since `moduleResolution: "Bundler"` turns on `resolveJsonModule`.
- **P10: `girlsLms(metric, ageDays): Lms | null`.**
  - `metric` is `"weightForAge"`, `"lengthForAge"` or `"headCircumferenceForAge"`.
  - It answers WHO's `{ L, M, S }` for a whole day from 0 to 730, and `null` for any other number: before birth, part of a day, past day 730, `NaN`.
  - It takes no sex, since only girls' tables are bundled. M4.2's `percentileFor(metric, sex, …)` answers `'unavailable'` for `"male"`.
  - `WHO_LAST_DAY` (730) is exported with it.
- **P11: Sizes.**
  - Nothing imports `girlsLms` yet, so Rolldown drops the table and both bundles are unchanged. Task 3 Step 9 checks that no WHO value is in either.
  - The repository grows by 525 KB of JSON.

## Review Focus

1. **A value carrying Excel's float noise, or rounded.** Expect every value to be WHO's published decimal. Tested in Task 1 ("keeps day 0 to the last day, in WHO's published decimals") and Task 3 (WHO's L, M and S on days 0 and 730 of each indicator).
2. **A table shifted by a day,** if the heading were read as day 0 or a row went missing. Every percentile after it would use the next day's curve. Expect day n to hold WHO's day n. Tested in Task 1 ("refuses a skipped day") and Task 3 (days 0 and 730).
3. **A bundled file changed by accident:** a formatter, a merge, a find-and-replace. Expect CI to fail. Tested in Task 2 (each sha256, and no unlisted file) and by its mutation check. P8 keeps oxfmt away.
4. **The runtime table drifting from the tables M4.2 validates against.** Expect them identical. Tested in Task 2 ("keeps the runtime L, M and S identical to the z-score tables'"), which still fails when `lms-girls.json` and its sha256 are both edited.
5. **An age outside the tables:** before birth, part of a day, past day 730, `NaN`. Expect no L, M and S at all, so M4.2 can answer "Percentile unavailable" instead of extrapolating. Tested in Task 3 ("has nothing for day …").

```ts
export type Indicator = "weightForAge" | "lengthForAge" | "headCircumferenceForAge"
export type TableKind = "zscore" | "percentiles"

export interface WhoSource {
  readonly dataset: string
  readonly indicator: Indicator
  readonly kind: TableKind
  readonly url: string
}

export const LAST_DAY = 730
export const LMS_FILE = "lms-girls.json"

const LMS_COLUMNS = ["L", "M", "S"] as const

export const COLUMNS = {
  zscore: [...LMS_COLUMNS, "SD4neg", "SD3neg", "SD2neg", "SD1neg", "SD0", "SD1", "SD2", "SD3", "SD4"],
  percentiles: [
    ...LMS_COLUMNS,
    "P01",
    "P1",
    "P3",
    "P5",
    "P10",
    "P15",
    "P25",
    "P50",
    "P75",
    "P85",
    "P90",
    "P95",
    "P97",
    "P99",
    "P999",
  ],
} as const

const DAY_HEADINGS: ReadonlySet<string> = new Set(["Day", "Age"])
const SHARED_STRING = /<si><t[^>]*>([^<]*)<\/t><\/si>/g
const ROW = /<row\b[^>]*[^/]>(.*?)<\/row>/gs
const CELL = /<c ([^>]*?)(?:\/>|>(?:<v>([^<]*)<\/v>)?<\/c>)/g
const DECIMAL = /^-?\d+(?:\.\d+)?(?:E[-+]?\d+)?$/i

export type Table = readonly (readonly number[])[]

export const sharedStrings = (xml: string): string[] => Array.from(xml.matchAll(SHARED_STRING), ([, text = ""]) => text)

const cellText = (attributes: string, value: string, strings: readonly string[]) =>
  attributes.includes('t="s"') ? (strings[Number(value)] ?? "") : value

export const sheetRows = (sheetXml: string, strings: readonly string[]): string[][] =>
  Array.from(sheetXml.matchAll(ROW), ([, cells = ""]) =>
    Array.from(cells.matchAll(CELL), ([, attributes = "", value = ""]) => cellText(attributes, value, strings)),
  )

const numberOf = (text: string) => (DECIMAL.test(text) ? Number(text) : Number.NaN)

const dayValues = (cells: readonly string[], day: number, width: number): number[] => {
  const [dayCell, ...values] = cells.map(numberOf)
  if (dayCell !== day || values.length !== width || !values.every(Number.isFinite)) {
    throw new Error(`Expected day ${day} and ${width} numbers; found ${cells.join(", ")}`)
  }
  return values
}

export const whoTable = (rows: readonly (readonly string[])[], columns: readonly string[], lastDay: number): Table => {
  const [heading = [], ...body] = rows
  const [dayHeading = "", ...valueHeadings] = heading
  if (!DAY_HEADINGS.has(dayHeading) || valueHeadings.join() !== columns.join()) {
    throw new Error(`Expected Day or Age, then ${columns.join(", ")}; found ${heading.join(", ")}`)
  }
  if (body.length <= lastDay) throw new Error(`Expected days 0 to ${lastDay}; found ${body.length} rows`)
  return body.slice(0, lastDay + 1).map((cells, day) => dayValues(cells, day, columns.length))
}

const column = (table: Table, index: number) => table.map((row) => row[index] ?? Number.NaN)

const jsonObject = (lines: readonly string[]) => `{\n${lines.join(",\n")}\n}\n`

export const tableJson = (columns: readonly string[], table: Table): string =>
  jsonObject(columns.map((name, index) => `  ${JSON.stringify(name)}: ${JSON.stringify(column(table, index))}`))

export interface LmsColumns {
  readonly L: readonly number[]
  readonly M: readonly number[]
  readonly S: readonly number[]
}

export interface IndicatorLms {
  readonly indicator: Indicator
  readonly lms: LmsColumns
}

export const lmsColumns = (table: Table): LmsColumns => ({
  L: column(table, 0),
  M: column(table, 1),
  S: column(table, 2),
})

const lmsRows = ({ L, M, S }: LmsColumns) => L.map((l, day) => `    ${JSON.stringify({ L: l, M: M[day], S: S[day] })}`)

export const lmsJson = (indicators: readonly IndicatorLms[]): string =>
  jsonObject(
    indicators.map(({ indicator, lms }) => `  ${JSON.stringify(indicator)}: [\n${lmsRows(lms).join(",\n")}\n  ]`),
  )

export interface SourceRead {
  readonly source: WhoSource
  readonly sha256: string
  readonly table: Table
}

export interface DataFile {
  readonly path: string
  readonly text: string
  readonly from: readonly string[]
}

const sameLms = (a: Table, b: Table) => JSON.stringify(lmsColumns(a)) === JSON.stringify(lmsColumns(b))

const checkLmsAgree = (zscores: readonly SourceRead[], percentiles: readonly SourceRead[]) => {
  for (const { source, table } of percentiles) {
    const zscore = zscores.find((read) => read.source.indicator === source.indicator)
    if (zscore === undefined || !sameLms(zscore.table, table)) {
      throw new Error(`${source.dataset}: L, M and S differ from the ${source.indicator} z-score table's`)
    }
  }
}

export const whoFiles = (reads: readonly SourceRead[]): DataFile[] => {
  const zscores = reads.filter(({ source }) => source.kind === "zscore")
  const percentiles = reads.filter(({ source }) => source.kind === "percentiles")
  checkLmsAgree(zscores, percentiles)
  return [
    ...reads.map(({ source, table }) => ({
      path: `${source.dataset}.json`,
      text: tableJson(COLUMNS[source.kind], table),
      from: [source.dataset],
    })),
    {
      path: LMS_FILE,
      text: lmsJson(zscores.map(({ source, table }) => ({ indicator: source.indicator, lms: lmsColumns(table) }))),
      from: zscores.map(({ source }) => source.dataset),
    },
  ]
}
```

  Why it reads this way, since the code can't carry comments:
  - `DECIMAL` accepts Excel's exponent form (`3.7830000000000003E-2`) and refuses an empty cell, which `Number("")` would read as 0.
  - `ROW` wants a character other than `/` before the `>`, so a self-closing empty `<row r="5"/>` can't swallow the next row.
  - `CELL` reads a `t="s"` cell through the shared strings. WHO's headings are shared strings, and their numbers are plain values.
  - `column` falls back to `NaN` only for `noUncheckedIndexedAccess`. `whoTable` has already checked every row's width, and a `NaN` would surface as `null` in the JSON.

```ts
import { spawnSync } from "node:child_process"
import { mkdirSync, mkdtempSync, rmSync, writeFileSync } from "node:fs"
import { tmpdir } from "node:os"
import { join } from "node:path"
import { fileURLToPath } from "node:url"
import {
  COLUMNS,
  LAST_DAY,
  MANIFEST_FILE,
  manifestJson,
  sha256Of,
  sharedStrings,
  sheetRows,
  type SourceRead,
  WHO_SOURCES,
  type WhoSource,
  whoFiles,
  whoManifest,
  whoTable,
} from "./who-tables.ts"

const dataDir = fileURLToPath(new URL("../packages/domain/data/who/", import.meta.url))
const downloads = mkdtempSync(join(tmpdir(), "who-tables-"))

const download = async ({ dataset, url }: WhoSource) => {
  const response = await fetch(url)
  if (!response.ok) throw new Error(`${dataset}: HTTP ${response.status} from ${url}`)
  return new Uint8Array(await response.arrayBuffer())
}

const unzipped = (workbook: string, entry: string) => {
  const run = spawnSync("unzip", ["-p", workbook, entry], { encoding: "utf8", maxBuffer: 64 * 1024 * 1024 })
  if (run.status !== 0) throw new Error(`unzip ${entry} from ${workbook}: ${run.error?.message ?? run.stderr}`)
  return run.stdout
}

const read = async (source: WhoSource): Promise<SourceRead> => {
  const bytes = await download(source)
  const workbook = join(downloads, `${source.dataset}.xlsx`)
  writeFileSync(workbook, bytes)
  const strings = sharedStrings(unzipped(workbook, "xl/sharedStrings.xml"))
  const rows = sheetRows(unzipped(workbook, "xl/worksheets/sheet1.xml"), strings)
  return { source, sha256: sha256Of(bytes), table: whoTable(rows, COLUMNS[source.kind], LAST_DAY) }
}

try {
  const reads = await Promise.all(WHO_SOURCES.map(read))
  const files = whoFiles(reads)
  mkdirSync(dataDir, { recursive: true })
  for (const { path, text } of files) writeFileSync(join(dataDir, path), text)
  writeFileSync(join(dataDir, MANIFEST_FILE), manifestJson(whoManifest(reads, files)))
  console.log(`Wrote ${files.length} tables and ${MANIFEST_FILE} to ${dataDir}`)
} finally {
  rmSync(downloads, { recursive: true, force: true })
}
```

## Handoffs (not M4.1 work)

- **M4.2 (the LMS engine and its validation):**
  - **L, M and S:** `girlsLms(metric, ageDays)` gives them for whole days 0 to 730.
  - **WHO's published values:** import the six tables in domain tests, such as `import wfaPercentiles from "../../data/who/wfa-girls-percentiles-expanded-tables.json" with { type: "json" }`. Each key is a WHO heading (`P3`, `SD3neg` and so on), and each value is an array indexed by day.
  - **Never import the six tables from `src`.** Together they are about 60 KiB gzip, against 12.9 KiB for `lms-girls.json`.
  - **Rounding:** WHO publishes the P and SD values to 3 decimals, so P3 read back through the LMS lands near 3 but not on it. That is what the ±0.5-point tolerance absorbs.
  - **The restricted adjustment:** length and head circumference have L = 1, a normal distribution. Only weight's L varies, so the adjustment beyond ±3 SD matters for weight, and the z-score tables carry SD4neg and SD4 to test it.
  - **`docs/percentiles.md`,** with the tolerance, is M4.2's.
- **Andrew, a decision for M4.2 or M4.4: corrected age.**
  - The child's profile stores `gestationalAgeDays` (M1.15). WHO's standards describe babies born at term, and growth for a baby born early is often read at corrected age until two years.
