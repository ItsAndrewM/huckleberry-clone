# M3.1 Sleep Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (chosen by Andrew on 13 Oct 2026) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The household keeps sleeps. Through the API a parent can start a sleep, wake it, log a past one, and edit, delete or restore one, with at most one running and no two overlapping. Today, the last 24 hours and every day, week and month count sleep: time asleep split into naps and nights, the sleeps started and the longest. Today answers the running sleep and the last one, every period lists its sleeps, Recently deleted lists deleted ones, the CSV carries them, and a birth date can't fall after one. Nothing shows a sleep on the phones until M3.2.

**Architecture:**
- **`packages/domain`:** a new `sleep/sleep.ts` holds the two kinds and `sleepKindAt`, the nap-or-night rule by the household's clock. `aggregate/` gains sleep: `totalsIn` and `totalsByDay` take one `Entries` argument (`{ feeds, diapers, sleeps }`), `Totals` gains five sleep fields, `sumTotals` keeps the longest of the days' longest, and `sleepTouches` says whether a sleep is in a period. `trends/days.ts` counts a day with sleep as a day with entries.
- **`packages/contracts`:** a new `sleeps.ts` holds the `Sleep` record, its four requests, `SleepConflict` and the `sleeps` group. `Totals`, `Today`, the period answers and `Deleted` gain their sleep fields.
- **`apps/worker`:** migration `0007-sleeps` adds the `sleeps` table. A new `core/sleeps/` folder holds its store, its rules, starting and waking, a past sleep, edits, deletes and restores, and its reads. `sleep-handlers.ts` serves the group. Today, the periods, Recently deleted, the CSV and the birth-date check read sleeps. The feed rules' `errorAt` and `invalidUnless` move to `core/fields.ts`, shared by both kinds.
- **`apps/web`:** only what keeps the app decoding and its numbers right: History's swap totals a day with its sleeps, Today's shift leaves the sleep numbers alone, and `withoutEntry` drops a restored sleep.
- **`scripts`:** `pnpm migrations:dry-run <export>` applies the migrations an export hasn't seen to an in-memory copy of it, the dry run Andrew asked for before the merge.

**Tech Stack:** TypeScript 5.9.3, `effect` 4.0.1 (Schema, `effect/http-api`), `@bt/contracts` and `@bt/domain`, Workers and Durable Objects (`@cloudflare/workers-types` 5.20261006.1, wrangler 4.148.0), `@cloudflare/vitest-plugin` 1.3.7, TanStack Query 5.104.1, Vitest 4.1.11, fast-check 4.10.2, Playwright 1.64.0, oxlint 1.87.0 and oxfmt 0.72.0, Node 24.21.0 (its built-in `node:sqlite` for the dry run). ## Decisions this plan makes (veto in review)

- **P1: A sleep is one row in `sleeps` (migration `0007-sleeps`).**
  - Columns: `id`, `kind` (`nap` or `night`), `started_at`, `ended_at` (null while it runs), `version`, `created_by`/`created_at`, `updated_by`/`updated_at` and `deleted_at`, each instant checked to fall in 2000 to 2099, with `ended_at > started_at`.
  - `sleeps_one_active` is a unique index on `(ended_at IS NULL)` where `ended_at IS NULL AND deleted_at IS NULL`, so at most one live sleep runs, whatever writes it. SQLite counts every NULL as distinct, so a unique index on `ended_at` itself wouldn't hold that.
  - `sleeps_by_time` on `(started_at, ended_at)` serves the day-intersection query and the last-sleep lookup.
  - No `source` or `source_ref` (D4): they served import only, which was dropped with M2.
  - No `status` column: a sleep runs exactly when `ended_at` is null. It isn't a Durable Object class change, so CI deploys it.
- **P2: Six endpoints in a `sleeps` group, after the feeds' `portions` group.** Each answers `SavedSleep` (`{ sleep, changed }`), through the receipts.
  - `POST /api/sleeps` (`logSleep`) takes `NewSleep`: `{ actionId, kind, startedAt, endedAt }`, a past sleep. 201.
  - `POST /api/sleeps/start` (`startSleep`) takes `SleepStart`: `{ actionId, kind, startedAt }`. 201.
  - `POST /api/sleeps/:id/wake` (`wakeSleep`) takes the feeds' `TimedAction`: `{ actionId, version, occurredAt }`.
  - `PATCH /api/sleeps/:id` (`editSleep`) takes `SleepEdit`: `{ actionId, version, kind, startedAt, endedAt }`, with `endedAt` null for a running sleep.
  - `DELETE /api/sleeps/:id` (`deleteSleep`) and `POST /api/sleeps/:id/restore` (`restoreSleep`) take `VersionedAction`.
  - Errors: `InvalidInput`, `NotFound` (not on the two creates), and `SleepConflict` with `SLEEP_ALREADY_ACTIVE`, `SLEEP_OVERLAP`, `STALE_VERSION` or `ACTION_REPLAY_MISMATCH`, carrying the sleep it's about.
  - The version and state checks follow the feeds': a version that isn't current answers `STALE_VERSION` with the sleep as it is now, deleted or not; the right version on the wrong state (waking a finished sleep, editing a deleted one, restoring a live one) answers 404.
- **P3: No two live sleeps overlap, and a running sleep reaches 5 minutes past now** (the M3.1 row's overlap check).
  - Every write that places a sleep checks it against every other live sleep, half-open: `started_at < end AND COALESCE(ended_at, now + 5 min) > start`. A running sleep counts up to 5 minutes past the household's clock, as a running side does for D9, since a phone ahead of the clock may send times up to 5 minutes ahead. The M3.1 row said `[start, now)`; D9's rule came later and is the same tolerance.
  - A sleep that ends as another starts doesn't overlap it.
  - A start answers `SLEEP_ALREADY_ACTIVE` with the running sleep before it checks overlaps (§5). Its own overlap check covers a saved sleep it would run into.
  - Overlap with a feed, a diaper or anything else is allowed (D9).
- **P4: A wake ends the running sleep at the tap.**
  - Its `occurredAt` must be after the start (`end_not_after_start`) and at most 5 minutes past now (`in_future`). A wake at the start is refused rather than deleting the sleep: M3.2's sheet offers Delete for that, so the API needs no `SLEEP_EMPTY` code.
  - A wake isn't held to P5's day, as a feed's finish isn't held to a side's 4 hours, so a sleep left running for 30 hours can still be woken and then corrected.
  - A wake checks no overlap: its sleep already covered every moment up to now + 5 minutes.
- **P5: A sleep someone types, a past one or an edit, runs a day at most** (`MAX_SLEEP_MS`, 24 hours, in contracts beside `MAX_SEGMENT_MS`). Longer answers `out_of_range` on `endedAt`. A start, an end at or before the start, and an end more than 5 minutes ahead are refused on their own fields, with both fields named when both are wrong.
- **P6: An edit keeps a sleep's state, and the times it keeps skip the time checks.**
  - A running sleep stays running and a finished one stays finished: an edit that changes `endedAt` between null and a time answers `invalid` on `endedAt`. Only a wake ends a sleep.
  - Times the edit keeps skip the birth-date and future checks, M3.4's rule for feeds, diapers and measurements. A start it keeps skips them, and a sleep whose start and end both stay skips every time check, P5's day included. So a sleep a zone change left before the birth date can be relabelled, and so can one woken after 30 hours.
  - The overlap check leaves the sleep itself out, so a sleep can move within its own old times.
  - The label is the edit's to set (P9).
- **P7: A delete marks the sleep deleted as it stands; a restore re-runs every check (D10).**
  - A delete works on a running or finished sleep, and frees the running slot at once. Its `changed` includes `deleted`.
  - A restore re-checks the start against the birth date (`before_birth` on `startedAt`, as M3.5's restores do), answers `SLEEP_ALREADY_ACTIVE` with the running sleep when it would bring back a second running one, and `SLEEP_OVERLAP` with any live sleep it now overlaps. A sleep deleted while running comes back running from its start. Its `changed` includes `deleted`.
- **P8: A sleep's `changed` keys cover its days from its start to its end, or to now while it runs** (D7). The span is `[start, max(end ?? now, start + 1))`, before and after, through `changedKeys`, so a sleep across midnight names both days, their weeks and their months, and one started ahead of the clock names its start day.
- **P9: Each sleep stores its label; the phone sets it** (Andrew, 13 Oct 2026).
  - `kind` is required on every start, past sleep and edit. The server stores what's sent and never works it out.
  - `sleepKindAt(startedAt, zone)` in the domain is the default the phone shows (M3.2): a sleep that starts from 19:00 to 06:59 on the household's clock is a night, any other a nap. It reads the household's wall clock, so a repeated hour reads as it shows.
  - A time zone change relabels nothing.
- **P10: `Totals` carry sleep** (Andrew, 13 Oct 2026).
  - Five fields join `Totals`, in the domain and the contract: `sleepsStarted`, `sleepSeconds`, `napSeconds`, `nightSeconds` and `longestSleepSeconds`.
  - Time asleep is each sleep's overlap with the period, a running one up to now, so a sleep across midnight gives each day its own part (AC 12). Nap and night time sum each kind's milliseconds before rounding down to whole seconds, as nursing does, and `sleepSeconds` is their sum.
  - A sleep counts as started in the period that holds its start, as a feed does. The longest is the longest whole sleep that started in the period, a running one up to now. So a week's or a month's longest is the longest of its days' longest, and `sumTotals` takes that maximum while it adds every other field. M3.6's property test checks both.
  - `totalsIn(period, entries, now)` and `totalsByDay(dates, zone, entries, now)` take one `Entries` argument, `{ feeds, diapers, sleeps }`, in place of separate feeds and diapers, so M3.3's doses join as one more key. A `DayPeriod` is already an `Entries`.
  - Trends: a day with any sleep has entries (M3.10's hand-off), and averages include the sleep fields. Trends charts no sleep until M3.2.
- **P11: Today answers `activeSleep` and `lastSleep`, and counts sleep in its totals.**
  - `activeSleep` is the running sleep, or null. `lastSleep` is the live sleep with the latest start, running or not, or null. It walks `sleeps_by_time` with `INDEXED BY`, as M5.5's `lastFeed` walks `feeds_by_time`, and reads the same handful of rows at any history length. M3.2 counts the time since the last wake from its `endedAt`.
  - Today's and the last 24 hours' totals read every live sleep that ends after the earlier of today's start and 24 hours ago, or still runs.
  - Today's recent list doesn't carry sleeps: `RecentEntry` gains its sleep kind with M3.2's row. Until then nothing can log a sleep, and a union member the app can't show would only add code to M3.1.
- **P12: Every period lists its `sleeps`** (M3.6's hand-off). A sleep is in a period when its span, up to `asOf` while it runs, overlaps it, or when it starts in it (`sleepTouches`, as `feedTouches` does), oldest first, whole. SQL narrows by `started_at < end AND (ended_at IS NULL OR ended_at > start)`, since a sleep is an interval only (§3.3). `DayPeriod`, `WeekPeriod` and `MonthPeriod` gain `sleeps` between `diapers` and `measurements`.
- **P13: Recently deleted lists deleted sleeps,** newest deletion first, from the last 30 days, as it lists the rest. `Deleted` gains `sleeps`. The web's `withoutEntry` takes a restored sleep off its list, though no row shows one until M3.2.
- **P14: The CSV gains a row per live sleep** (M3.11's test requires it the moment the table exists, so it lands with the table in Task 3).
  - Two new columns sit after `Dirty`: `Asleep (min)` (to a tenth, a running sleep's up to the export) and `Nap or night` (`Nap` or `Night`). Kind is `Sleep`, Start and End at the household's time, End blank while it runs.
  - Every other row gains two empty cells there.
- **P15: The birth date can't fall after a sleep** (M1.15's hand-off). `earliestRecordAt` includes live sleeps' starts.
- **P16: Feeds and sleeps share the domain and the field errors, not SQL.** `errorAt` and `invalidUnless` move from `core/feeds/rules.ts` to `core/fields.ts`, and the feed modules import them from there. M1.7's `openInterval`, `closeInterval` and `correctInterval` aren't extracted (the hand-offs above). §3.5 says so (Task 9).
- **P17: The web changes only to keep decoding and its numbers right.**
  - History's `swappedDay` totals a cached day with its own sleeps, so an edit to a feed or a diaper never drops the day's sleep numbers.
  - Today's optimistic `shifted` totals spread the cached totals first and move only the feed and diaper fields. Only feeds and diapers swap until M3.2, and a sleep swap would need `longestSleepSeconds` worked out again, not shifted.
  - Trends' Day view totals the day's `DayPeriod` as its `Entries`.
  - Fixtures and E2E mocks gain the fields: `Totals`' five, Today's `activeSleep` and `lastSleep`, and the periods' and `Deleted`'s `sleeps`. A test fixture `sleptAt` builds a sleep.
- **P18: The bench and the dry run.**
  - `seedTwoYears` adds 6 sleeps a day (150 minutes each, every 4 hours, alternating night and nap), and `pnpm bench` times a sleep write beside the feed write. At two years (4,380 sleeps): Today 2 ms, this month 7 ms, a month a year ago 13 ms, a sleep write 1 ms, the CSV 0.23 s.
  - `pnpm migrations:dry-run <export>` (`scripts/migration-dry-run.ts`, CLI `scripts/dry-run-migrations.ts`) rebuilds the tables a fresh export was taken under, in `node:sqlite` in memory, loads every row with foreign keys off, and applies the migrations the export hasn't seen. It fails if one of them fails, if a table is left with fewer rows, or if a reference breaks. It writes nothing and needs no token. The Finish runs it on a fresh `pnpm admin export` before the merge, as Andrew asked, and M3.3's 0008 can use it unchanged.

## Review Focus

The five ways this is most likely to fail a parent, each with the test that pins it:

1. **Two sleeps at once.** Two phones tap Start sleep, or one parent logs a nap that runs into the night sleep Emily started. Expect one running sleep at most, the second start answered `SLEEP_ALREADY_ACTIVE` with it, and a typed sleep that runs into the running one answered `SLEEP_OVERLAP`, since a running sleep reaches 5 minutes past now. Pinned by `sleep-lifecycle.test.ts` ("refuses a second sleep while one is running, …" and "refuses a start before a saved sleep that's still to come, …", Task 3), `sleeps-table.test.ts` ("holds at most one live running sleep, …", Task 3), `sleep-log.test.ts` ("refuses a sleep that runs into the running one, …", Task 4) and the shared suite (Task 7).
2. **A sleep across midnight** (AC 12). Expect 30 minutes on the day it started and 60 on the next, the sleep and its whole 90 minutes as the longest counted on the first day only, and both days' keys changed. Pinned by the domain's `totals.test.ts` and `periods.test.ts` (Task 1), `periods-core.test.ts` ("holds a sleep across midnight whole in both days, …", Task 6), `sleep-lifecycle.test.ts` ("changes both days of a sleep woken after midnight, …", Task 3) and the shared suite (Task 7).
3. **A forgotten timer.** Expect a sleep left running for more than a day to wake, and then to take a new label, though no one could type a sleep that long. Pinned by `sleep-lifecycle.test.ts` ("wakes a sleep left running for more than a day, …", Task 3) and `sleep-edits.test.ts` ("relabels a sleep woken after more than a day, …", Task 4).
4. **The other phone got there first.** Emily woke the sleep, edited it, or started another while Andrew's restore was on its way. Expect `STALE_VERSION` with the sleep as it is now, and a restore that would bring back a second running sleep answered `SLEEP_ALREADY_ACTIVE`. Pinned by `sleep-lifecycle.test.ts` ("lets one of two phones' wakes …", Task 3), `sleep-edits.test.ts` ("answers STALE_VERSION …" twice, and "refuses a running sleep while another runs, …", Task 4), `sleeps.test.ts` (Task 5) and the shared suite (Task 7).
5. **Night or nap by the household's clock.** Expect a sleep starting at 19:00 to be a night and one at 07:00 a nap, by the household's zone, through a repeated hour. Pinned by `sleep.test.ts` (Task 1).

````ts
import fc from "fast-check"
import { describe, expect, it } from "vitest"
import { localDateTimeOf, resolveLocal, SLEEP_KINDS, sleepKindAt } from "../../src/index.ts"
import { LONDON, VANCOUVER, zonedInstants } from "../fixtures/zones.ts"

const atLocal = (local: string, zone: string) => {
  const resolved = resolveLocal(local, zone)
  if (resolved.kind !== "ok") throw new Error(`${local} isn't a single instant in ${zone}`)
  return resolved.instant
}

describe("sleepKindAt", () => {
  it("names the two kinds a sleep can be", () => {
    expect(SLEEP_KINDS).toEqual(["nap", "night"])
  })

  it.each([
    ["06:59", "night"],
    ["07:00", "nap"],
    ["12:30", "nap"],
    ["18:59", "nap"],
    ["19:00", "night"],
    ["23:30", "night"],
    ["00:00", "night"],
  ])("calls a sleep starting at %s the household's time a %s", (time, kind) => {
    expect(sleepKindAt(atLocal(`2026-10-08T${time}`, VANCOUVER), VANCOUVER)).toBe(kind)
  })

  it("reads the household's own clock, not UTC's", () => {
    const sevenThirtyInLondon = atLocal("2026-10-08T07:30", LONDON)
    expect(sleepKindAt(sevenThirtyInLondon, LONDON)).toBe("nap")
    expect(sleepKindAt(sevenThirtyInLondon, VANCOUVER)).toBe("night")
  })

  it("reads each pass of a repeated hour as the clock shows it, when the clocks go back", () => {
    const first = Date.parse("2025-11-02T08:30:00Z")
    const second = Date.parse("2025-11-02T09:30:00Z")
    expect([localDateTimeOf(first, VANCOUVER), localDateTimeOf(second, VANCOUVER)]).toEqual([
      "2025-11-02T01:30",
      "2025-11-02T01:30",
    ])
    expect([sleepKindAt(first, VANCOUVER), sleepKindAt(second, VANCOUVER)]).toEqual(["night", "night"])
  })

  it("is night exactly when the local hour is from 19 to 6, in every zone", () => {
    fc.assert(
      fc.property(zonedInstants, ([instant, zone]) => {
        const hour = Number(localDateTimeOf(instant, zone).slice(11, 13))
        expect(sleepKindAt(instant, zone)).toBe(hour >= 19 || hour < 7 ? "night" : "nap")
      }),
    )
  })
})
````

````ts
  const piece = clipTo({ start: sleep.startedAt, end: sleep.endedAt ?? now }, period)
  return piece === null ? 0 : durationMs(piece)
}

  Math.floor(
    sleeps.filter((sleep) => sleep.kind === kind).reduce((total, sleep) => total + asleepMsIn(period, sleep, now), 0) /

  )
````

````ts
import { createSleep, loadSleep, saveSleep } from "../src/core/sleeps/store.ts"
import { ANDREW, caregiverId, EMILY, inHousehold, minutesAgo, NOW, stampOf } from "./fixtures.ts"

const BEFORE_INSTANTS = Date.UTC(2000, 0, 1) - 1
const AFTER_INSTANTS = Date.UTC(2100, 0, 1)
const NOW_IN_SECONDS = NOW / 1000

const insertSleep = (
  sql: SqlStorage,
  kind: string,
  startedAt: number,
  endedAt: number | null,
  deletedAt: number | null = null,
) => {
  const andrew = caregiverId(sql, ANDREW.email)
  sql.exec(
    `INSERT INTO sleeps (id, kind, started_at, ended_at, version, created_by, created_at, updated_by, updated_at, deleted_at)
     VALUES (?, ?, ?, ?, 1, ?, ?, ?, ?, ?)`,
    crypto.randomUUID(),
    kind,
    startedAt,
    endedAt,
    andrew,
    NOW,
    andrew,
    NOW,
    deletedAt,
  )
}

describe("the sleep store", () => {
  it("creates a sleep as version 1, stamped with who logged it", async () => {
    const { sleep, andrew } = await inHousehold((sql) => ({
      sleep: createSleep(sql, stampOf(sql), { kind: "night", startedAt: minutesAgo(90), endedAt: minutesAgo(10) }),
      andrew: caregiverId(sql, ANDREW.email),
    }))
    expect(sleep).toEqual({
      id: expect.any(String),
      kind: "night",
      startedAt: minutesAgo(90),
      endedAt: minutesAgo(10),
      version: 1,
      createdBy: andrew,
      createdAt: NOW,
      updatedBy: andrew,
      updatedAt: NOW,
      deletedAt: null,
    })
  })

  it("saves a sleep as the next version, stamped with who saved it and when, keeping who logged it", async () => {
    const { created, saved, loaded, emily } = await inHousehold((sql) => {
      const created = createSleep(sql, stampOf(sql), { kind: "nap", startedAt: minutesAgo(40), endedAt: null })
      const later = stampOf(sql, EMILY.email, NOW + 60_000)
      const saved = saveSleep(sql, later, { ...created, kind: "night", endedAt: NOW })
      return { created, saved, loaded: loadSleep(sql, created.id), emily: caregiverId(sql, EMILY.email) }
    })
    expect(saved).toEqual({
      ...created,
      kind: "night",
      endedAt: NOW,
      version: 2,
      updatedBy: emily,
      updatedAt: NOW + 60_000,
    })
    expect(loaded).toEqual(saved)
  })

  it("finds no sleep for an id it doesn't hold", async () => {
    expect(await inHousehold((sql) => loadSleep(sql, "no-such-sleep"))).toBeUndefined()
  })
})

describe("the sleeps table", () => {
  it("holds at most one live running sleep, whatever writes it, beside any number of deleted ones", async () => {
    await inHousehold((sql) => {
      insertSleep(sql, "nap", minutesAgo(90), null, minutesAgo(80))
      insertSleep(sql, "nap", minutesAgo(70), null, minutesAgo(60))
      insertSleep(sql, "night", minutesAgo(10), null)
      expect(() => insertSleep(sql, "nap", minutesAgo(5), null)).toThrow("UNIQUE constraint failed")
    })
  })

  it.each([
    ["a kind other than nap or night", "evening", minutesAgo(60), minutesAgo(30), null],
    ["a sleep that ends as it starts", "nap", minutesAgo(60), minutesAgo(60), null],
    ["a sleep that ends before it starts", "nap", minutesAgo(60), minutesAgo(61), null],
    ["a sleep that starts before the years an Instant allows", "nap", BEFORE_INSTANTS, null, null],
    ["a sleep that ends after them", "night", minutesAgo(60), AFTER_INSTANTS, null],
    ["a sleep deleted in seconds, not milliseconds", "nap", minutesAgo(60), minutesAgo(30), NOW_IN_SECONDS],
  ])("refuses %s", async (_label, kind, startedAt, endedAt, deletedAt) => {
    await inHousehold((sql) => {
      expect(() => insertSleep(sql, kind, startedAt, endedAt, deletedAt)).toThrow("CHECK constraint failed")
    })
  })
````

````ts
import { type Changed, NotFound, type Sleep, SleepConflict } from "@bt/contracts"
import { FUTURE_TOLERANCE_MS, type Instant, type Interval, type Span } from "@bt/domain"
import { type Calendar, changedKeys } from "../calendar.ts"
import type { CoreResult } from "../receipts.ts"
import { loadSleep, sleepsWhere } from "./store.ts"

type SleepState = "live" | "running" | "finished" | "deleted"

type Found =
  | { readonly ok: true; readonly sleep: Sleep }
  | { readonly ok: false; readonly error: NotFound | SleepConflict }

const isIn = (sleep: Sleep, wanted: SleepState): boolean => {
  if (wanted === "deleted") return sleep.deletedAt !== null
  if (sleep.deletedAt !== null) return false
  if (wanted === "live") return true
  return (sleep.endedAt === null) === (wanted === "running")
}

export const sleepFor = (sql: SqlStorage, id: string, version: number, wanted: SleepState): Found => {
  const sleep = loadSleep(sql, id)
  if (sleep === undefined) return { ok: false, error: new NotFound() }
  if (sleep.version !== version) {
    return { ok: false, error: new SleepConflict({ code: "STALE_VERSION", current: sleep }) }
  }
  return isIn(sleep, wanted) ? { ok: true, sleep } : { ok: false, error: new NotFound() }
}

export const activeSleep = (sql: SqlStorage): Sleep | undefined =>
  sleepsWhere(sql, "WHERE ended_at IS NULL AND deleted_at IS NULL")[0]

export const alreadyActive = (sleep: Sleep) => new SleepConflict({ code: "SLEEP_ALREADY_ACTIVE", current: sleep })

export const overlappedSleep = (
  sql: SqlStorage,
  span: Span,
  now: Instant,
  exceptId: string | null,
): Sleep | undefined => {
  const runningUntil = now + FUTURE_TOLERANCE_MS
  return sleepsWhere(
    sql,
    `WHERE deleted_at IS NULL AND id IS NOT ? AND started_at < ? AND COALESCE(ended_at, ?) > ?
     ORDER BY started_at LIMIT 1`,
    exceptId,
    span.endedAt ?? runningUntil,
    runningUntil,
    span.startedAt,
  )[0]
}

export const overlapConflict = (sleep: Sleep) => new SleepConflict({ code: "SLEEP_OVERLAP", current: sleep })

const spanOf = (sleep: Sleep, now: Instant): Interval => ({
  start: sleep.startedAt,
  end: Math.max(sleep.endedAt ?? now, sleep.startedAt + 1),
})

export const sleepChanges = (calendar: Calendar, before: Sleep | null, after: Sleep | null, now: Instant): Changed =>
  changedKeys(calendar, before === null ? null : spanOf(before, now), after === null ? null : spanOf(after, now))

export const savedSleep = (
  calendar: Calendar,
  before: Sleep | null,
  after: Sleep,
  now: Instant,
): CoreResult<Sleep, never> => ({ ok: true, response: after, changed: sleepChanges(calendar, before, after, now) })
````

````ts
import type { InvalidInput, NotFound, Sleep, SleepConflict, SleepStart, TimedAction } from "@bt/contracts"
import { type Instant, type ValidationIssue, validateEndAfterStart, validateNotInFuture } from "@bt/domain"
import { calendarOf, timeIssue } from "../calendar.ts"
import { errorAt, invalidUnless } from "../fields.ts"
import type { CoreResult, Stamp } from "../receipts.ts"
import { activeSleep, alreadyActive, overlapConflict, overlappedSleep, savedSleep, sleepFor } from "./rules.ts"
import { createSleep, saveSleep } from "./store.ts"

const wakeIssue = (sleep: Sleep, at: Instant, now: Instant): ValidationIssue | null =>
  validateEndAfterStart(sleep.startedAt, at) ?? validateNotInFuture(at, now)

export const startSleep =
  (stamp: Stamp, start: SleepStart) =>
  (sql: SqlStorage): CoreResult<Sleep, InvalidInput | SleepConflict> => {
    const calendar = calendarOf(sql)
    const invalid = invalidUnless(errorAt("startedAt", timeIssue(calendar, start.startedAt, stamp.now)))
    if (invalid !== null) return { ok: false, error: invalid }
    const active = activeSleep(sql)
    if (active !== undefined) return { ok: false, error: alreadyActive(active) }
    const opened = { kind: start.kind, startedAt: start.startedAt, endedAt: null }
    const overlapped = overlappedSleep(sql, opened, stamp.now, null)
    if (overlapped !== undefined) return { ok: false, error: overlapConflict(overlapped) }
    return savedSleep(calendar, null, createSleep(sql, stamp, opened), stamp.now)
  }

export const wakeSleep =
  (stamp: Stamp, id: string, action: TimedAction) =>
  (sql: SqlStorage): CoreResult<Sleep, InvalidInput | NotFound | SleepConflict> => {
    const found = sleepFor(sql, id, action.version, "running")
    if (!found.ok) return found
    const invalid = invalidUnless(errorAt("occurredAt", wakeIssue(found.sleep, action.occurredAt, stamp.now)))
    if (invalid !== null) return { ok: false, error: invalid }
    const woken = saveSleep(sql, stamp, { ...found.sleep, endedAt: action.occurredAt })
    return savedSleep(calendarOf(sql), found.sleep, woken, stamp.now)
  }
````

````ts
import {
  type FieldError,
  type InvalidInput,
  type NotFound,
  queryKeys,
  type Sleep,
  type SleepConflict,
  type SleepEdit,
  type VersionedAction,
} from "@bt/contracts"
import { calendarOf, timeIssue } from "../calendar.ts"
import { errorAt, invalidUnless } from "../fields.ts"
import type { CoreResult, Stamp } from "../receipts.ts"
import {
  activeSleep,
  alreadyActive,
  overlapConflict,
  overlappedSleep,
  savedSleep,
  sleepChanges,
  sleepFor,
  timesErrors,
} from "./rules.ts"
import { saveSleep } from "./store.ts"

type Failure = InvalidInput | NotFound | SleepConflict

const runningChanged = (sleep: Sleep, edit: SleepEdit): FieldError[] =>
  (sleep.endedAt === null) === (edit.endedAt === null) ? [] : [{ path: "endedAt", issue: "invalid" }]

export const editSleep =
  (stamp: Stamp, id: string, edit: SleepEdit) =>
  (sql: SqlStorage): CoreResult<Sleep, Failure> => {
    const found = sleepFor(sql, id, edit.version, "live")
    if (!found.ok) return found
    const { sleep } = found
    const calendar = calendarOf(sql)
    const invalid = invalidUnless([...runningChanged(sleep, edit), ...timesErrors(calendar, edit, stamp.now, sleep)])
    if (invalid !== null) return { ok: false, error: invalid }
    const overlapped = overlappedSleep(sql, edit, stamp.now, sleep.id)
    if (overlapped !== undefined) return { ok: false, error: overlapConflict(overlapped) }
    const { kind, startedAt, endedAt } = edit
    return savedSleep(calendar, sleep, saveSleep(sql, stamp, { ...sleep, kind, startedAt, endedAt }), stamp.now)
  }

export const deleteSleep =
  (stamp: Stamp, id: string, action: VersionedAction) =>
  (sql: SqlStorage): CoreResult<Sleep, NotFound | SleepConflict> => {
    const found = sleepFor(sql, id, action.version, "live")
    if (!found.ok) return found
    const deleted = saveSleep(sql, stamp, { ...found.sleep, deletedAt: stamp.now })
    const changed = [...sleepChanges(calendarOf(sql), found.sleep, null, stamp.now), queryKeys.deleted]
    return { ok: true, response: deleted, changed }
  }

export const restoreSleep =
  (stamp: Stamp, id: string, action: VersionedAction) =>
  (sql: SqlStorage): CoreResult<Sleep, Failure> => {
    const found = sleepFor(sql, id, action.version, "deleted")
    if (!found.ok) return found
    const { sleep } = found
    const calendar = calendarOf(sql)
    const invalid = invalidUnless(errorAt("startedAt", timeIssue(calendar, sleep.startedAt, stamp.now)))
    if (invalid !== null) return { ok: false, error: invalid }
    const active = sleep.endedAt === null ? activeSleep(sql) : undefined
    if (active !== undefined) return { ok: false, error: alreadyActive(active) }
    const overlapped = overlappedSleep(sql, sleep, stamp.now, null)
    if (overlapped !== undefined) return { ok: false, error: overlapConflict(overlapped) }
    const restored = saveSleep(sql, stamp, { ...sleep, deletedAt: null })
    return {
      ok: true,
      response: restored,
      changed: [...sleepChanges(calendar, null, restored, stamp.now), queryKeys.deleted],
    }
  }
````

````ts
import { readdirSync, readFileSync } from "node:fs"
import { DatabaseSync } from "node:sqlite"
import type { ExportRow, HouseholdExport } from "../packages/contracts/src/export.ts"

export interface Migration {
  readonly name: string
  readonly sql: string
}

export interface DryRun {
  readonly applied: ReadonlyArray<string>
  readonly rows: number
  readonly tables: number
}

const MIGRATIONS_FOLDER = new URL("../apps/worker/src/db/migrations/", import.meta.url)

export const migrationsOnDisk = (): Migration[] =>
  readdirSync(MIGRATIONS_FOLDER)
    .filter((file) => file.endsWith(".sql"))
    .toSorted()
    .map((file) => ({ name: file.replace(/\.sql$/u, ""), sql: readFileSync(new URL(file, MIGRATIONS_FOLDER), "utf8") }))

const quoted = (name: string) => `"${name.replaceAll('"', '""')}"`

const checkLedger = (applied: ReadonlyArray<string>, migrations: ReadonlyArray<Migration>) => {
  applied.forEach((name, index) => {
    const known = migrations[index]?.name ?? "none"
    if (known !== name) {
      throw new Error(`The export's migration ${index + 1} is "${name}", but the code's is "${known}"`)
    }
  })
}

const insertRows = (db: DatabaseSync, table: string, rows: ReadonlyArray<ExportRow>) => {
  for (const row of rows) {
    const columns = Object.keys(row)
    const placeholders = columns.map(() => "?").join(", ")
    db.prepare(`INSERT INTO ${quoted(table)} (${columns.map(quoted).join(", ")}) VALUES (${placeholders})`).run(
      ...columns.map((column) => row[column] ?? null),
    )
  }
}

const countOf = (db: DatabaseSync, table: string) =>
  Number(db.prepare(`SELECT count(*) AS n FROM ${quoted(table)}`).get()?.n)

const checkRowsKept = (db: DatabaseSync, tables: HouseholdExport["tables"]) => {
  for (const [table, rows] of Object.entries(tables)) {
    const left = countOf(db, table)
    if (left !== rows.length) throw new Error(`${table} had ${rows.length} rows, but ${left} are left`)
  }
}

const checkReferences = (db: DatabaseSync) => {
  const broken = db.prepare("PRAGMA foreign_key_check").all()
  if (broken.length > 0) throw new Error(`${broken.length} references point at rows that aren't there`)
}

export const dryRun = (exported: HouseholdExport, migrations: ReadonlyArray<Migration>): DryRun => {
  checkLedger(exported.migrations, migrations)
  const db = new DatabaseSync(":memory:", { enableForeignKeyConstraints: false })
  for (const { sql } of migrations.slice(0, exported.migrations.length)) db.exec(sql)
  for (const [table, rows] of Object.entries(exported.tables)) insertRows(db, table, rows)
  const pending = migrations.slice(exported.migrations.length)
  for (const { sql } of pending) db.exec(sql)
  checkRowsKept(db, exported.tables)
  checkReferences(db)
  const rows = Object.values(exported.tables).reduce((total, table) => total + table.length, 0)
  return { applied: pending.map(({ name }) => name), rows, tables: Object.keys(exported.tables).length }
}

export const dryRunSummary = ({ applied, rows, tables }: DryRun): string =>
  applied.length === 0
    ? "The export already has every migration, so there was nothing to apply."
    : `Applied ${applied.join(", ")} on top of the export: all ${rows} rows of its ${tables} tables are still there, and every reference still holds.`
````
