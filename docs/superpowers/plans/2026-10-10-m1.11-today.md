# M1.11 Today Screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (chosen by Andrew on 10 Oct 2026) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A parent who unlocks the phone at 3 a.m. reads Today at a glance:
- how long since the last feed started, or the feed running now
- today's totals, or the last 24 hours' on a switch
- every feed and diaper of the last 24 hours, with who logged it

The other phone's entries appear on their own. A quick-action bar waits above the tabs for M1.12's sheets.

**Architecture:** `apps/web` gains three layers, each tested on its own:
- **Data:** `src/api/today.ts` holds the `today` and `last24h` queries, read through `useToday` and `useLast24h`. M1.10's socket already refreshes both on every change (D7). The contract's `recent` list skips entries this app can't read, so an installed app keeps working when M3 adds sleep and supplements (P1).
- **Time and logic:** `src/timer/` holds a clock that ticks as each second begins, read through `useSyncExternalStore`, so no `useEffect` (P3). `src/features/today/*.ts` turns the household's answers into what the cards show. It runs in Node tests, using `@bt/domain`'s `feedSummary`, `formatElapsed` and unit conversions.
- **Screen:** `src/features/today/*.tsx` holds the feed card, the totals card with its switch, the recent list and the quick-action bar, built on shadcn's Card. Components only display.

**Tech Stack:** React 19.3, TypeScript 5.9.3, TanStack Query 5.104.1, `effect` 4.0.1 with `@bt/contracts` and `@bt/domain`, shadcn 4.21.4 on Base UI, Tailwind CSS 4.3.3, `lucide-react` 1.51.0, Vitest 4.1.11, Playwright 1.64.0, oxlint 1.87.0 and oxfmt 0.72.0, Node 24.21.0. M1.11 adds no package to the catalog; `apps/web` starts depending on the workspace's `@bt/domain`.

## Decisions this plan makes (veto in review)

- **P1: Today's `recent` skips entries this app can't read, inside the contract.** This is the M1.10 handoff's first option.
  - `RecentEntries` is an array of `RecentEntry` or any JSON value, and drops what isn't a `RecentEntry` as it decodes. `Today.recent` uses it. The type stays `ReadonlyArray<RecentEntry>`, and the server encodes the same JSON as before.
  - M3.1 and M3.3 add sleep and supplement entries. An installed app still running M1.11's code then shows Today without them, rather than failing the whole response. The socket's `changedKeys` already skips keys that way (M1.10's P7).
  - It also skips a feed or diaper entry it can't read, as `changedKeys` does.
  - `docs/api.json` gains one `{}` member in the entries' `anyOf`: "or anything else".
  - The other option, `responseMode: "response-only"`, would make that one call classify status 0, 401 and 503 by hand.
- **P2: Two queries, fetched together.**
  - `todayQuery(api)` and `last24hQuery(api)` are `queryOptions` for `queryKeys.today` and `queryKeys.last24h`. `useToday` and `useLast24h` sit beside `useMe`.
  - The page asks for both when it opens. Fetching `last24h` only once the totals card mounted made a waterfall, and the socket specs' 4401 test caught that late answer (P12).
  - Queries don't pass TanStack's `signal`. A refetch that starts while another runs replaces its result anyway, so aborting would only save a little traffic for two phones. The M1.10 handoff's warning about aborting through `RequestInit` therefore doesn't arise.
- **P3: One clock for every ticking number.**
  - `createClock(1000)` notifies its listeners as each second begins, from a `setTimeout` aimed at the next whole second, so the display never skips or repeats a second.
  - `now()` is `Date.now()` rounded down to the second, so React reading it twice in one second sees the same value.
  - The clock stops its timer once nothing shows it, and `useNow()` reads it through `useSyncExternalStore`.
  - It only redraws and never sends anything. §3.5's "On `visibilitychange → visible` it calls `refetch`" is TanStack Query's `refetchOnWindowFocus`, which M1.10 turned on.
- **P4: The feed card has four states**, from `today.activeFeed` and `today.lastFeed`:

  | State | When | Shows |
  |---|---|---|
  | Running | the active feed has an open segment | "Feeding now · Left side", the feed's nursing so far ticking in violet (`formatElapsed`), "Started 2:10 AM" |
  | Paused | the active feed has no open segment (the M1.7 handoff) | "Feed paused", its nursing so far, still, and its start |
  | Since | no active feed, a last feed | "Since last feed started", "2 h 14 min", then the start time and the feed's parts: "2:10 AM · Left 12 min · Right 8 min · 60 mL" |
  | None | no feed yet | "No feeds yet" |

  - Nursing comes from `feedSummary(feed, now).nursingSeconds` (the M1.2 handoff).
  - "Since" counts whole seconds from the last feed's `startedAt` (the M1.8 handoff). It never goes below zero when the phone's clock runs behind the household's (AC 21), and shows "Just now" under a minute.
- **P5: The totals card switches between Today and Last 24 h** (Andrew, 10 Oct 2026).
  - It opens on Today each time the page mounts; the choice isn't kept.
  - Rows: Feeds started, Nursing (left and right beneath), Bottles (breast milk and formula beneath), and Diapers (pee and poo beneath). A part that's zero isn't listed.
  - The totals are the household's figures from the last fetch. The socket refetches them on every change (D7), and so does each return to the app after 5 s. Only the feed card ticks: during a running feed, Nursing grows at the next refetch, not every second.
- **P6: Bottles show in the household's unit** (the M1.15 handoff): mL rounded to the whole number, and fl oz to one decimal. Today shows no weights or lengths.
- **P7: Times are in the household's zone, written the phone's way.** `Intl.DateTimeFormat` with the phone's locale and `me.household.timeZone` gives "2:10 AM" on an en-US phone and "2:10 a.m." on an en-CA one.
- **P8: The words** (confirmed by Andrew in review).
  - Diapers read "pee" and "poo", as M1.12's Diaper sheet (Pee / Poo / Both) will.
  - A feed reads "Nursing", "Bottle" or "Nursing and bottle".
  - An unfinished feed in the recent list starts with "In progress" or "Paused".
  - Each part of a line stays on one line, so "60 mL" never breaks between its number and unit.
- **P9: The recent list is the household's `recent`**, newest first (M1.8's P4).
  - Each row shows an icon, the title, the parts, the time and who logged it (`createdBy`'s display name from `me`). A caregiver the household doesn't list is named by no one.
  - Rows aren't tappable until M3.4 brings editing.
- **P10: The quick-action bar sits above the tab bar, with Bottle, Nursing and Diaper disabled until M1.12** wires them to its sheets.
  - It's where a thumb rests at night, and M1.12's tap budget counts from it: a diaper is two taps (AC 2).
  - The page pads its foot by the bar's height.
  - Andrew kept it in M1.11 in review.
- **P11: Loading and failure.** Until `me` and `today` both arrive, Today says "Loading…". If either fails with nothing cached, it says "Today couldn't be loaded.", and the banner explains why: "No connection" or "Sign in to continue".
  - A failed `me` counts even when `today` arrived, since the page needs both. The first version read only `today`'s error and stayed on "Loading…" for good.
  - The totals card's Last 24 h view says "Loading…" until `last24h` arrives, and "The last 24 hours couldn't be loaded." if it fails. Its Today view and the rest of the page carry on.
- **P12: After a 4401, live updates stay off until the page reloads; "Sign in" reloads it.**
  - This reverses the default I proposed when offering M1.11 (restart on the next successful fetch). Andrew agreed in review.
  - A fetch already in flight when a caregiver is disabled can answer 200 after the 4401. That marks the session valid (M1.10's P3), so restarting on it could reopen a socket for a caregiver who's still disabled, retrying it for good.
  - The same late answer can clear the sign-in banner until the next fetch says 401. Since the caregiver re-enables rarely and "Sign in" reloads the page, M1.11 leaves both as they are. The socket specs wait for Today's first answers before acting (P14).
- **P13: shadcn's Card, by hand**, from 4.21.4's `base-nova` file with M1.10's P10 edits: `ComponentProps` imported from React, and no `cn-font-heading`, since the app keeps the system font.
- **P14: E2E with the household's answers played by the test.**
  - Most Today specs answer `/api/today` and `/api/last24h` with fixed JSON (as M1.15's P15 does) and fix the clock with `page.clock.setFixedTime`.
  - `pauseAt` doesn't work here. TanStack Query hands results to the screen through `setTimeout(0)`, which a paused clock never fires: under repeated runs, pages stayed on "Loading…".
  - One spec logs a real diaper through the household and waits for it to appear, which proves the socket's refresh end to end.
  - The socket specs' `beforeEach` waits for Today's first answers, so a late 200 can't race the 4401 test (P12).
  - `connectivity.spec.ts`'s sign-in spec has the household refuse every `/api/**` call, not `/api/me` alone (the commit "Make the sign-in spec's household refuse every call, now that Today asks for more than /api/me").
    - A household that refuses a caregiver refuses all of that caregiver's calls. With only `/api/me` refused, `/api/today` still answered 200, a mix the household can't produce, and that 200 cleared the banner (P12).
    - The plan's dry runs passed the old spec by chance: Chromium failed 2 of 4 runs of it with retries off.
  - `live.spec.ts` gains the sharper test the M1.10 handoff asked for: a `changed` message naming `["last24h"]` refetches that alone, now that `me`, `today` and `last24h` are all cached.
- **P15: Sizes.** The web bundle grows from 191.02 to 194.72 KB gzip, and the Worker from 255.35 to 255.95 KiB gzip, well under the 400 KiB budget. These are `main` at `2b82e20` against the finished branch. The plan's first measurements, on `main` at `be25a59` and the prototype, were 190.70 to 194.34 and 254.25 to 254.85.

```ts
export interface Clock {
  readonly now: () => number
  readonly subscribe: (listener: () => void) => () => void
}

export const createClock = (tickMs: number): Clock => {
  const listeners = new Set<() => void>()
  let next: ReturnType<typeof setTimeout> | undefined
  const now = () => Math.floor(Date.now() / tickMs) * tickMs
  const tick = () => {
    next = setTimeout(tick, tickMs - (Date.now() % tickMs))
    for (const listener of listeners) listener()
  }
  return {
    now,
    subscribe: (listener) => {
      listeners.add(listener)
      if (listeners.size === 1) next = setTimeout(tick, tickMs - (Date.now() % tickMs))
      return () => {
        listeners.delete(listener)
        if (listeners.size === 0) clearTimeout(next)
      }
    },
  }
}
```

```ts
import type { VolumeUnit } from "@bt/contracts"
import { flOzFromMl, roundTo } from "@bt/domain"

const MINUTE_S = 60
const HOUR_MIN = 60

export const formatMinutes = (seconds: number) => {
  if (seconds > 0 && seconds < MINUTE_S) return "<1 min"
  const minutes = Math.floor(seconds / MINUTE_S)
  const hours = Math.floor(minutes / HOUR_MIN)
  const rest = minutes % HOUR_MIN
  if (hours === 0) return `${minutes} min`
  return rest === 0 ? `${hours} h` : `${hours} h ${rest} min`
}

export const formatSince = (seconds: number) => (seconds < MINUTE_S ? "Just now" : formatMinutes(seconds))

export const formatVolume = (ml: number, unit: VolumeUnit) =>
  unit === "ml" ? `${Math.round(ml)} mL` : `${roundTo(flOzFromMl(ml), 1).toFixed(1)} fl oz`

export const clockTime = (instant: number, timeZone: string, locale?: string) =>
  new Intl.DateTimeFormat(locale, { hour: "numeric", minute: "2-digit", timeZone }).format(instant)

export const presentParts = (parts: ReadonlyArray<readonly [number, string]>) =>
  parts.filter(([amount]) => amount > 0).map(([, text]) => text)
```

```ts
import type { Feed, Side, Today } from "@bt/contracts"
import { feedSummary } from "@bt/domain"

export type FeedStatus =
  | { readonly kind: "running"; readonly feed: Feed; readonly side: Side; readonly nursingSeconds: number }
  | { readonly kind: "paused"; readonly feed: Feed; readonly nursingSeconds: number }
  | { readonly kind: "since"; readonly feed: Feed; readonly seconds: number }
  | { readonly kind: "none" }

const SECOND_MS = 1000

export const runningSide = (feed: Feed): Side | undefined =>
  feed.segments.find((segment) => segment.endedAt === null)?.side

const activeStatus = (feed: Feed, now: number): FeedStatus => {
  const { nursingSeconds } = feedSummary(feed, now)
  const side = runningSide(feed)
  return side === undefined ? { kind: "paused", feed, nursingSeconds } : { kind: "running", feed, side, nursingSeconds }
}

export const feedStatus = ({ activeFeed, lastFeed }: Pick<Today, "activeFeed" | "lastFeed">, now: number) => {
  if (activeFeed !== null) return activeStatus(activeFeed, now)
  if (lastFeed === null) return { kind: "none" } satisfies FeedStatus
  const seconds = Math.max(0, Math.floor((now - lastFeed.startedAt) / SECOND_MS))
  return { kind: "since", feed: lastFeed, seconds } satisfies FeedStatus
}
```

```ts
  readonly kind: RowKind
  readonly at: number
  readonly time: string
  readonly title: string

  readonly by: string

  if (feed.status === "completed") return []
  return [runningSide(feed) === undefined ? "Paused" : "In progress"]

  title: feedTitle(feed),

})

  id: diaper.id,
  kind: "diaper",
  at: diaper.occurredAt,
  time: clockTime(diaper.occurredAt, display.timeZone, display.locale),
  title: "Diaper",
  detail: [diaperDetail(diaper)],
  by: nameOf(display, diaper.createdBy),
})
```
