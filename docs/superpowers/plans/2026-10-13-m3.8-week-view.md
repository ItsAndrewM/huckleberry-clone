# M3.8 Calendar Week View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (chosen by Andrew on 13 Oct 2026) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** History shows a whole week at a glance, so a parent can see when she fed and when each diaper came across seven days, then tap a day to read it. Both views gain Feeds, Diapers and Growth filters, and a way to go to any date.

**Architecture:**
- **The wall-clock day** (`packages/domain/src/calendar/wall-clock-day.ts`, pure, held at 100 % coverage): `onWallClock(day)` moves a `DayInput` onto the household's wall clock, so `layoutDay` gives every column of a week the same 24 rows, whatever the clocks did that day.
- **The week's model** (`apps/web/src/features/history/week-model.ts`, Node tests): `weekModel(week, context)` turns M3.6's `WeekPeriod` into seven columns, Monday first, each laid out at 10-minute steps from M3.7's own pieces (`piecesOf`, now exported from `day-model.ts`), with the kinds the filters hide left out.
- **The address** (`history-period.ts`, `history-navigation.ts`, `history-kinds.ts`): `/history?view=week&date=<Monday>&hide=<kinds>`, read by the router's `validateSearch`, stepping a day or a week as Trends does.
- **The page** (`history-page.tsx`): Day | Week in the page header; a sticky switcher with ‹ › and Change → Go to; the chips; then the Day view (M3.7's) or the Week view, whose grid fits the screen through container query units.

**Tech Stack:** React 19.3.0, TypeScript 5.9.3, TanStack Router 1.170.41 (search params) and Query 5.104.1, `effect` 4.0.1 (Schema), `@bt/contracts` and `@bt/domain`, shadcn on Base UI 1.8.0 (`ToggleGroup` with `multiple`, `Input`, `Button`), Tailwind CSS 4.3.3 (functional `@utility` classes, container query units in arbitrary values), `lucide-react` 1.51.0, Vitest 4.1.11 with fast-check 4.10.2, Playwright 1.64.0, oxlint 1.87.0 and oxfmt 0.72.0, Node 24.21.0. ## Decisions this plan makes (veto in review)

- **P1: The wall clock.** Every column shares one set of hour labels. On a day the clocks go back, both passes of the repeated hour draw on its rows, side by side where they overlap. On a day they go forward, the skipped hour stays empty and a side across it is drawn as long as the clock says. A side whose clock goes back as it ends is drawn from its start (`onWallClock` clamps it). America/Vancouver has no more clock changes after tzdata 2026c, so the tests use America/Los_Angeles.
- **P2: Fitting the screen.** A column's step is its own height over 144 (`[container-type:size]` and `--cal-step: calc(100cqh / 144)`), at 10-minute steps. On an iPhone 15 that's about 17 px an hour installed (406 px of grid) and 12.8 px in a Safari tab (307 px). The week stops shrinking at 288 px (`min-h-72`) and the page scrolls. The hour lines are drawn by a child of the column, because container query units on an element resolve against an ancestor, never the element itself.
- **P3: The marks.**
  - A nursing feed is a bar in the column's left half, each side shaded as on the Day view and at least 20 minutes tall.
  - A bottle on its own and a diaper are 6 px dots, in two lanes of their own; each kind gathers within 20 minutes.
  - A measurement is a ruler beside the day's date.
  - Today has the now line, with the rest of its day greyed. A day before her birth date or after today is greyed and doesn't open.
- **P4: Names.** Each column that opens is one link, named with the day's totals for the kinds shown: "Fri, Oct 9: 4 feeds started, 58 min nursing, 150 mL in bottles; 3 diapers, 2 pee; a measurement", or "Mon, Oct 5: nothing logged". The bars, dots, headers and hours are hidden from screen readers.
- **P5: The address.** `?view=week&date=<Monday>&hide=diapers,growth`. Today and this week leave the date out, so they follow the household's midnight. `hide` is written in one order (feeds, diapers, growth), and anything else in it is dropped. M3.10's `?date=` links keep opening the Day view.
- **P6: Switching.** Day → Week opens the week that holds the day. Week → Day opens today when the week holds it, otherwise its Monday (Trends' rule). The toggle sits in the page header, as the grill's preview showed, not full width as on Trends.
- **P7: History entries.** A chip replaces the current history entry, so Back leaves History rather than undoing a chip. The arrows, the toggle, a column and Go to each push one.
- **P8: The Day view's filters.** The chips hide the grid's blocks and markers and the growth strip. The totals line stays whole, and "Nothing logged." shows only when nothing was logged, hidden or not.
- **P9: Go to.** Change toggles a "Go to" row: a labelled `Input` with `type="date"`, `min` her birth date and `max` today, focused as it opens. A date in range navigates and closes the row; an incomplete or out-of-range value does nothing.
- **P10: The sticky switcher.** It sticks below the safe area while the Day view scrolls. Offline, the No-connection banner (also sticky, above it) covers it once the page is scrolled; scrolling back up shows it. Left as is.
- **P11: The legend.** A line under the week names the marks shown: Nursing, Bottle, Diaper, Measured.
- **P12: Size.** The prototype measured +2.95 kB gzip of JS (319.01 to 321.96 kB) and +0.44 kB of CSS (11.46 to 11.90 kB) against M3.10's head, inside M5.5's 350 kB limit.

## Review Focus

The five ways this is most likely to fail a parent, each with the test that pins it:

1. **A phone in another zone than the household's.**
   - Columns, hours and the now line must follow the household's clock.
   - Pinned by `wall-clock-day.test.ts` ("puts every moment of a day at its wall-clock minute", a property over every zone with a clock change, Task 1) and every `history-week.spec.ts` test, which run the phone in Europe/London (Tasks 4–7).
2. **The nights the clocks change.**
   - Each column keeps 24 rows; both 1:30s land on the same row.
   - Pinned by `wall-clock-day.test.ts` ("draws a 25-hour day as 24 rows…", "draws a 23-hour day…", "keeps a side whose clock goes back…", Task 1).
3. **A feed across midnight, and one still running.**
   - It shows in both days' columns, cut at midnight, and a running feed reaches now.
   - Pinned by `history-week.test.ts` ("draws a feed across midnight in both days, and today's now line on today alone", Task 2).
4. **A filter left on.**
   - It must never stick unseen: it lives in the address only, a fresh History opens with every chip on, and it carries across views and days.
   - Pinned by `history-kinds.test.ts` (Task 2) and `history-week.spec.ts` ("hides a kind on both views, and keeps it while stepping and switching", Task 6).
5. **A small phone or larger text.**
   - The week fits above the tab bar, or scrolls sideways with the hours in view.
   - Pinned by `history-week.spec.ts` ("fits all 24 hours of the week on the screen, above the tab bar" and "on a narrow screen › scrolls the week sideways, keeping the hours in view", Task 5).

import { utcMidnightOf } from "../time/calendar.ts"
import { DAY_MS, type Instant } from "../time/instant.ts"
import { offsetMsAt } from "../time/zone.ts"
import type { Span } from "../timer/timer.ts"
import type { DayInput } from "./layout.ts"

const WALL_ZONE = "UTC"

export const onWallClock = <Kind extends string>(day: DayInput<Kind>): DayInput<Kind> => {
  const wall = (at: Instant) => at + offsetMsAt(day.zone, at)
  const onWall = <Item extends Span>(item: Item): Item => {
    const startedAt = wall(item.startedAt)
    const endedAt = item.endedAt === null ? null : Math.max(startedAt, wall(item.endedAt))
    return { ...item, startedAt, endedAt }
  }
  const start = utcMidnightOf(day.date)
  return {
    date: day.date,
    zone: WALL_ZONE,
    bounds: { start, end: start + DAY_MS },
    now: wall(day.now),
    blocks: day.blocks.map((block) => ({ ...onWall(block), bands: block.bands.map(onWall) })),
    points: day.points.map((point) => ({ ...point, at: wall(point.at) })),
  }
}

import { flow, Option, Schema } from "effect"

export const SHOWN_KINDS = ["feeds", "diapers", "growth"] as const

export type ShownKind = (typeof SHOWN_KINDS)[number]

export type Hidden = ReadonlySet<ShownKind>

const isShownKind = (value: string): value is ShownKind => SHOWN_KINDS.some((kind) => kind === value)

export const hiddenIn = (hide: string | undefined): Hidden => new Set((hide ?? "").split(",").filter(isShownKind))

export const hideOf = (hidden: Hidden): string | undefined => {
  const listed = SHOWN_KINDS.filter((kind) => hidden.has(kind))
  return listed.length === 0 ? undefined : listed.join(",")
}

export const hideInSearch = flow(
  Schema.decodeUnknownOption(Schema.String),
  Option.flatMap((hide) => Option.fromNullishOr(hideOf(hiddenIn(hide)))),
  Option.getOrUndefined,
)

export const hiddenExcept = (shown: ReadonlyArray<string>): Hidden =>
  new Set(SHOWN_KINDS.filter((kind) => !shown.includes(kind)))

import type { IsoWeek, LocalDate } from "@bt/contracts"
import { addDaysToDate, isoWeekMonday, isoWeekOfDate } from "@bt/domain"

export type HistoryView = "day" | "week"

export type HistoryPeriod =
  | { readonly view: "day"; readonly date: LocalDate }
  | { readonly view: "week"; readonly week: IsoWeek }

export const periodOf = (view: HistoryView, date: LocalDate): HistoryPeriod =>
  view === "day" ? { view, date } : { view, week: isoWeekOfDate(date) }

export const firstDateOf = (period: HistoryPeriod): LocalDate =>
  period.view === "day" ? period.date : isoWeekMonday(period.week)

export const lastDateOf = (period: HistoryPeriod): LocalDate =>
  period.view === "day" ? period.date : addDaysToDate(isoWeekMonday(period.week), 6)

export const holds = (period: HistoryPeriod, date: LocalDate) =>
  firstDateOf(period) <= date && date <= lastDateOf(period)

export const periodBefore = (period: HistoryPeriod): HistoryPeriod =>
  periodOf(period.view, addDaysToDate(firstDateOf(period), -1))

export const periodAfter = (period: HistoryPeriod): HistoryPeriod =>
  periodOf(period.view, addDaysToDate(lastDateOf(period), 1))

export const periodKey = (period: HistoryPeriod) => `${period.view}:${firstDateOf(period)}`
