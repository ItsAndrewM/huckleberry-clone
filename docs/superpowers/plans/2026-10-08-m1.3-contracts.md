# M1.3 Contracts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, chosen by Andrew on 8 Oct 2026) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `@bt/contracts` gets the wire vocabulary that every endpoint shares: time schemas that reject anything the domain can't handle, the API errors with their HTTP statuses, the stable conflict codes, and the query keys behind the `changed` list.

**Architecture:** Effect 4 schemas in `packages/contracts/src/<module>.ts`, re-exported from `src/index.ts`. The schemas never parse dates themselves: their filters call new non-throwing predicates in `@bt/domain` (`isLocalDate`, `isIsoWeek`, `isYearMonth`) and the existing `canonicalTimeZone`. Errors are `Schema.TaggedError` classes carrying `httpApiStatus`. A conflict is declared per record type through a `Conflict<Self>()` builder. The error tests run each error through a real http-api handler. A property test checks that every key the server derives decodes on the client. A repo-wide lint rule bans the two number schemas that accept NaN.

**Tech Stack:** TypeScript 5.9.3, `effect` 4.0.1 (`effect`, `effect/http`, `effect/http-api`), Vitest 4.1.11, `fast-check` 4.10.2, oxlint 1.87.0 + oxfmt 0.72.0.

## Decisions this plan makes (veto in review)

- **P1: Shared pieces only** (Andrew, 8 Oct 2026). M1.3 builds the time schemas (`Instant`, `LocalDate`, `IsoWeek`, `YearMonth`, `TimeZone`), the errors and conflict codes, and the query keys with the `changed` list. Each endpoint's request and response schemas come with the task that builds the endpoint: M1.5 `/api/me`, M1.6 diapers, M1.7 feeds, M1.8 today and last24h. The http-api definition and `docs/api.json` start in M1.5 with the first endpoint. So do `ActionId` and `Version`, which M1.5's receipts need first.
- **P2: The domain decides what a real date is, without throwing.** New `isLocalDate`, `isIsoWeek` and `isYearMonth` return a boolean. `utcMidnightOf` and `isoWeekMonday` now throw exactly when they return false. The M1.2 handoff suggested calling `addDaysToDate(s, 0)` inside a schema filter. But a filter that throws escapes Effect's decoder as an exception, checked with `decodeUnknownExit`, which rethrew the `RangeError`. Over HTTP that's a 500, not an `InvalidInput`. §1 changes to say contracts may import domain functions, not just types.
- **P3: `Instant` is an integer number of epoch milliseconds from 2000-01-01T00:00Z up to, but not including, 2100-01-01T00:00Z.** The bounds reject NaN and ±Infinity, which Effect's JSON codec builds from the strings `"NaN"` and `"Infinity"`. They also reject fractions, and seconds or microseconds sent by mistake. Every domain function stays on four-digit years. The real limits (not before birth, not in the future) stay with the core's validators.
- **P4: Dates, weeks and months allow years 1999–2100, one year either side of the instant range.** An instant in range can fall on 1999-12-31 (UTC−12) or 2100-01-01 (UTC+14) locally, in week 1999-W52 or 2099-W53, and every key the server sends must decode on the client. The window also keeps years 0–99 away from `nextMonth` and `isoWeekMonday`, where `Date.UTC` reads them as 1900–1999.
- **P5: `TimeZone` accepts whatever `canonicalTimeZone` accepts.** That includes aliases (`US/Pacific`), `UTC` and `Etc/GMT±N`, but not fixed offsets (`-07:00`). Which zones a household may use, and storing the canonical name, are for M1.5 and M1.15.
- **P6: Errors are `Schema.TaggedError` classes carrying `httpApiStatus`:** `Unauthorized` 401, `InvalidInput` 400, `NotFound` 404, `RateLimited` 429, `ServiceUnavailable` 503. `Unauthorized` encodes as `{"_tag":"Unauthorized"}`, which is the body the Worker already sends. `httpApiStatus` is an untyped annotation, so a typo compiles. Only the http-api test in Task 3 catches it.
- **P7: `Conflict` is built per record type:** `class FeedConflict extends Conflict<FeedConflict>()(["FEED_ALREADY_ACTIVE", "STALE_VERSION"], Feed) {}`. `current` has that endpoint's record type, and `code` is limited to the codes that endpoint can raise. So there's no single `ApiError` schema: each endpoint's error list (M1.5 on) is its union. `ConflictCode` lists the eight stable codes from §3.2.
- **P8: `InvalidInput.fieldErrors` is a list of `{ path, issue }`.** `path` is the field's dotted path (`portions.0.formulaMl`, or `""` for the whole body). `issue` is a domain `ValidationIssue`, or `invalid` for input that failed schema decoding. The domain exports `VALIDATION_ISSUES` so the list lives in one place. Turning a decode failure into `InvalidInput` is M1.5's job (Handoffs).
- **P9: Lint bans `Schema.Number` and `Schema.NumberFromString` in every package,** with `no-restricted-properties`. `Schema.Number`'s JSON codec decodes the strings `"NaN"`, `"Infinity"` and `"-Infinity"`. `Schema.NumberFromString` decodes them too, and reads `""` as 0. Use `Schema.Finite`, `Schema.Int` or `Schema.FiniteFromString`.
- **P10: `QueryKey` is one schema for all eight key kinds, and `queryKeys` builds them.** `Changed` is the list that mutation responses and socket messages carry (§3.3, §3.4). Its day, week and month members use the P4 schemas, so a `PeriodKey[]` from `affectedPeriods` type-checks as `QueryKey[]`.
- **P11: Contract tests run in a new `contracts` Vitest project.** They aren't under the coverage gate, which §3.1 sets for the domain only.

## Review Focus

1. **Non-finite numbers sent as strings.** Effect's JSON codec turns `"NaN"`, `"Infinity"` and `"-Infinity"` into numbers for `Schema.Number`. A buggy or stale client could then store a feed that starts at NaN, which breaks every summary for that day. Expect `Instant` to reject all three, and lint to reject `Schema.Number` and `Schema.NumberFromString` in contracts, the Worker and the web app. Tested in Task 2.
2. **Timestamps in the wrong unit.** A client that sends seconds puts the entry in January 1970; one that sends microseconds puts it around the year 57,000. Expect a 400, not an entry. Tested in Task 2.
3. **An impossible date in a URL or form**, such as `/days/2026-02-30`, `2026-W54` or `2026-13`. A domain parser that throws inside a filter escapes as an exception, so the request becomes a 500. Expect the schema to reject it like any other bad input, and the predicates never to throw. Tested in Tasks 1 and 2.
4. **The other phone not refreshing after an entry near the edge of the range.** If the client can't decode one key in a `changed` list, it can't use the list. An instant at 2000-01-01T00:00Z is still 1999-12-31, in week 1999-W52, at UTC−12. Expect every key `affectedPeriods` derives from an in-range instant, in any zone, to decode. Tested in Task 4.
5. **A conflict that arrives as a 500.** A misspelt `httpApiStatus` compiles and becomes a 500. Then the "Emily changed this a moment ago" prompt never shows, and a 401 no longer reads as "sign in again". Expect each error's status and JSON body, sent through a real http-api handler, to be exactly as declared. Tested in Task 3.

```ts
import { tz } from "@date-fns/tz"
import { getISOWeek, getISOWeekYear, setISOWeek, startOfISOWeek } from "date-fns"
import { DAY_MS } from "./instant.ts"

export type LocalDate = string
export type IsoWeek = string
export type YearMonth = string

const utc = tz("UTC")

export const utcDateOf = (ms: number): LocalDate => new Date(ms).toISOString().slice(0, 10)

const LOCAL_DATE_FORMAT = /^\d{4}-\d{2}-\d{2}$/
const ISO_WEEK_FORMAT = /^(\d{4})-W(\d{2})$/

const midnightOf = (date: string): number | null => {
  const ms = Date.parse(`${date}T00:00:00Z`)
  return LOCAL_DATE_FORMAT.test(date) && Number.isFinite(ms) && utcDateOf(ms) === date ? ms : null
}

export const isLocalDate = (value: string): boolean => midnightOf(value) !== null

export const isYearMonth = (value: string): boolean => isLocalDate(`${value}-01`)

export const utcMidnightOf = (date: LocalDate): number => {
  const ms = midnightOf(date)
  if (ms === null) throw new RangeError(`Expected a date like 2026-10-06, got "${date}"`)
  return ms
}

export const addDaysToDate = (date: LocalDate, days: number): LocalDate =>
  utcDateOf(utcMidnightOf(date) + days * DAY_MS)

export const datesBetween = (first: LocalDate, last: LocalDate): LocalDate[] => {
  const dates: LocalDate[] = []
  const end = utcMidnightOf(last)
  for (let ms = utcMidnightOf(first); ms <= end; ms += DAY_MS) dates.push(utcDateOf(ms))
  return dates
}

export const monthOfDate = (date: LocalDate): YearMonth => utcDateOf(utcMidnightOf(date)).slice(0, 7)

export const nextMonth = (month: YearMonth): YearMonth => {
  const first = new Date(utcMidnightOf(`${month}-01`))
  return monthOfDate(utcDateOf(Date.UTC(first.getUTCFullYear(), first.getUTCMonth() + 1, 1)))
}

export const isoWeekOfDate = (date: LocalDate): IsoWeek => {
  const day = utc(utcMidnightOf(date))
  return `${getISOWeekYear(day)}-W${String(getISOWeek(day)).padStart(2, "0")}`
}

const mondayOf = (week: string): LocalDate | null => {
  const [, year, weekNumber] = ISO_WEEK_FORMAT.exec(week) ?? []
  if (weekNumber === undefined) return null
  const monday = utcDateOf(startOfISOWeek(setISOWeek(utc(Date.UTC(Number(year), 0, 4)), Number(weekNumber))).getTime())
  return isLocalDate(monday) && isoWeekOfDate(monday) === week ? monday : null
}

export const isIsoWeek = (value: string): boolean => mondayOf(value) !== null

export const isoWeekMonday = (week: IsoWeek): LocalDate => {
  const monday = mondayOf(week)
  if (monday === null) throw new RangeError(`Expected an ISO week like 2026-W41, got "${week}"`)
  return monday
}
```

```ts
import { canonicalTimeZone, isIsoWeek, isLocalDate, isYearMonth } from "@bt/domain"
import { Schema } from "effect"

const FIRST_INSTANT = Date.UTC(2000, 0, 1)
const INSTANT_LIMIT = Date.UTC(2100, 0, 1)
const FIRST_CALENDAR_YEAR = 1999
const LAST_CALENDAR_YEAR = 2100

const inCalendarYears = (value: string) => {
  const year = Number(value.slice(0, 4))
  return year >= FIRST_CALENDAR_YEAR && year <= LAST_CALENDAR_YEAR
}

const calendarString = (isReal: (value: string) => boolean, example: string) =>
  Schema.String.check(
    Schema.makeFilter((value: string) => isReal(value) && inCalendarYears(value), {
      expected: `${example} from ${FIRST_CALENDAR_YEAR} to ${LAST_CALENDAR_YEAR}`,
    }),
  )

export const Instant = Schema.Int.check(Schema.isGreaterThanOrEqualTo(FIRST_INSTANT), Schema.isLessThan(INSTANT_LIMIT))
export type Instant = typeof Instant.Type

export const LocalDate = calendarString(isLocalDate, "a date like 2026-10-06")
export type LocalDate = typeof LocalDate.Type

export const IsoWeek = calendarString(isIsoWeek, "an ISO week like 2026-W41")
export type IsoWeek = typeof IsoWeek.Type

export const YearMonth = calendarString(isYearMonth, "a month like 2026-10")
export type YearMonth = typeof YearMonth.Type

export const TimeZone = Schema.String.check(
  Schema.makeFilter((name: string) => canonicalTimeZone(name) !== null, {
    expected: "an IANA time zone like America/Vancouver",
  }),
)
```
