# M1.2 Domain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `@bt/domain` gets the pure functions M1 builds on: time zones and local dates, half-open intervals, timers, feed summaries, validation, units and cache-key invalidation. A CI gate holds the package at 100 % coverage.

**Architecture:** Pure functions in `packages/domain/src/<module>/`, re-exported from `src/index.ts`. Tests and other packages import only `src/index.ts`. All zone math goes through one primitive, `offsetMsAt`, which wraps `tzOffset` from `@date-fns/tz`. `resolveLocal` finds the instants behind a wall-clock time by checking the zone's offsets a day either side. Every day, week and month boundary comes from `startOfDate`. Tests run in a new `domain` Vitest project under a host zone that isn't UTC, and fast-check properties are checked against `Intl`.

**Tech Stack:** TypeScript 5.9.3, `date-fns` 4.4.0, `@date-fns/tz` 1.5.0, Vitest 4.1.11 + `@vitest/coverage-v8` 4.1.11, `fast-check` 4.10.2, oxlint 1.87.0 + oxfmt 0.72.0.

**Spec:** `docs/implementation-plan.md`: the M1.2 row, §1 (layout), §3.1 (`packages/domain`), D7, D11, D12, §5, and §6 (domain tests and named fixtures). The product spec (v0.10) isn't in the repo. The fixtures follow the plan's one-line descriptions of AC 3, 4, 8, 12, 21 and 23. Andrew confirmed the AC 3 and AC 4 readings on 8 Oct 2026. Every code block below was run before this plan was written. Each task's tests fail first and then pass, and after each task `pnpm coverage`, `pnpm typecheck`, `pnpm lint` and `pnpm test` all pass.

## Global Constraints

- Exact versions, each defined once in the `pnpm-workspace.yaml` catalog. Packages use `catalog:`. `@vitest/coverage-v8` must equal `vitest` (4.1.11).
- `packages/domain/src` imports only `date-fns`, `@date-fns/tz` and its own files. That means nothing from the workspace, no framework, and no `node:*` or `cloudflare:*` (§1, §3.1; lint enforces it).
- Nothing reads the clock or the host's time zone. `now` and `zone` are always arguments. So: no `Date.now()`, no `new Date()` without an argument, no `new Date(y, m, d)`, no local getters such as `getHours()` or `getDate()`, and no date-fns call on a plain `Date` (§3.1).
- An `Instant` is epoch milliseconds (UTC). Intervals are half-open: `[start, end)`.
- Style: no semicolons, double quotes, 2-space indent, 120 columns, `.ts` extensions on relative imports. `pnpm format` writes; `pnpm lint` checks. The code below is already formatted.
- Lint bans comments of every kind (`gamesheet/no-comments`). Don't turn a comment into JSDoc or a `SAFETY:` comment to get past the rule; put the reason in a name or a test title. No type assertions except `as const`. Complexity is at most 10 per function. The anti-slop rules ban `unknown` and `object` parameters, `typeof` checks, "shape" in names, and module mocking.
- No coverage-ignore comments (`v8 ignore`, `istanbul ignore`). The lint rule allows them; this plan doesn't.
- Tests import from `../../src/index.ts`, the public API, never from module files.
- Out of scope: `aggregate/` (M1.8, M3.6), `growth/` (M4), and any change outside `packages/domain` except the root config, CI, README and docs edits listed below.

## Decisions this plan makes (veto in review)

- **P1:** Coverage runs as `pnpm coverage` (`vitest run --project domain --coverage`, v8), not inside `pnpm test`, because Vitest accepts coverage options only in the root config. With `thresholds: { 100: true }` it fails below 100 % statements, branches, functions or lines. CI gets a step for it.
- **P2:** Domain tests run with `TZ=Australia/Lord_Howe`, set in the project's `test.env`. That zone isn't UTC, shifts by 30 minutes for DST, and is in the southern hemisphere. Code that reads the host zone therefore fails both locally and in CI.
- **P3:** `startOfDate` resolves local midnight with `resolveLocal` instead of `new TZDate(y, m, d, zone)`. When midnight happens twice, `TZDate` picks the later one (Havana, Gaza, Scoresbysund), which would start those days an hour late. `startOfDate`, `resolveLocal` and `localDateOf` were checked against an `Intl` brute-force oracle for all 418 IANA zones at every DST change from 2015 to 2030. There were no mismatches.
- **P4:** Plain type aliases, no brands. `Instant` is `number`; `LocalDate`, `IsoWeek`, `YearMonth`, `LocalDateTime` and `TimeZone` are `string`. A brand would need a type assertion, with its `SAFETY:` comment, in every constructor, and a matching Effect brand in M1.3. Instead, every function that parses one of these strings throws `RangeError` on anything malformed or impossible. Without that check, V8's `Date.parse` reads `2026-02-30` as 2 March, date-fns rolls `2026-W54` into 2027, and `tzOffset` returns `NaN` for an unknown zone.
- **P5:** Domain owns the period keys: `PeriodKey = ["day", LocalDate] | ["week", IsoWeek] | ["month", YearMonth]`. `@bt/contracts` builds `QueryKey` on top in M1.3, because domain may not import contracts. `affectedPeriods(old, new, zone)` takes `Interval | null` for each side and treats a point event as `{ start: t, end: t }`. It returns days, then weeks, then months. The caller adds `today` and `last24h` (§5).
- **P6:** Feed input types are the minimum §3.1 needs. A segment is `{ side, startedAt, endedAt | null }`. A portion is `{ occurredAt, breastMilkMl, formulaMl }`, so a mixed bottle is one portion (AC 3). §8 isn't in the repo, so M1.5's migration decides the columns, and M1.7 maps rows into these types. `feedSummary(feed, now)` takes `now` so an active feed's preview counts the running side (§3.4).
- **P7:** Validators return a `ValidationIssue` code or `null`. M1.6 onwards can then fill `InvalidInput{fieldErrors}` one field at a time.
- **P8:** Bottles use the US fluid ounce (29.5735295625 mL), confirmed by Andrew on 8 Oct 2026. Units are a display setting that parents can switch back and forth at any time, and switching never changes a stored value. Values are always stored as mL, g and cm. `mlFromFlOz` rounds to 0.1 mL, the precision volumes are stored at, so an ounce entry passes volume validation. Any amount entered to a tenth of an ounce shows the same after a switch to mL and back. Grams and centimetres stay at full precision (§3.1). `poundsOuncesFromGrams` rounds the total ounces before splitting, so 7 lb 15.97 oz shows as 8 lb 0.0 oz.
- **P9:** These are additions to §3.1's list, each needed within M1:
  - `canonicalTimeZone`, for the M1.5 seed script and M1.15 Settings. It rejects fixed offsets such as `-07:00`, which never observe DST.
  - `mlFromFlOz` and `flOzFromMl`, for the ounce steppers in M1.12.
  - `startOfDate`.
  - The calendar helpers `addDaysToDate`, `datesBetween`, `isoWeekOfDate`, `isoWeekMonday`, `monthOfDate` and `nextMonth`.
- **P10:** `formatElapsed` shows `m:ss` under an hour and `h:mm:ss` from an hour (`0:59`, `59:59`, `1:00:00`), confirmed by Andrew on 8 Oct 2026.
- **P11:** Property tests call `fc.assert` inside `it`, without the `@fast-check/vitest` wrapper. Half of the sampled instants fall within 3 hours of a DST change in one of ten zones, because uniform samples over 15 years almost never land on one.

## Review Focus

1. **DST days.** Expect exact results for 23- and 25-hour days, a repeated 01:30, a skipped 02:30, and the first of Havana's two midnights. A mistake here puts a night feed on the wrong day twice a year. Tested by exact Vancouver, London, Lord Howe, Havana and Santiago fixtures (Tasks 2, 3 and 5), and by `Intl`-oracle properties sampled around every DST change in ten zones.
2. **A bottle or diaper that changes no day.** A point event is `{ start: t, end: t }`, which is an empty half-open interval. Expect it to invalidate its day, week and month anyway; otherwise the other phone never refreshes after a bottle. Tested in Task 7.
3. **Phone clock skew.** A phone that is behind the server shows `-0:03`; one that is ahead gets its entry rejected as "in the future". Expect timers to clamp at 0, and `validateNotInFuture` to allow exactly 5 minutes (AC 21). Tested in Tasks 4 and 6.
4. **Numbers that don't add up on screen.** Examples: `7 lb 16.0 oz`, `0.30000000000000004 mL`, left plus right not matching the total, an ounce bottle failing the 0.1 mL rule, or an amount that changes when a parent switches units. Expect a carry into pounds, sums in tenths of a mL, each side floored before the sides are added, `mlFromFlOz` rounded to 0.1 mL, and every tenth of an ounce shown unchanged after a switch to mL and back. Tested in Tasks 4 and 6.
5. **The host's time zone leaking in.** Code that reads the machine's zone passes on UTC CI and breaks for a parent whose phone is in another zone. Expect every domain test to run under `TZ=Australia/Lord_Howe`. Tested in Task 1 (`test/harness.test.ts`).

## Post-review notes

Execution changed these points. The task text below is the plan as written before review.

- **Two host zones (P2, Review Focus 5).** Australia/Lord_Howe sits east of UTC, so it can't expose local getters, or date-fns on a plain `Date`, in code that works on UTC midnights. Only a zone west of UTC does. Task 1's review added a second Vitest project, `domain-west` (America/Adak, UTC−10/−9 with DST, used by no fixture), defined inline in the root `vitest.config.ts`. Each project provides its `hostZone`, and `test/harness.test.ts` asserts it with `inject`. `pnpm test` runs both projects; `pnpm coverage` stays on `domain`.
- **`datesBetween` validates both ends (Task 1).** It parses `first` and `last` with `utcMidnightOf` and iterates on milliseconds, so a malformed end throws `RangeError` instead of looping. Six throw tests were added.
- **Task 1 Step 11's gate check.** Deleting `"2026-02-30"` no longer fails the gate, because the new `datesBetween` rows reach the same throw. The step also said "the first `it.each`", but it means the `throws on %j instead of guessing a date` one. To see the gate fail now, shrink the ISO-week throws list to `["2026-41"]`. `pnpm coverage` then exits 1, because `isoWeekMonday`'s throw goes uncovered (97.14 % statements at Task 1).
- **`offsetMsAt` checks the zone (Task 2).** `tzOffset` returns non-numbers for names like `"constructor"`, and it treats names containing `±HH` as fixed offsets. That let some unknown zones past a `NaN` check. `offsetMsAt` now checks each zone once against `canonicalTimeZone` (memoized) and throws `RangeError` for any zone it rejects, fixed offsets included. There's no `NaN` check any more.
- **Test counts.** From Task 2 on, the `domain` project has 10 more tests than each task's expected output: 6 `datesBetween` rows and 4 zone rows. `pnpm test` also runs the `domain-west` copy. Task 7's review added 3 more tests: a point event at exactly local midnight, a same-day edit and an edit that moves a record earlier. After Task 7 the counts were 182 per domain project and 461 for `pnpm test`.
- **§3.1 wording (Task 8).** `docs/implementation-plan.md` now says functions taking a date, week, month or zone string throw `RangeError`, and that `canonicalTimeZone` returns `null` instead. This supersedes the sentence quoted in Task 8 Step 1.
- **Final review fixes.** `utcMidnightOf` also checks the `YYYY-MM-DD` format, so expanded years such as `+010000-01` throw. `splitByDays` throws on a non-finite end instead of running away. `validateVolumeMl` rejects positive volumes below 0.1 mL. Three interface claims gained tests: the per-segment clamp, a running segment beside closed ones, and several segments on one side. The unit round trips now check every case instead of sampling. Final counts: 194 tests per domain project, 485 for `pnpm test`.
- **Time-zone data (PR #6 CI).** IANA tz 2026b (April 2026) made British Columbia permanent UTC−7, so `America/Vancouver` no longer falls back on 2026-11-01. CI's Node 22.23.3 (tz 2026c) has that rule; local Node 22.23.1 (tz 2026a) didn't, so the Vancouver fall-back fixtures failed only in CI. They now use Vancouver's last fall-back, 2025-11-02, and pass on both tz versions. The code needed no change, because it reads offsets from the runtime's tz data.
- **PR review fixes (CodeRabbit).** `validateEndAfterStart`, `validateNotBeforeBirth` and `validateNotInFuture` return `not_finite` for `NaN` or ±Infinity instants instead of comparing them. `feedSummary` sums raw volumes and rounds the total to 0.1 mL, so two 40.15 mL portions give 80.3, not 80.4. Results for valid volumes, which have at most one decimal, are unchanged. Final counts: 205 tests per domain project, 507 for `pnpm test`.

```ts
import { tz } from "@date-fns/tz"
import { getISOWeek, getISOWeekYear, setISOWeek, startOfISOWeek } from "date-fns"
import { DAY_MS } from "./instant.ts"

export type LocalDate = string
export type IsoWeek = string
export type YearMonth = string

const utc = tz("UTC")

export const utcDateOf = (ms: number): LocalDate => new Date(ms).toISOString().slice(0, 10)

export const utcMidnightOf = (date: LocalDate): number => {
  const ms = Date.parse(`${date}T00:00:00Z`)
  if (utcDateOf(ms) !== date) throw new RangeError(`Expected a date like 2026-10-06, got "${date}"`)
  return ms
}

export const addDaysToDate = (date: LocalDate, days: number): LocalDate =>
  utcDateOf(utcMidnightOf(date) + days * DAY_MS)

export const datesBetween = (first: LocalDate, last: LocalDate): LocalDate[] => {
  const dates: LocalDate[] = []
  for (let date = first; date <= last; date = addDaysToDate(date, 1)) dates.push(date)
  return dates
}

export const monthOfDate = (date: LocalDate): YearMonth => utcDateOf(utcMidnightOf(date)).slice(0, 7)

export const nextMonth = (month: YearMonth): YearMonth => {
  const first = new Date(utcMidnightOf(`${month}-01`))
  return monthOfDate(utcDateOf(Date.UTC(first.getUTCFullYear(), first.getUTCMonth() + 1, 1)))
}

export const isoWeekOfDate = (date: LocalDate): IsoWeek => {
  const day = utc(utcMidnightOf(date))
  return `${getISOWeekYear(day)}-W${String(getISOWeek(day)).padStart(2, "0")}`
}

export const isoWeekMonday = (week: IsoWeek): LocalDate => {
  const [year = Number.NaN, weekNumber = Number.NaN] = week.split("-W").map(Number)
  const monday = utcDateOf(startOfISOWeek(setISOWeek(utc(Date.UTC(year, 0, 4)), weekNumber)).getTime())
  if (isoWeekOfDate(monday) !== week) throw new RangeError(`Expected an ISO week like 2026-W41, got "${week}"`)
  return monday
}
```

```ts
import { tzOffset } from "@date-fns/tz"
import { type Instant, MINUTE_MS } from "./instant.ts"

export type TimeZone = string

const FIXED_OFFSET = /^[+-]/

export const canonicalTimeZone = (name: string): TimeZone | null => {
  try {
    const canonical = new Intl.DateTimeFormat("en-US", { timeZone: name }).resolvedOptions().timeZone
    return FIXED_OFFSET.test(canonical) ? null : canonical
  } catch {
    return null
  }
}

export const offsetMsAt = (zone: TimeZone, instant: Instant): number => {
  const minutes = tzOffset(zone, new Date(instant))
  if (Number.isNaN(minutes)) throw new RangeError(`No UTC offset for "${zone}" at ${instant}`)
  return minutes * MINUTE_MS
}
```

Create `packages/domain/src/time/wall-clock.ts`. `instantsShowing` tries the offsets in force a day before and a day after the wall time, and keeps each candidate instant whose own offset agrees. No survivors means the time fell in a gap. Two survivors means it happened twice. On the rare day whose midnight falls in a gap (Santiago), `startOfDate` returns the moment the gap ends.

```ts
import type { LocalDate } from "./calendar.ts"
import { DAY_MS, type Instant } from "./instant.ts"
import { offsetMsAt, type TimeZone } from "./zone.ts"

export type LocalDateTime = string

export type LocalResolution =
  | { readonly kind: "ok"; readonly instant: Instant }
  | { readonly kind: "ambiguous"; readonly earlier: Instant; readonly later: Instant }
  | { readonly kind: "nonexistent" }

const wallMsOf = (local: LocalDateTime): number => {
  const wallMs = Date.parse(`${local}:00Z`)
  if (new Date(wallMs).toISOString().slice(0, 16) !== local) {
    throw new RangeError(`Expected a local date-time like 2026-11-01T01:30, got "${local}"`)
  }
  return wallMs
}

const instantsShowing = (wallMs: number, zone: TimeZone): Instant[] => {
  const offsets = new Set([offsetMsAt(zone, wallMs - DAY_MS), offsetMsAt(zone, wallMs + DAY_MS)])
  return [...offsets]
    .map((offset) => wallMs - offset)
    .filter((instant) => offsetMsAt(zone, instant) === wallMs - instant)
    .sort((a, b) => a - b)
}

export const resolveLocal = (local: LocalDateTime, zone: TimeZone): LocalResolution => {
  const [earlier, later] = instantsShowing(wallMsOf(local), zone)
  if (earlier === undefined) return { kind: "nonexistent" }
  if (later === undefined) return { kind: "ok", instant: earlier }
  return { kind: "ambiguous", earlier, later }
}

export const startOfDate = (date: LocalDate, zone: TimeZone): Instant => {
  const midnight = wallMsOf(`${date}T00:00`)
  const [first] = instantsShowing(midnight, zone)
  return first ?? midnight - offsetMsAt(zone, midnight - DAY_MS)
}
```

```ts
import { type Instant, SECOND_MS } from "../time/instant.ts"

export interface Span {
  readonly startedAt: Instant
  readonly endedAt: Instant | null
}

const elapsedMs = (span: Span, now: Instant) => Math.max(0, (span.endedAt ?? now) - span.startedAt)

const wholeSeconds = (ms: number) => Math.floor(ms / SECOND_MS)

export const nursingElapsed = (segments: ReadonlyArray<Span>, now: Instant): number =>
  wholeSeconds(segments.reduce((total, segment) => total + elapsedMs(segment, now), 0))

export const sleepElapsed = (session: Span, now: Instant): number => wholeSeconds(elapsedMs(session, now))

const twoDigits = (value: number) => String(value).padStart(2, "0")

export const formatElapsed = (seconds: number): string => {
  const total = Math.max(0, Math.floor(seconds))
  const hours = Math.floor(total / 3600)
  const minutes = Math.floor(total / 60) % 60
  const secondsPart = twoDigits(total % 60)
  return hours > 0 ? `${hours}:${twoDigits(minutes)}:${secondsPart}` : `${minutes}:${secondsPart}`
}
```

Create `packages/domain/src/feed/feed.ts`. Volumes are summed in whole tenths of a mL, so `0.1 + 0.2` gives `0.3`. Each side is floored to whole seconds before the sides are added, so the two numbers on screen always add up to the total.

```ts
import type { Instant } from "../time/instant.ts"
import { nursingElapsed, type Span } from "../timer/timer.ts"

export type Side = "left" | "right"

export interface NursingSegment extends Span {
  readonly side: Side
}

export interface BottlePortion {
  readonly occurredAt: Instant
  readonly breastMilkMl: number
  readonly formulaMl: number
}

export interface FeedComponents {
  readonly segments: ReadonlyArray<NursingSegment>
  readonly portions: ReadonlyArray<BottlePortion>
}

export interface FeedSummary {
  readonly leftSeconds: number
  readonly rightSeconds: number
  readonly nursingSeconds: number
  readonly breastMilkMl: number
  readonly formulaMl: number
  readonly bottleMl: number
}

const tenths = (ml: number) => Math.round(ml * 10)

const sumMl = (portions: ReadonlyArray<BottlePortion>, pick: (portion: BottlePortion) => number) =>
  portions.reduce((total, portion) => total + tenths(pick(portion)), 0) / 10

const sideSeconds = (feed: FeedComponents, side: Side, now: Instant) =>
  nursingElapsed(
    feed.segments.filter((segment) => segment.side === side),
    now,
  )

export const feedSummary = (feed: FeedComponents, now: Instant): FeedSummary => {
  const leftSeconds = sideSeconds(feed, "left", now)
  const rightSeconds = sideSeconds(feed, "right", now)
  const breastMilkMl = sumMl(feed.portions, (portion) => portion.breastMilkMl)
  const formulaMl = sumMl(feed.portions, (portion) => portion.formulaMl)
  return {
    leftSeconds,
    rightSeconds,
    nursingSeconds: leftSeconds + rightSeconds,
    breastMilkMl,
    formulaMl,
    bottleMl: (tenths(breastMilkMl) + tenths(formulaMl)) / 10,
  }
}

export const sessionBounds = (feed: FeedComponents): Span | null => {
  const portionTimes = feed.portions.map((portion) => portion.occurredAt)
  const starts = [...feed.segments.map((segment) => segment.startedAt), ...portionTimes]
  if (starts.length === 0) return null
  const ends = [...feed.segments.map((segment) => segment.endedAt), ...portionTimes]
  const closedEnds = ends.filter((end) => end !== null)
  return { startedAt: Math.min(...starts), endedAt: closedEnds.length === ends.length ? Math.max(...closedEnds) : null }
}
```

```ts
import type { Instant, Interval } from "../time/instant.ts"
import type { TimeZone } from "../time/zone.ts"
import { localDateOf, zonedDayBounds } from "../time/zoned.ts"

export interface DayPiece {
  readonly date: LocalDate
  readonly interval: Interval
}

export const durationMs = (interval: Interval): number => interval.end - interval.start

export const overlaps = (a: Interval, b: Interval): boolean => Math.max(a.start, b.start) < Math.min(a.end, b.end)

export const clipTo = (interval: Interval, period: Interval): Interval | null => {
  const start = Math.max(interval.start, period.start)
  const end = Math.min(interval.end, period.end)
  return start < end ? { start, end } : null
}

export const splitByDays = (interval: Interval, zone: TimeZone): DayPiece[] => {
  const pieces: DayPiece[] = []
  let date = localDateOf(interval.start, zone)
  let cursor: Instant = interval.start
  while (cursor < interval.end) {
    const end = Math.min(zonedDayBounds(date, zone).end, interval.end)
    pieces.push({ date, interval: { start: cursor, end } })
    cursor = end
    date = addDaysToDate(date, 1)
  }
  return pieces
}
```

```ts
import { type Instant, MINUTE_MS } from "../time/instant.ts"
import { startOfDate } from "../time/wall-clock.ts"
import type { TimeZone } from "../time/zone.ts"

export type ValidationIssue =
  | "not_finite"
  | "not_positive"
  | "too_many_decimals"
  | "end_not_after_start"
  | "before_birth"
  | "in_future"
  | "out_of_range"

export const FUTURE_TOLERANCE_MS = 5 * MINUTE_MS

const positiveIssue = (value: number): ValidationIssue | null => {
  if (!Number.isFinite(value)) return "not_finite"
  return value > 0 ? null : "not_positive"
}

export const validateVolumeMl = (ml: number): ValidationIssue | null => {
  const issue = positiveIssue(ml)
  if (issue !== null) return issue
  return Math.abs(ml * 10 - Math.round(ml * 10)) < 1e-9 ? null : "too_many_decimals"
}

export const validateDurationSeconds = (seconds: number): ValidationIssue | null => positiveIssue(seconds)

export const validateEndAfterStart = (start: Instant, end: Instant): ValidationIssue | null =>
  end > start ? null : "end_not_after_start"

export const validateNotBeforeBirth = (
  instant: Instant,
  birthDate: LocalDate,
  zone: TimeZone,
): ValidationIssue | null => (instant >= startOfDate(birthDate, zone) ? null : "before_birth")

export const validateNotInFuture = (
  instant: Instant,
  serverNow: Instant,
  toleranceMs: number = FUTURE_TOLERANCE_MS,
): ValidationIssue | null => (instant <= serverNow + toleranceMs ? null : "in_future")

export const validateOunces = (ounces: number): ValidationIssue | null => {
  if (!Number.isFinite(ounces)) return "not_finite"
  return ounces >= 0 && ounces < 16 ? null : "out_of_range"
```

```ts
export const GRAMS_PER_POUND = 453.59237
export const OUNCES_PER_POUND = 16
export const GRAMS_PER_OUNCE = GRAMS_PER_POUND / OUNCES_PER_POUND
export const CM_PER_INCH = 2.54
export const ML_PER_FL_OZ = 29.5735295625

export interface PoundsOunces {
  readonly pounds: number
  readonly ounces: number
}

export const roundTo = (value: number, decimals: number): number => {
  const scale = 10 ** decimals
  return Math.round(value * scale) / scale
}

export const gramsFromPoundsOunces = (pounds: number, ounces: number): number =>
  (pounds * OUNCES_PER_POUND + ounces) * GRAMS_PER_OUNCE

export const poundsOuncesFromGrams = (grams: number, ounceDecimals: number): PoundsOunces => {
  const totalOunces = roundTo(grams / GRAMS_PER_OUNCE, ounceDecimals)
  const pounds = Math.floor(totalOunces / OUNCES_PER_POUND)
  return { pounds, ounces: roundTo(totalOunces - pounds * OUNCES_PER_POUND, ounceDecimals) }
}

export const cmFromInches = (inches: number): number => inches * CM_PER_INCH

export const inchesFromCm = (cm: number): number => cm / CM_PER_INCH

export const flOzFromMl = (ml: number): number => ml / ML_PER_FL_OZ

export const mlFromFlOz = (flOz: number): number => roundTo(flOz * ML_PER_FL_OZ, 1)
```

```ts
import {
  datesBetween,
  type IsoWeek,
  isoWeekOfDate,
  type LocalDate,
  monthOfDate,
  type YearMonth,
} from "../time/calendar.ts"
import type { Interval } from "../time/instant.ts"
import type { TimeZone } from "../time/zone.ts"
import { localDateOf } from "../time/zoned.ts"

export type PeriodKey = readonly ["day", LocalDate] | readonly ["week", IsoWeek] | readonly ["month", YearMonth]

const datesTouched = (interval: Interval, zone: TimeZone): LocalDate[] =>
  datesBetween(localDateOf(interval.start, zone), localDateOf(Math.max(interval.start, interval.end - 1), zone))

export const affectedPeriods = (before: Interval | null, after: Interval | null, zone: TimeZone): PeriodKey[] => {
  const intervals = [before, after].filter((interval) => interval !== null)
  const dates = [...new Set(intervals.flatMap((interval) => datesTouched(interval, zone)))].sort()
  const weeks = [...new Set(dates.map(isoWeekOfDate))]
  const months = [...new Set(dates.map(monthOfDate))]
  return [
    ...dates.map((date) => ["day", date] as const),
    ...weeks.map((week) => ["week", week] as const),
    ...months.map((month) => ["month", month] as const),
  ]
}
```

## Handoffs (not M1.2 work)

- **M1.3:** Build `QueryKey` on `PeriodKey`. Pick how schemas validate date, week, month and zone strings. Either call the domain in filters (for example `addDaysToDate(s, 0)`, `isoWeekMonday(s)`, `nextMonth(s)`, `canonicalTimeZone(s) !== null`) and change §1's "may import `domain` types" to say so, or map the domain's `RangeError` to `InvalidInput` at the edge, which would otherwise surface as a 500. The `Instant` schema must reject `NaN` and ±Infinity too; the validators return `not_finite` for them. Cap volumes and durations, because the validators set no upper bound. Cap any free date range, because `datesBetween` and `splitByDays` take one step per day.
- **M1.5:** The seed script checks `canonicalTimeZone(arg) !== null` and sends the argument as typed. Only the Worker canonicalizes and stores it, and the script prints what was stored, so `EST` shows up as `America/Panama`, which has no DST. `canonicalTimeZone` returns the runtime's identifier (Node 22 maps `Asia/Kolkata` to `Asia/Calcutta`), so compare stored names only with each other. Decide whether `Etc/GMT±N` and `UTC` should be allowed.
- **M1.7:** `overlaps` needs closed intervals. §M3.1 treats a running session as `[start, now)`. With the 5-minute future tolerance, a manual segment can start after `now` and still collide with the running segment once it grows. Decide whether D9 checks a running segment as `[start, now + FUTURE_TOLERANCE_MS)`. Never pass an open-ended interval to `splitByDays`. Find the active feed by its status, not by `endedAt === null`: `sessionBounds` gives a paused feed an end. Pass a running session to `affectedPeriods` as `{ start, end: now }`.
- **M1.8:** Build `daySummary` on `splitByDays` (nursing, sleep), `localDateOf` (bottles at portion time, feeds on their start date) and `feedSummary`. The AC 4 fixture is in `packages/domain/test/fixtures/scenarios.ts`. Close a running session at `now` before passing it to `splitByDays`, and never pass `end: Infinity`.
- **M1.12, M1.15, M3.4:** Units switch back and forth at any time (P8). A sheet shows amounts in the display unit but must send back the stored mL unchanged unless the parent changes it. Otherwise a 60 mL prefill shown as 2.0 oz would save as 59.1 mL on a one-tap save or an untouched edit. Wherever per-side times are shown (§3.5 `useTimer`, M1.11, M1.12), take the nursing total from `feedSummary(feed, now).nursingSeconds`, because summing raw milliseconds can be a second higher. `validateOunces` checks the ounce part of a weight, not fluid ounces. Keep datetime-local inputs at `step` 60 s, because `resolveLocal` takes `YYYY-MM-DDTHH:mm` only.
- **M4:** `roundTo` rounds negative ties toward +∞, and `poundsOuncesFromGrams` misbehaves on negative grams, so growth validators must reject non-positive values first. Rename `validateOunces` to say it checks the ounce part of a weight, and use `OUNCES_PER_POUND` in it.
- **Time-zone data (all runtimes):** Since tz 2026b, America/Vancouver stays on UTC−7, and 2026c–e did the same for Alberta, the Northwest Territories and Manitoba. Any runtime with older tz data puts Vancouver back on UTC−8 from 2026-11-01, an hour off. Before M1.8 ships, check that workerd reports `GMT-07:00` for America/Vancouver on 2026-11-01. Keep day bucketing on the Worker. For D11 manual entry (M1.12), resolve the local time on the Worker, or make the sheet compare the phone's offset with the server's.
