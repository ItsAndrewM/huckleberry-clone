# M3.9 History List View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, chosen by Andrew on 13 Oct 2026) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** History shows a day as a list as well as a grid: every feed and diaper of the day, earliest first, each row opening what the grid opens, with "Log on this day…" under the rows. It's the calendar's full-size, accessible equivalent (issue #46).

**Architecture:**
- **The rows** (`apps/web/src/features/history/list-rows.ts`, Node tests): `listRows(day, display, now, hidden)` turns M3.6's `DayPeriod` into Today's `RecentRow`s through Today's own `recentRow`, earliest first. A finished nursing feed's time is its span, and a time outside the day names its weekday. `listNote(day, rows)` says why no row shows.
- **The log time** (`apps/web/src/features/history/log-time.ts`, Node tests): `logTimeOn(date, zone, now)` is now on today, and the same clock time on another day, on the household's clock.
- **The address** (`history-period.ts`, `history-date.ts`, `history-navigation.ts`, `history-titles.ts`): `?view=list` is a third `HistoryView`, a day-shaped period that steps, titles and goes to dates as a day does (`unitOf`).
- **The page** (`history-view-switch.tsx`, `history-page.tsx`, `day-view.tsx`, `day-list.tsx`): Day | Week | List. For a list, `DayView` draws `DayList` in the grid's place, keeping its totals, growth strip, details and Log-at sheets and open handler. Each row is Today's `RecentItem`.

Andrew decided these on 13 Oct 2026, in the grill before this plan:
- **Execution:** native. Built ahead of the rest of M3 and before M1's week of use, since it only reads, apart from opening the sheets that exist. One plan, one PR.
- **Day | Week | List.** List is a third choice in History's toggle, kept in the address like Week, so day steps, the chips, Go to and Back keep it; a fresh visit to History opens Day. - **Log on this day.** A "Log on this day…" button under the rows opens the Log-at sheet's four kinds at the same clock time on that day, or at now on today; the sheet each kind opens can move the time with Change. He chose it over a time field in the Log-at sheet, and over the time after the day's last entry.

## Decisions this plan makes (veto in review)

- **P1: Today's rows.** The list draws Today's `RecentItem` with Today's words: its title ("Nursing", "Bottle", "Nursing and bottle", "Diaper"), its details ("Left 14 min · Right 9 min · 60 mL", "Pee and poo", "In progress"), and who logged it. While an entry is still being saved, "Saving…" takes the name's place and the row doesn't open, as on Today.
- **P2: Times.** A finished nursing feed shows its span ("1:05 – 1:28 AM", from `Intl`'s range). A bottle on its own, a diaper and a feed still going show when they started; a feed still going leads its details with "In progress", or "Paused", as on Today. A time outside the day names its weekday: "Thu 11:40 PM – 12:15 AM" for a feed from the night before, "11:50 PM – Sat 12:10 AM" for one into the next day, "Thu 11:55 PM" for one still going since the night before. `Intl`'s own range across days reads "8 Thu, 11:40 PM – 9 Fri, 12:15 AM", so such a span is joined by hand.
- **P3: The grid's entries.** Every feed and diaper the day's answer holds, so a feed across midnight shows on both days, and the chips hide their kinds. Measurements stay in the growth strip above the rows, as on the Day view, so they aren't listed twice. A feed and a diaper at the same moment list the feed first.
- **P4: What a row opens.** The Day view's own handler: a feed still going, running or paused, opens the Nursing sheet (`isLiveFeed`); anything else opens the details sheet, whose Edit follows `editSheetOf`.
- **P5: When no row shows.** "Nothing shown." when the chips hide every row; "No feeds or diapers." on a day with only a measurement; and nothing when nothing was logged, since the totals above already say "Nothing logged."
- **P6: Log on this day.** A full-width outline button under the rows, with lucide's `CalendarPlusIcon`, opens the Log-at sheet at `logTimeOn`: now on today, and the same clock time, to the minute, on another day. On the night the clocks go back it takes the first of the two times; a time the clocks skipped moves an hour on (2:30 → 3:30 AM).
- **P7: The address.** `?view=list`, with `date` (left out for today) and `hide` as for the Day view. The ‹ › arrows step a day ("Previous day", "Next day"), with "Back to today", and Go to opens the picked day as a list. Day ↔ List keeps the day; Week → List opens today if the week holds it, otherwise its Monday (Week → Day's rule); List → Week opens the week that holds the day. A week's column and Trends' "Open in History" still open the Day view.
- **P8: Names.** The list is a region named "The day's entries", and each row's button is named by its visible text, as on Today. The switcher's nav stays "Days".
- **P9: A repeated hour.** On the night the clocks go back, two rows can read the same time. Their order says which came first, as the details sheet's time does; only the grid's "Log at" rows name the two passes. Vancouver no longer changes its clocks (tzdata 2026c).
- **P10: Today's row on a narrow phone.** The shared row caps its time column at 40 % of the row, right-aligned, so a long time wraps under itself rather than covering the title. Without it, "Thu 11:40 PM – 12:15 AM" covered "Nursing" by 27 px on a 320 px phone. Today's short times never reach the cap.
- **P11: Size.** +0.70 kB gzip of JS (328.90 to 329.60 kB by Vite's report; 325.36 to 326.10 of 350 kB by `bundle:check`) and +0.01 kB of CSS (11.96 to 11.97 kB), against `main` at `e770ac4`. The Worker is unchanged.

const entriesOf = ({ feeds, diapers }: Kept): ReadonlyArray<Entry> =>
  [
    ...feeds.map((feed) => ({ kind: "feed", feed }) as const),
    ...diapers.map((diaper) => ({ kind: "diaper", diaper }) as const),

const nursedSpan = (entry: Entry): Interval | null => {
  if (entry.kind === "diaper") return null
  const { feed } = entry
  if (feed.status !== "completed" || feed.segments.length === 0 || feed.endedAt === null) return null
  return { start: feed.startedAt, end: feed.endedAt }
}

const within = ({ start, end }: Interval, at: number) => start <= at && at < end

const timeOf = (entry: Entry, day: Interval, { timeZone, locale }: Display) => {
  const at = (instant: number) =>
    within(day, instant) ? clockTime(instant, timeZone, locale) : dayClockTime(instant, timeZone, locale)
  const span = nursedSpan(entry)
  if (span === null) return at(startOf(entry))
  if (within(day, span.start) && within(day, span.end)) {
    return formatterFor("time", timeZone, locale).formatRange(span.start, span.end)
  }
  return `${at(span.start)} – ${at(span.end)}`
}

export const listRows = (day: DayPeriod, display: Display, now: number, hidden: Hidden): ReadonlyArray<RecentRow> =>

import type { LocalDate } from "@bt/contracts"

const wallMsIntoDay = (date: LocalDate, clock: string) =>
  Date.parse(`${date}T${clock}:00Z`) - Date.parse(`${date}T00:00:00Z`)

export const logTimeOn = (date: LocalDate, zone: string, now: number) => {
  if (localDateOf(now, zone) === date) return now
  const clock = localDateTimeOf(now, zone).slice("YYYY-MM-DDT".length)
  const resolution = resolveLocal(`${date}T${clock}`, zone)
  if (resolution.kind === "ok") return resolution.instant
  if (resolution.kind === "ambiguous") return resolution.earlier
  return startOfDate(date, zone) + wallMsIntoDay(date, clock)
}
