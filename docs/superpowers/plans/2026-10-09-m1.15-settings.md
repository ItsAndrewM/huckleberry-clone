# M1.15 Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen by Andrew on 9 Oct 2026) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A parent can choose the household's units and time zone, and correct the child's profile, from Settings on either phone. Both phones then show the same. Settings also says who is signed in.

**Architecture:**
- **Server first (Tasks 1–4), which needs nothing from M1.10:**
  - `packages/contracts` gains the household and child records (`Household`, `Child`), their edits, their conflicts and two groups.
  - Migration `0005` gives the household three unit columns, and gives the household and child a `version` and an `updated_by`.
  - `GET /api/me` carries both records whole.
  - `PATCH /api/household` and `PATCH /api/child` run through M1.6's `mutations` and `withReceipt`, like every other edit. Each is version-checked, applied once per `actionId`, and answers the keys it changed.
- **Then the screen (Tasks 5–7), after M1.10 merges:**
  - The branch rebases onto `main`.
  - Settings gains Units, Time zone, Child and "Signed in as" sections under M1.10's Theme.
  - The save logic sits in `apps/web/src/api/settings.ts`, which runs in Node tests. Components only display.
  - A save that meets another phone's newer copy applies its own change on top of that copy, once.

## Decisions this plan makes (veto in review)

- **P1: Units are one household setting** (Andrew, 9 Oct 2026).
  - Three kinds: bottles (`ml` or `fl_oz`), weight (`kg`, `g` or `lb_oz`) and length (`cm` or `in`). They're stored on the household row beside the time zone.
  - They start at mL, kg and cm, the units values are stored in. The seed takes no units: a parent sets them in Settings.
  - Weight and length take effect with M4's growth screens. Settings shows all three now, so it needs no change then.
  - The theme stays per phone (M1.10).
- **P2: Migration `0005-household-settings`** adds the unit columns, each `CHECK`ed to its choices. It also adds `version` (1 or more, default 1) and `updated_by` (a caregiver, `NULL` until a parent edits) to the household and the child (the M1.5 handoff). It only adds columns.
- **P3: `GET /api/me` carries both records whole.**
  - The household: `name`, `timeZone`, `units`, `version`, `updatedBy`, `updatedAt` and `caregivers`.
  - The child: `name`, `birthDate`, `sex`, `gestationalAgeDays`, `version`, `updatedBy` and `updatedAt`.
  - Settings reads them from `me`, so there's no new read and no new query key. Each conflict's `current` has the same fields.
- **P4: Two endpoints, each sending every field it edits** (M1.6's P6).
  - `PATCH /api/household` with `{ actionId, version, timeZone, units }` answers `{ household, changed }`.
  - `PATCH /api/child` with `{ actionId, version, name, birthDate, sex, gestationalAgeDays }` answers `{ child, changed }`.
  - `HouseholdConflict` and `ChildConflict` carry `STALE_VERSION` or `ACTION_REPLAY_MISMATCH`.
  - Neither has a 404: both rows exist once the household is seeded, and an unseeded household refuses everyone with 401.
- **P5: The order of refusals:** a stale version (409) first, then the birth date's rules (400), as M1.6's P8 orders them.
- **P6: The stored zone stays canonical.** The edit stores `canonicalTimeZone(timeZone)`, so `US/Pacific` becomes `America/Los_Angeles`, as the seed already does. The contract's `TimeZone` check calls the same function, so a zone it let through that can't be canonicalized is a defect: a logged 500.
- **P7: The birth date's rules.**
  - It can't be after today in the household's zone: `in_future` on `birthDate`.
  - It can't be after the local date of the earliest live diaper or feed: `before_birth` on `birthDate`. A feed's `started_at` is its earliest live part (M1.7's session bounds).
  - Deleted records don't count, so a wrong early entry that was deleted can't block a correction. Restoring a record from before the new birth date stays possible, as M1.7 left it. M3.5 decides whether a restore refuses it.
  - The name, sex and gestational age follow the seed's rules, which move into `packages/contracts`: a trimmed name of 1 to 60 characters, `female` or `male`, and 154 to 314 days.
- **P8: `changed` is `me`, `today` and `last24h` for both endpoints.** D7 refreshes `today` and `last24h` on every mutation, and `me` carries the records. A zone change moves every day boundary, but nothing reads a day, week or month before M3.6 (handoff).
- **P9: D8 has nothing to recompute until `supplement_logs` arrives (M3.3).** The zone change runs in the transaction where M3.3 adds the recompute.
  - A move west can leave a record from the first hours of the birth date before its start. That's accepted: it needs a record within hours of birth and a later move. Reads don't check it, and an edit of that record would answer `before_birth`.
- **P10: The screen.**
  - Sections go under Theme, which keeps its picker:
    - Units ("Both phones show amounts in these units.")
    - Time zone ("Each day runs from midnight to midnight here, on both phones.")
    - Child
    - Signed in as (the caregiver's name and email)
  - Units and the zone save on a tap or a choice, as the theme does. The child form has a Save button.
  - There's no sign-out: Access sessions last 730 hours.
- **P11: A save that meets a stale version reapplies only its own change, once.**
  - A unit tap or a zone choice sends just that field on top of the household the 409 carried. The child form sends the fields this parent changed on top of the child the 409 carried, each with a new `actionId`.
  - That never undoes the other parent's change to a field this parent didn't touch. Both changing the same field means the later tap wins, which is what that parent just asked for.
  - A second 409 shows "This changed on another phone a moment ago. Check it and try again."
  - M1.13's prompts are for records. Settings needs none.
- **P12: The saved record goes straight into `me`, and only the other changed keys refetch.** The socket's broadcast (M1.9, M1.10) brings the other phone up to date, and refreshes this one again.
- **P13: Time zone choices come from the phone.**
  - They come from `Intl.supportedValuesOf("timeZone")`, in a native select grouped by region, which opens the iOS picker.
  - The household's zone stays in the list even if the phone doesn't know it. The Worker still checks a zone against its own tz data (M1.10's P15).
- **P14: The child form.**
  - Fields: the name, the birth date (a native date input), sex ("Girl" or "Boy", radio buttons drawn as a segmented control) and the gestational age as weeks and days.
  - It's uncontrolled and keyed by the child's version, so a save, or the other phone's edit, reloads it. Save stays off until something changes.
  - It has `noValidate`: the household's 400 explains each field in the parent's words.
- **P15: E2E plays the household's answers.**
  - A spec routes `/api/me`, `PATCH /api/household` and `PATCH /api/child` through `page.route`, and never changes the real household.
  - Why: every spec shares the one local household, and WebKit and Chromium run at the same time. A real save would race the other browser's run of the same test, and change the child's name and zone that other specs read.
  - Worker tests cover the real saves.
- **P16: Two shadcn components.**
  - `native-select` and `input` are shadcn 4.21.4's `base-nova` files, with M1.10's P10 edits: `ComponentProps` from React, 44 px tall, and 16 px text. The steps give each file's final content, so there's no CLI to run.
  - Not added:
    - `label`: `jsx-a11y` flags shadcn's generic `Label`, and a plain `<label htmlFor>` passes
    - `field`: about 240 lines of parts this screen doesn't use
- **P17: The `pagehide` lint guard and the form drafts kept across a sign-in stay with M1.12.** The guard protects the timers, and the drafts belong to the sheets. Settings saves only on a tap.
- **P18: The bundles.** The Worker grows from 253.04 to 254.24 KiB gzip, against a 400 KiB budget. The web app grows by about 6 KB gzip, to 190 KB.

import { Schema } from "effect"
import { HttpApiEndpoint, HttpApiGroup } from "effect/http-api"
import { ActionId } from "./action-id.ts"
import { Conflict, InvalidInput } from "./errors.ts"
import { Changed } from "./query-keys.ts"
import { Instant, LocalDate, TimeZone } from "./time.ts"
import { Version } from "./version.ts"

const EARLIEST_BIRTH_DAYS = 154
const LATEST_BIRTH_DAYS = 314

export const Name = Schema.String.check(Schema.isTrimmed(), Schema.isBetweenLength(1, 60))
export type Name = typeof Name.Type

export const Sex = Schema.Literals(["female", "male"])
export type Sex = typeof Sex.Type

export const GestationalAgeDays = Schema.Int.check(
  Schema.isBetween({ minimum: EARLIEST_BIRTH_DAYS, maximum: LATEST_BIRTH_DAYS }),
)
export type GestationalAgeDays = typeof GestationalAgeDays.Type

export const VolumeUnit = Schema.Literals(["ml", "fl_oz"])
export type VolumeUnit = typeof VolumeUnit.Type

export const WeightUnit = Schema.Literals(["kg", "g", "lb_oz"])
export type WeightUnit = typeof WeightUnit.Type

export const LengthUnit = Schema.Literals(["cm", "in"])
export type LengthUnit = typeof LengthUnit.Type

export const Units = Schema.Struct({ volume: VolumeUnit, weight: WeightUnit, length: LengthUnit })
export type Units = typeof Units.Type

const audit = { version: Version, updatedBy: Schema.NullOr(Schema.String), updatedAt: Instant }

const householdFields = { timeZone: TimeZone, units: Units }

const childFields = { name: Name, birthDate: LocalDate, sex: Sex, gestationalAgeDays: GestationalAgeDays }

export const Household = Schema.Struct({ name: Schema.String, ...householdFields, ...audit })
export type Household = typeof Household.Type

export const Child = Schema.Struct({ ...childFields, ...audit })
export type Child = typeof Child.Type

export const HouseholdEdit = Schema.Struct({ actionId: ActionId, version: Version, ...householdFields })
export type HouseholdEdit = typeof HouseholdEdit.Type

export const ChildEdit = Schema.Struct({ actionId: ActionId, version: Version, ...childFields })
export type ChildEdit = typeof ChildEdit.Type

export const SavedHousehold = Schema.Struct({ household: Household, changed: Changed })
export type SavedHousehold = typeof SavedHousehold.Type

import { type Changed, type Household, HouseholdConflict, type HouseholdEdit, queryKeys } from "@bt/contracts"
import { canonicalTimeZone } from "@bt/domain"
import { HOUSEHOLD_COLUMNS, householdFrom, householdOf, type HouseholdRow } from "./household.ts"
import type { CoreResult, Stamp } from "./receipts.ts"

const PROFILE_CHANGED: Changed = [queryKeys.me, queryKeys.today, queryKeys.last24h]

export const editHousehold =
  (stamp: Stamp, edit: HouseholdEdit) =>
  (sql: SqlStorage): CoreResult<Household, HouseholdConflict> => {
    const current = householdOf(sql)
    if (current.version !== edit.version) {
      return { ok: false, error: new HouseholdConflict({ code: "STALE_VERSION", current }) }
    }
    const timeZone = canonicalTimeZone(edit.timeZone)
    if (timeZone === null) throw new RangeError(`Expected an IANA time zone, got "${edit.timeZone}"`)
    const row = sql
      .exec<HouseholdRow>(
        `UPDATE household
         SET time_zone = ?, volume_unit = ?, weight_unit = ?, length_unit = ?, version = version + 1, updated_by = ?, updated_at = ?
         RETURNING ${HOUSEHOLD_COLUMNS}`,
        timeZone,
        edit.units.volume,
        edit.units.weight,
        edit.units.length,
        stamp.caregiverId,
        stamp.now,
      )
      .one()
    return { ok: true, response: householdFrom(row), changed: PROFILE_CHANGED }

  (sql: SqlStorage): CoreResult<Household, HouseholdConflict> => {

    .exec<{ at: number | null }>(

         SELECT min(occurred_at) AS at FROM diapers WHERE deleted_at IS NULL
         UNION ALL SELECT min(started_at) FROM feeds WHERE deleted_at IS NULL
       )`,
    )
    .one().at

  const { zone } = calendarOf(sql)
  if (birthDate > localDateOf(now, zone)) return "in_future"
  const earliest = earliestRecordAt(sql)
  return earliest === null ? null : validateNotBeforeBirth(earliest, birthDate, zone)
}

  (stamp: Stamp, edit: ChildEdit) =>
  (sql: SqlStorage): CoreResult<Child, InvalidInput | ChildConflict> => {
    const current = childOf(sql)
    if (current.version !== edit.version) {
      return { ok: false, error: new ChildConflict({ code: "STALE_VERSION", current }) }
    }
    const issue = birthDateIssue(sql, edit.birthDate, stamp.now)
    if (issue !== null) return { ok: false, error: new InvalidInput({ fieldErrors: [{ path: "birthDate", issue }] }) }
    const row = sql
      .exec<ChildRow>(
        `UPDATE child
         SET name = ?, birth_date = ?, sex = ?, gestational_age_days = ?, version = version + 1, updated_by = ?, updated_at = ?
         RETURNING ${CHILD_COLUMNS}`,
        edit.name,
        edit.birthDate,
        edit.sex,
        edit.gestationalAgeDays,
        stamp.caregiverId,
        stamp.now,
      )
      .one()
    return { ok: true, response: childFrom(row), changed: PROFILE_CHANGED }

  type Changed,

  HouseholdConflict,
  type HouseholdEdit,
  type Me,
  queryKeys,
  type SavedHousehold,
  type Units,
} from "@bt/contracts"

import type { HouseholdApi } from "./client.ts"

export interface HouseholdChange {
  readonly timeZone?: string
  readonly units?: Partial<Units>
}

export const householdEdit = (household: Household, change: HouseholdChange): HouseholdEdit => ({
  actionId: crypto.randomUUID(),
  version: household.version,
  timeZone: change.timeZone ?? household.timeZone,
  units: { ...household.units, ...change.units },
})

export const saveHousehold = async (
  api: HouseholdApi,
  household: Household,
  change: HouseholdChange,
): Promise<SavedHousehold> => {
  const send = (latest: Household) =>
    api.request((client) => client.household.editHousehold({ payload: householdEdit(latest, change) }))
  try {
    return await send(household)
  } catch (error) {
    if (error instanceof HouseholdConflict && error.code === "STALE_VERSION") return send(error.current)
    throw error
  }
}

export const rememberSaved = (queryClient: QueryClient, update: (me: Me) => Me, changed: Changed) => {
  queryClient.setQueryData<Me>(queryKeys.me, (me) => (me === undefined ? me : update(me)))
  for (const queryKey of changed) {
    if (queryKey[0] !== queryKeys.me[0]) void queryClient.invalidateQueries({ queryKey })
  }
}

export interface ZoneOption {
  readonly value: string
  readonly label: string
}

export interface ZoneGroup {
  readonly region: string
  readonly zones: ReadonlyArray<ZoneOption>
}

const OTHER_REGION = "Other"

const placeOf = (zone: string) => {
  const [region = OTHER_REGION, ...place] = zone.split("/")
  if (place.length === 0) return { region: OTHER_REGION, value: zone, label: zone.replaceAll("_", " ") }
  return { region, value: zone, label: place.join(" / ").replaceAll("_", " ") }
}

export const timeZoneGroups = (zones: ReadonlyArray<string>, current: string): ZoneGroup[] => {
  const places = [...new Set([...zones, current])].map(placeOf)
  const regions = [...new Set(places.map(({ region }) => region))].toSorted()
  return regions.map((region) => ({
    region,
    zones: places
      .filter((place) => place.region === region)
      .map(({ value, label }) => ({ value, label }))
      .toSorted((a, b) => a.label.localeCompare(b.label)),
  }))
}

const playHousehold = async (page: Page): Promise<Played> => {
  const me = await (await page.request.get("/api/me")).json()
  const played: Played = { household: householdOf(me.household), child: me.child, sent: [] }
  await page.route("**/api/me", (route) =>
    route.fulfill({
      json: { ...me, household: { ...played.household, caregivers: me.household.caregivers }, child: played.child },
    }),
  )
  await page.route("**/api/household", (route) => {
    const body = route.request().postData() ?? ""
    played.sent.push(body)
    const edit: HouseholdEdit = JSON.parse(body)
    played.household = { ...played.household, timeZone: edit.timeZone, units: edit.units, version: edit.version + 1 }
    return route.fulfill({ json: { household: played.household, changed: CHANGED } })
  })
  await page.route("**/api/child", (route) => {
    const body = route.request().postData() ?? ""
    played.sent.push(body)
    const { version, name, birthDate, sex, gestationalAgeDays }: ChildEdit = JSON.parse(body)
    played.child = { ...played.child, name, birthDate, sex, gestationalAgeDays, version: version + 1 }
    return route.fulfill({ json: { child: played.child, changed: CHANGED } })
  })
