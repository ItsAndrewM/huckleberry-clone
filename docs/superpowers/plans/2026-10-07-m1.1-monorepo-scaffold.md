# M1.1 Monorepo scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pnpm monorepo (`apps/web`, `apps/worker`, `packages/domain`, `packages/contracts`, `e2e/`). Lint, typecheck, unit and Workers tests, build, the bundle-size gate and Playwright (WebKit and Chromium at iPhone size) all pass locally and in GitHub Actions.

**Architecture:** pnpm workspace. Internal packages are consumed as TS source, with no build step. The Worker owns `apps/worker/wrangler.jsonc`. `apps/web`'s `vite build` compiles the client and the Worker through `@cloudflare/vite-plugin` (`configPath: "../worker/wrangler.jsonc"`). Every version is pinned once, in the pnpm catalog. The Worker denies every `/api/*` request with 401 until M1.4 adds Access.

**Tech Stack:** pnpm 10.32.1, Node 22, TypeScript 5.9.3, Biome 2.5.15, Vitest 4.1.11 + `@cloudflare/vitest-plugin` 1.3.7, wrangler 4.148.0, Vite 8.3.3 + `@vitejs/plugin-react` 6.1.2 + `@cloudflare/vite-plugin` 1.63.0, React 19.3.0, Playwright 1.64.0, GitHub Actions.

**Spec:** `docs/implementation-plan.md`: the M1.1 row, D1, D12, §1 (layout) and §6 (testing). `docs/spike-results.md`: pinned versions and the S6 bundle baseline. The product spec (v0.10) is not in the repo, and M1.1 needs nothing from it.

## Global Constraints

- Exact versions only (no `^` or `~`), each defined once in the `pnpm-workspace.yaml` catalog. Packages use `catalog:` or `workspace:*`.
- Node 22.x. `packageManager: pnpm@10.32.1`.
- TS: strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`, `allowImportingTsExtensions`, `noEmit` (the spike's settings).
- Style follows the spike: no semicolons, double quotes, 2-space indent, 120 columns, `.ts`/`.tsx` extensions on relative imports.
- The API lives under `/api/*`, with `run_worker_first: ["/api/*"]` and SPA `not_found_handling` (D1).
- `packages/domain` imports nothing from the workspace and no framework or runtime. `date-fns` and `@date-fns/tz` are allowed only inside `packages/domain` (§1, D12).
- Bundle gate: **fail above 400 KiB gzip** (spike S6).
- No `nodejs_compat`. `compatibility_date: "2026-10-06"`.
- Comments only for a non-obvious *why*.
- No product logic. Domain code is M1.2, contracts M1.3, Access M1.4, the DO M1.5, router/Tailwind/shadcn M1.10, the service worker M1.14, deploy M1.16.

## Decisions this plan makes (veto in review)

- **P1:** Test pool `@cloudflare/vitest-plugin@1.3.7` replaces `@cloudflare/vitest-pool-workers@0.22.0`. It is the same pool renamed upstream, with the same `cloudflareTest` API. It ships wrangler 4.148.0 and miniflare 5.20261006, the same as our wrangler pin, so `compatibility_date` rises from 2026-08-22 to 2026-10-06 (spike-results: "raise it when the pool catches up"). **Fallback:** pool-workers 0.22.0 with compat date 2026-08-22, which the spike proved.
- **P2:** Pins live in a pnpm **catalog**, not the root `package.json`. That is pnpm's mechanism for one version across workspace packages.
- **P3:** The Worker is named `baby-tracker`, which becomes `baby-tracker.dinocode.workers.dev` at M1.16. It can be renamed for free before the first deploy. Same `account_id` pin as the spike.
- **P4:** Effect stays 4.0.1 and jose 6.2.12 in the catalog (spike-proven), although 4.0.2 is out. M1.3 decides whether to bump.
- **P5:** The 100 % branch-coverage gate moves to M1.2, which owns the code it measures. The `pagehide`/`visibilitychange` guard moves to M1.10, which creates the mutation modules.
- **P6:** E2E serves the build with `vite preview` (workerd through the Cloudflare plugin), not `wrangler dev` as §6 says. M1.1 needs no identity. M1.4 checks whether preview applies `access.dev`. If it doesn't, M1.4 switches `webServer` to `wrangler dev` on the build output.

## Review Focus

1. **Version drift:** a caret range or an unfrozen install moves a spike-proven version. Expect exact pins and `--frozen-lockfile`. Tested by the pin check in Task 2, which CI repeats (Task 7).
2. **Bundle gate passes on output it can't read** (wrangler changes its format or unit). It must fail. Tested by parser unit tests (Task 5).
3. **Workers tests silently run in Node, not workerd.** Tested by asserting `navigator.userAgent === "Cloudflare-Workers"` (Task 4).
4. **Boundary violations:** domain imports the workspace or a framework, `date-fns` appears outside domain, or web and worker import each other. Each must be a lint error. Tested by violation probes (Task 3).
5. **SPA deep link or `/api/*` routing misconfigured (D1).** Tested end to end: `/history` serves the shell, and `/api/me` returns 401 through the whole stack (Task 6).

```ts
const UPLOAD_LINE = /Total Upload:\s*([\d.]+)\s*KiB\s*\/\s*gzip:\s*([\d.]+)\s*KiB/

export interface UploadSize {
  readonly rawKiB: number
  readonly gzipKiB: number
}

export const parseUploadSize = (wranglerOutput: string): UploadSize => {
  const match = UPLOAD_LINE.exec(wranglerOutput)
  if (match === null) throw new Error("No 'Total Upload: <n> KiB / gzip: <n> KiB' line in wrangler output")
  return { rawKiB: Number(match[1]), gzipKiB: Number(match[2]) }
}

export const exceedsBudget = (size: UploadSize, budgetGzipKiB: number): boolean => size.gzipKiB > budgetGzipKiB
```
