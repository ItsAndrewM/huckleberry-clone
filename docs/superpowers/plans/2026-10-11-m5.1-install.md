> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, as Andrew chose on 11 Oct 2026) to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a parent who opens the app in a browser tab on an iPhone learns how to install it, and the installed app's offline copy never reads as saved while a file is missing:
- **Card:** in a browser tab on an iPhone or iPad, a card at the top of each page gives the steps. "Not now" hides it on that phone for good.
- **Settings:** a Home Screen line says "Installed." in the app, and gives the same steps in a tab.
- **Save order:** the service worker saves `/` only after every other file. This is CodeRabbit's outside-diff Minor on #26, which merged without it.

**Architecture:**
- **`apps/web/src/service-worker/shell-cache.ts`:** `saveBuild(cache, files)` saves the build's assets, then `/`. `sw.ts` calls it in place of one `Promise.all` over every file.
- **`apps/web/src/install/home-screen.ts` (new, pure, tested in Node):** works out what this phone is (`installed`, `browser-tab` or `elsewhere`) from `navigator.standalone` and the display mode. It also keeps the card's "Not now" per phone, as `bt.install-card` in localStorage, the way `theme.ts` keeps the theme.
- **`apps/web/src/install/this-phone.ts` (new):** reads the two browser facts once, at load, as `offline-copy-section.tsx` reads the page's build. It declares `Navigator.standalone`, which TypeScript's DOM types lack.
- **The views:**

  - `install-card.tsx`: the card, in the shell's `main` above every page
  - `features/settings/home-screen-section.tsx`: Settings' line, after Offline copy
- **E2E:** WebKit's iPhone emulation is a Safari tab: `navigator.standalone` is `false` there (measured). So the suite starts on a phone that has dismissed the card, through `storageState` in `playwright.config.ts`, and `install.spec.ts` clears that to test it.

## Decisions this plan makes (veto in review)

- **P1, what counts as an iPhone.** Only iOS and iPadOS WebKit define `navigator.standalone`, so the flag decides it, with no user-agent sniffing:
  - `true`, or `(display-mode: standalone)` matching, means installed
  - `false` means a browser tab
  - `undefined` means elsewhere, such as desktop or Android: no card and no line

  An iPad's desktop-class user agent doesn't matter.
- **P2, one way to dismiss it: "Not now".** It's a 44 px ghost button. D2's sketch also had an ×, but two buttons that do the same thing read twice to VoiceOver.
- **P3, the card's title isn't a heading.** The card sits above each page's `h1`, so its title names the `section` instead. VoiceOver reads it as an "Install Baby tracker" region, and each page's first heading stays its own `h1`.
- **P4, the card shows above every tab, Settings included, until Not now.** Settings' line stays after that.
- **P5, blocked storage.** With storage blocked (Private Browsing with cookies blocked), "Not now" hides the card for that visit only, and it's back on the next open. Nothing throws.
- **P6, what VoiceOver hears.** The share icon is hidden from VoiceOver, since the word "Share" comes before it. ⋯ reads "More". M5.2's VoiceOver pass can rename it.
- **P7, the E2E suite starts with the card dismissed,** through `storageState` in `playwright.config.ts` and in each private config. Other sessions' private configs need the same line once they merge a `main` that has M5.1 (a hand-off).
- **P8, the save order.**
  - **The order:** the assets are saved together, then `/` alone.
  - **When a file fails:** a failed asset write leaves no `/`. The install fails as before, and Settings' check, which counts a copy only when it holds `/`, can't call the partial copy saved.
  - **The partial cache stays:** the next install of the same version reopens and overwrites it, and an older version's is swept on the next activation.

## Review Focus

The five inputs most likely to bite a parent that the spec implies but doesn't spell out, each with the test that pins it:

1. **A Safari tab where storage is blocked** (Private Browsing with cookies blocked): "Not now" must still hide the card, with no error. Task 3, "Not now still hides the card for this visit when the browser blocks storage".
2. **A value in `bt.install-card` that this code didn't write** (an older build, a typo): it must not count as dismissed, or the card would never show. Task 2, "ignores a stored value it didn't write".
3. **An installed app whose WebKit reports `standalone` late or not at all, while the display mode says standalone:** it must not show the card in the installed app. Task 2, "trusts the display mode too".
4. **A phone that runs out of space while the service worker saves an update:** Settings must not say "Saved for this version." for a copy missing a file. Task 1, "never saves the page when another file can't be saved".
5. **Dismissing the card on one tab, then moving to another:** it must stay gone everywhere, and after a reload. Task 3, "shows the card above every tab until Not now, wherever that's tapped", and the first card test's reload.

```ts
    [SHELL_URL, new Response("<html>")],

  ]
  const urlOf = (request: RequestInfo | URL) => (request instanceof Request ? request.url : request.toString())

  const heldCache = () => {
    const puts: string[] = []
    const held = new Map<string, () => void>()
    const put = (request: RequestInfo | URL) => {
      puts.push(urlOf(request))
      return new Promise<void>((resolve) => held.set(urlOf(request), resolve))

    expect(puts).toEqual([SCRIPT_URL, STYLES_URL])
```

```ts
import { attempt, type BrowserStorage } from "../storage.ts"

export type HomeScreen = "installed" | "browser-tab" | "elsewhere"

export const INSTALL_CARD_KEY = "bt.install-card"
const DISMISSED = "dismissed"

export const homeScreenOf = (standalone: boolean | undefined, displayedStandalone: boolean): HomeScreen => {
  if (standalone === undefined) return "elsewhere"
  return standalone || displayedStandalone ? "installed" : "browser-tab"
}

export const installCardDismissed = (openStorage: () => BrowserStorage) =>
  attempt(() => openStorage().getItem(INSTALL_CARD_KEY), null) === DISMISSED

export const dismissInstallCard = (openStorage: () => BrowserStorage) =>
  attempt(() => openStorage().setItem(INSTALL_CARD_KEY, DISMISSED), undefined)

export const showsInstallCard = (homeScreen: HomeScreen, dismissed: boolean) =>
  homeScreen === "browser-tab" && !dismissed
```

## Post-review notes

The final review ran on Opus, in a fresh context, over `20390a3..2188877`. Its verdict was "With fixes": 2 Important and 4 Minor. Review Focus 1–5 all held. One fix pass followed, each behaviour fix test first:

- **A Mac's Safari showed the card and the line (Important), against D4.**
  - **Cause:** P1 was wrong. WebKit gave macOS `navigator.standalone` in 2023 (WebKit bug 257776), which is why Playwright's WebKit reports it here. Under the iPhone profile it also reports 0 touch points; Chromium reports 1.
  - **Fix:** `homeScreenOf` now takes `navigator.maxTouchPoints`, and no touch means elsewhere (an iPhone or iPad reports 5). The E2E helper stubs the touch points beside the flag. A unit test and a Mac E2E spec each failed first.
  - **Docs:** §6 now gives the right reason the suite starts with the card dismissed.
- **"For good" didn't hold (Important).**
  - **Cause:** Safari deletes a site's localStorage after about seven days of Safari use without visiting it, though not a Home Screen app's. So the card comes back for a parent who reaches Safari only through the odd link, and it tells an already-installed parent to install.
  - **Fix:** the card and the Settings line now end "Already added it? Open Baby tracker from your Home Screen." This extends D3's wording; it's in the rulings below.
  - **Docs:** the M5.1 row says Safari forgets "Not now" after about a week.
- **The runbook (raised from Minor to Important):** it expected Settings' "Installed." line before M5.1 ships, while Emily's checks are pending. It now says the line comes with M5.1's release.
- **Test gaps (Minor, fixed under this plan's fix-wave rule):**
  - the every-tab spec now shows the card on Today and on Settings before "Not now"
  - a new spec logs a diaper in two taps while the card shows
- **Deferred (Minor):** the card lacks the app's `mx-auto w-full max-w-lg` column and Today's `rounded-xl ring-1 ring-foreground/10` outline. It shows only on an iPad or in landscape, since a portrait iPhone is narrower than the column.

- **The added sentence.** "Already added it? Open Baby tracker from your Home Screen." extends D3. Undoing it means removing one sentence in `share-steps.tsx` and two E2E assertions.
