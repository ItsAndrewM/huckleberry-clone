# GH-75 A Second Tap Saves the First Tap's Time Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, chosen by Andrew on 14 Oct 2026) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After a send fails in its open sheet, tapping the sheet's own button again saves what Try again saves: the first tap's time, to the second, under the first tap's actionId (issue #75). This covers 12 controls:
- the seven forms whose time starts at Now: Start sleep, Wake up, Start nursing, Finish feed, Bottle, Diaper and Add measurement
- M3.3's dose sheet ("Log Vitamin D"), which merged while this was planned
- the four nursing buttons with no time field: Pause, Switch, Resume and a paused feed's Finish

**Architecture:**
- **To the second** (`apps/web/src/sheets/when.ts`, Node tests): `resolveSent(sent, seeded, when, zone, now, earliest)` sends a held send's own instant while the field still shows it, and reads the field once it shows anything else. Bottle's `occurredAtOf` and Measurement's `measuredAtOf` did this already; both now call it.
  - Diaper, Start sleep, Wake up, Start nursing, Finish and the dose sheet keep the held instant in their sessions (`occurredAt`, `startedAt`, `stoppedAt`).
  - Wake up and Finish also keep the held actionId (`wakeSession`, `stopSession`), as Start's sessions already did.
- **The forms** (`apps/web/src/sheets/sheets-state.ts`, Node tests): offline, a send that closes its sheet keeps the sheet open (`sendingState`). Its failure then landed in a form that had read the held send only when it mounted, so the field still said Now.
  - `failedState` now opens the sheet again on that failure, as it already did when the failure found the sheet closed. The sheet's content mounts again (`opened` + 1), seeded from the failure.
  - It doesn't hold taps (`queued: false`), since the sheet never left the screen.
- **The time-less buttons** (`apps/web/src/sheets/held.ts`, Node tests; `running-view.tsx`, `paused-view.tsx`): `retapped(held, fresh)` sends the held failure again when the tap is the same control on the same feed (the same switch direction) and the failure's note offers a retry (`offersRetry`). Resume takes the side picked. Anything else sends the tap as it is.
- **The spec** (`e2e/first-tap.spec.ts`): for each control, the first tap fails, 15 minutes pass, the signal comes back, and the second tap must send the first tap's instant under the first tap's actionId.

**Tech Stack:** React 19, TanStack Query 5, Effect's `HttpApiClient`, TypeScript 5.9.3, Vitest 4.1.11, Playwright 1.64.0, oxlint 1.87.0 and oxfmt 0.72.0, Node 24.21.0. No package is added.

## Decisions this plan makes (veto in review)

- **P1: The forms reopen in place.** When the phone is offline and kept a sheet open for its send, that send's failure opens the sheet again, as a failure that finds the sheet closed does (`failedState` → `opening`). Every form seeds itself from the held failure when it mounts, which the closed-sheet path already counts on, so the one change fixes all eight.
  - It doesn't hold taps for the 500 ms a sheet sliding in does (`queued: false`), since the sheet never left the screen.
  - Only the sheet's own send (`keptOpen`) of an action that closes on send. A nursing button's failure, which never closes its sheet, and another sheet's failure landing while this one is open, leave the open sheet as it is, so nothing being typed is lost.
- **P2: To the second.** While a field still shows the held time, the button sends the held instant itself, not the minute the field shows (2:40:37, not 2:40:00). Try again and the button then send the same body under the same actionId, so if the first send did land, the household's receipt answers the repeat, instead of "This was already saved as you first entered it." (`ACTION_REPLAY_MISMATCH`). Bottle and Measurement already did this. It also tightens the closed-sheet path, which sent the minute for Diaper, Start sleep and Start nursing.
- **P3: Wake up and Finish keep the held actionId**, as Start sleep's and Start nursing's sessions already did. Without a held failure they still use a fresh one for each opening. `wakeAction` and `finishAction` take it, defaulting to a fresh one.
- **P4: The time-less buttons resend their held failure** (`retapped`): when the held failure is the same control on the same feed and, for Switch, the same direction, and its note offers a retry. Resume takes the side picked and keeps the rest. Delete on the running and paused views goes through it too, so a held delete is sent again as it was. After a conflict (the other phone's change), the tap is sent as it is, with the feed's current version. Closing the sheet still drops the held failure, as before (#91), so a later tap acts at its own time.
- **P5: Which failures count.** `offersRetry` refuses the failures whose note has no retry button: an expired or refused sign-in, `InvalidInput`, `NotFound` and the five conflicts. A test ties it to `failureNote`'s retry button for each kind of error, so the two can't drift. `isConflict` moves from `recovery.ts` to `held.ts`, which both use.
- **P6: The dose sheet joins the class.** It merged while this was planned (#86), with its form already keyed on the held failure (`formKeyOf`). Its session now keeps the held instant too (P2), and the spec covers it.
- **P7: The spec.** A new `e2e/first-tap.spec.ts`, one test per control in each engine (24 runs, about 30 s), so it doesn't collide with #72's edits to the existing specs. It mutes the live socket and goes offline as `deleted.spec.ts` does.
- **P8: Size.** +0.31 kB gzip of JS (336.92 to 337.23 of 350 kB by `bundle:check`), against `main` at `68af79e`, both built with `CLOUDFLARE_ENV=local`. The CSS (12.04 kB) and the Worker (262.84 KiB gzip) are unchanged.
- **P9: The docs.** The implementation plan's M1.12 row gains "Decided 14 Oct 2026 (#75)".

## Review Focus

The five ways this is most likely to fail a parent, each with the test that pins it:

1. **A second entry, or a second wake, from one tap.**
   - Try again and the button must be one action: the same actionId, and the same body when nothing changed.
   - Pinned by every spec test's "one actionId across both sends" (Tasks 2 and 3), the sessions' "keeps the actionId" rows (Task 1), and `retapped`'s "sends the held one again" (Task 3).
2. **A parent who changes the time after the failure.**
   - The field she changed wins, and Now means the moment of the tap.
   - Pinned by each session's "until its time is changed" row and `resolveSent`'s "reads the field once it shows another time, or Now" (Task 1).
3. **The other phone's change between the two taps.**
   - A conflict must not be resent with a stale version; the tap goes out with the feed's current one.
   - Pinned by `retapped`'s "sends what was tapped when the note offers no Try again" and `offersRetry`'s conflict rows (Task 3).
4. **A failure landing in another sheet's form.**
   - A diaper that fails while the parent types a bottle mustn't wipe the bottle form.
   - Pinned by `failedState`'s "leaves another open sheet as it is" and "leaves a running feed's control in place" (Task 2).
5. **A switch the other way, or another feed.**
   - Only the same control on the same feed resends; a switch back, another control, or a new feed acts at its own tap.
   - Pinned by `retapped`'s "sends what was tapped for another control, another feed or a switch the other way" (Task 3).
