# M1.6 Diapers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen by Andrew on 9 Oct 2026) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Parents can log, edit, delete and restore a diaper through the household's API. These are the first mutation endpoints: each is applied once per `actionId`, checks the version it was made from, and answers the query keys it changed.

**Architecture:** `packages/contracts` gains the diaper record, its payloads, `Version`, `DiaperConflict` and a `diapers` group in `Api`. In the Worker, migration `0003` adds the `diapers` table, and `core/diapers.ts` holds four synchronous core functions that take a `Stamp` (who and when) and the SQL handle. A new `mutations` helper reads the caller, hashes the request, reads the clock once, runs the core through `withReceipt`, and turns each outcome into the response or a contract error. Before any of that, two of M1.5's handoffs land. Migrations check their names against the household's ledger. Receipts store their route (migration `0002`), so an `actionId` reused on another route answers 400 instead of failing to decode.

**Tech Stack:** TypeScript 5.9.3, `effect` 4.0.1 (Schema, `effect/http`, `effect/http-api`), `@bt/contracts`, `@bt/domain`, Workers and Durable Objects (`@cloudflare/workers-types` 5.20261006.1, wrangler 4.148.0), `@cloudflare/vitest-plugin` 1.3.7, Vitest 4.1.11, Playwright 1.64.0, oxlint 1.87.0 + oxfmt 0.72.0, Node 24.21.0. No new dependencies.

## Decisions this plan makes (veto in review)

- **P1: A diaper is its time, wet and dirty, and nothing else** (Andrew, 9 Oct 2026; the spec's §8 isn't in the repo). At least one of wet and dirty is true.
  - The record the API answers also carries `id`, `version`, `createdBy`, `createdAt`, `updatedBy`, `updatedAt` and `deletedAt`. The 409 prompt (M1.13) needs who changed it and when, Recently deleted (M3.5) needs `deletedAt`, and Today (M1.8) shows who logged it.
  - Caregivers appear by id. M1.8 decides how the client learns their names.
  - D4's `source` and `source_ref` stay in the table, out of the record.
- **P2: Two migrations.** `0002-receipt-routes` adds the receipt's route (P4). `0003-diapers` adds the table, which the M1.5 handoff called `0002-diapers`. The receipt change goes first because the diaper endpoints rely on it.
  - The table is `STRICT`. `CHECK`s keep `wet` and `dirty` to 0 or 1 with at least one set, `version` at 1 or more, and `source` to `app` or `import`. `source_ref` is set exactly when `source` is `import`. `created_by` and `updated_by` reference `caregivers`.
  - D4's partial unique index on `(source, source_ref) WHERE source = 'import'`, and an index on `occurred_at` for the day queries (M1.8, M3.6).
  - A soft delete sets `deleted_at`. A delete or restore sets `updated_by` and `updated_at` like any edit (§3.3 Audit), so there's no `deleted_by`.
- **P3: `migrate` checks the ledger's names before applying anything** (the M1.5 handoff). A household whose ledger names a migration differently from the code, at the same position, refuses to start, and the error names both.
  - Today, a migration renamed or moved under an applied one is skipped without a word whenever the SQL at its old position happens to run again cleanly.
  - A ledger longer than the code is fine: that's older code after a rollback.
- **P4: Receipts store their route, and an `actionId` reused on another route answers 400 `InvalidInput` on `actionId`** (the M1.5 handoff's open question).
  - `withReceipt` compares the route before it decodes the stored response, so a feed's receipt is never decoded as a diaper. Today that decode fails, and the caller gets a 500.
  - The same route with a different request hash is still 409 `ACTION_REPLAY_MISMATCH` with the saved record.
  - No receipt exists before M1.6, since no endpoint wrote one. The column's `DEFAULT ''` is only there because SQLite needs a default to add a `NOT NULL` column.
- **P5: The endpoints.** All four answer `{ diaper, changed }`, so the phone that made the change invalidates the same keys M1.9 will broadcast to the other phone (§5).
  - `POST /api/diapers` with `{ actionId, occurredAt, wet, dirty }` → 201.
  - `PATCH /api/diapers/:id` with `{ actionId, version, occurredAt, wet, dirty }` → 200.
  - `DELETE /api/diapers/:id` with the JSON body `{ actionId, version }` → 200. It answers the deleted diaper and its new version, which an Undo restores from.
  - `POST /api/diapers/:id/restore` with `{ actionId, version }` → 200.
- **P6: An edit sends every field.** The edit form always holds the time, wet and dirty, and the version check already demands the latest copy, so a partial `PATCH` would buy nothing. The wet-or-dirty rule then lives in one schema check that POST and PATCH share. It names both fields, and the table's `CHECK` stands behind it.
- **P7: `occurredAt` is required, and it's the moment of the tap.** A save retried after a lost connection or a sign-in then keeps the time the diaper happened, not the time the retry got through. The core refuses a time more than 5 minutes ahead of the server's clock (`in_future`, AC 21) or before the child's birth date began in the household's zone (`before_birth`).
- **P8: The order of refusals for PATCH, DELETE and restore.**
  - An unknown id gets 404.
  - A stale version gets 409 `STALE_VERSION` with the diaper as it is now, deleted or not, so M1.13 can say "Emily deleted this".
  - The right version in the wrong state gets 404: editing or deleting a deleted diaper, or restoring a live one.
  - Then the time is checked (400).
  - Diapers have no invariant across records, so D10's restore checks only the version and the state.
- **P9: `changed` is `today`, `last24h`, and the day, week and month keys of the old and new times** (D7, a point event being `{ start: t, end: t }`). A delete or restore adds `deleted`. Diapers have no volume or duration, so the M1.3 handoff's caps don't apply.
- **P10: One `DiaperConflict` serves all four endpoints,** with the codes `STALE_VERSION` and `ACTION_REPLAY_MISMATCH` and `current: Diaper` (M1.3: one per endpoint, with one `current` type). `POST` can't be stale, but one class per record type gives the client one decoder for a diaper's 409.
- **P11: `Version` is an integer from 1, and `VersionedAction` (`{ actionId, version }`) is the body of every delete and restore:** diapers now, then feeds, sleep and growth.
- **P12: The Worker's mutation path.**
  - The core functions take a `Stamp` (`caregiverId`, `now`), which `Mutation` now extends, and run inside `withReceipt`.
  - `mutations(storage, record, replayMismatch)` in `src/mutations.ts` reads the caller and hashes ``${method} ${pathname}`` with the payload. It then reads the clock once, runs `withReceipt`, and maps each outcome to the response or a contract error.
  - `householdApi` takes the Durable Object's storage instead of its SQL handle, since `withReceipt` needs `transactionSync`.
- **P13: `api.test.ts` pins the list of endpoints,** so its other checks can't pass on an empty API (an M1.5 deferred minor).
- **P14: The Worker bundle grows from 240.88 to 244.77 KiB gzip,** well under the 400 KiB budget.

## Review Focus

1. **A save applied twice** (AC 14). A phone whose save went through, but whose answer was lost, sends it again. Expect the stored 201 again, still one diaper. Tested in Task 5.
2. **Two parents editing one diaper at once** (AC 13). Expect one edit saved and the other answered 409 `STALE_VERSION` with the winner's diaper, never a silent overwrite. Tested in Tasks 4 and 5.
3. **A phone whose clock runs a few minutes fast** (AC 21). Expect a diaper logged "now" to save up to 5 minutes ahead of the server's clock, and a 400 `in_future` beyond that. Tested in Tasks 4 and 5.
4. **A diaper moved across midnight at the end of a month.** Expect `changed` to name both days and both months, so both phones refresh both. Tested in Task 4.
5. **An edit to a diaper the other parent just deleted.** Expect 409 `STALE_VERSION` showing it deleted: not a 404, and not a silent edit of a deleted diaper. Tested in Task 4.

```ts
export interface Migration {
  readonly name: string
  readonly sql: string
}

const LEDGER = `CREATE TABLE IF NOT EXISTS _migrations (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  applied_at INTEGER NOT NULL
) STRICT`

const appliedNames = (storage: DurableObjectStorage): string[] =>
  storage.sql
    .exec<{ name: string }>("SELECT name FROM _migrations ORDER BY id")
    .toArray()
    .map(({ name }) => name)

const checkLedger = (applied: ReadonlyArray<string>, migrations: ReadonlyArray<Migration>): void => {
  applied.forEach((name, index) => {
    const known = migrations[index]
    if (known !== undefined && known.name !== name) {
      throw new Error(`Migration ${index + 1} is "${name}" in this household, but "${known.name}" in the code`)
    }
  })
}

export const migrate = (storage: DurableObjectStorage, migrations: ReadonlyArray<Migration>, now: number): void => {
  storage.sql.exec(LEDGER)
  const applied = appliedNames(storage)
  checkLedger(applied, migrations)
  migrations.slice(applied.length).forEach(({ name, sql }, index) =>
    storage.transactionSync(() => {
      storage.sql.exec(sql)
      storage.sql.exec(
        "INSERT INTO _migrations (id, name, applied_at) VALUES (?, ?, ?)",
        applied.length + index + 1,
        name,
        now,
      )
    }),
  )
}
```

import { type ActionId, Changed } from "@bt/contracts"
import { Schema } from "effect"

const HOUR_MS = 60 * 60 * 1000
export const RECEIPT_TTL_MS = 24 * HOUR_MS
export const PRUNE_EVERY_MS = 6 * HOUR_MS

export interface Mutation {
  readonly route: string
  readonly actionId: ActionId
  readonly requestHash: string
  readonly caregiverId: string
  readonly now: number
}

export type CoreResult<A, E> =
  | { readonly ok: true; readonly response: A; readonly changed: Changed }
  | { readonly ok: false; readonly error: E }

export type Outcome<A, E> =
  | { readonly kind: "applied" | "replayed"; readonly response: A; readonly changed: Changed }
  | { readonly kind: "replay-mismatch"; readonly saved: A }
  | { readonly kind: "other-route" }
  | { readonly kind: "rejected"; readonly error: E }

type ReceiptRow = { route: string; request_hash: string; response: string; changed: string }

const changedJson = Schema.fromJsonString(Changed)

class Rollback extends Error {}

export const withReceipt = <A, E>(
  storage: DurableObjectStorage,
  mutation: Mutation,
  response: Schema.Codec<A, Schema.Json>,
  core: (sql: SqlStorage) => CoreResult<A, E>,
): Outcome<A, E> => {
  const responseJson = Schema.fromJsonString(response)
  let rejected: { readonly error: E } | undefined
  try {
    return storage.transactionSync((): Outcome<A, E> => {
      const { sql } = storage
      const [receipt] = sql
        .exec<ReceiptRow>(
          "SELECT route, request_hash, response, changed FROM receipts WHERE action_id = ?",
          mutation.actionId,
        )
        .toArray()
      if (receipt !== undefined) {
        if (receipt.route !== mutation.route) return { kind: "other-route" }
        const saved = Schema.decodeSync(responseJson)(receipt.response)
        if (receipt.request_hash !== mutation.requestHash) return { kind: "replay-mismatch", saved }
        return { kind: "replayed", response: saved, changed: Schema.decodeSync(changedJson)(receipt.changed) }
      }
      const result = core(sql)
      if (!result.ok) {
        rejected = { error: result.error }
        throw new Rollback()
      }
      sql.exec(
        "INSERT INTO receipts (action_id, route, caregiver_id, request_hash, response, changed, created_at) VALUES (?, ?, ?, ?, ?, ?, ?)",
        mutation.actionId,
        mutation.route,
        mutation.caregiverId,
        mutation.requestHash,
        Schema.encodeSync(responseJson)(result.response),
        Schema.encodeSync(changedJson)(result.changed),
        mutation.now,
      )
      return { kind: "applied", response: result.response, changed: result.changed }
    })
  } catch (error) {
    if (error instanceof Rollback && rejected !== undefined) return { kind: "rejected", error: rejected.error }
    throw error
  }
}

export const requestHash = async <A>(
  route: string,
  payload: Schema.Codec<A, Schema.Json>,
  value: A,
): Promise<string> => {
  const body = JSON.stringify(Schema.encodeSync(payload)(value))
  const digest = await crypto.subtle.digest("SHA-256", new TextEncoder().encode(`${route}\n${body}`))
  return [...new Uint8Array(digest)].map((byte) => byte.toString(16).padStart(2, "0")).join("")
}

export const pruneReceipts = (sql: SqlStorage, now: number): number =>
  sql.exec("DELETE FROM receipts WHERE created_at < ?", now - RECEIPT_TTL_MS).rowsWritten

import {
  type Changed,
  type Diaper,
  DiaperConflict,
  type DiaperEdit,
  InvalidInput,
  type NewDiaper,
  NotFound,
  queryKeys,
  type VersionedAction,
} from "@bt/contracts"
import { affectedPeriods, type Instant, validateNotBeforeBirth, validateNotInFuture } from "@bt/domain"
import type { CoreResult, Stamp } from "./receipts.ts"

type DiaperRow = {
  id: string
  occurred_at: number
  wet: number
  dirty: number
  version: number
  created_by: string
  created_at: number
  updated_by: string
  updated_at: number
  deleted_at: number | null
}

type Found =
  | { readonly ok: true; readonly row: DiaperRow }
  | { readonly ok: false; readonly error: NotFound | DiaperConflict }

const COLUMNS = "id, occurred_at, wet, dirty, version, created_by, created_at, updated_by, updated_at, deleted_at"

const diaperOf = (row: DiaperRow): Diaper => ({
  id: row.id,
  occurredAt: row.occurred_at,
  wet: row.wet === 1,
  dirty: row.dirty === 1,
  version: row.version,
  createdBy: row.created_by,
  createdAt: row.created_at,
  updatedBy: row.updated_by,
  updatedAt: row.updated_at,
  deletedAt: row.deleted_at,
})

const zoneOf = (sql: SqlStorage) => sql.exec<{ time_zone: string }>("SELECT time_zone FROM household").one().time_zone

const moment = (at: Instant | null) => (at === null ? null : { start: at, end: at })

const changedKeys = (sql: SqlStorage, before: Instant | null, after: Instant | null): Changed => [
  queryKeys.today,
  queryKeys.last24h,
  ...affectedPeriods(moment(before), moment(after), zoneOf(sql)),
]

const invalidTime = (sql: SqlStorage, occurredAt: Instant, now: Instant): InvalidInput | null => {
  const { birth_date } = sql.exec<{ birth_date: string }>("SELECT birth_date FROM child").one()
  const issue = validateNotInFuture(occurredAt, now) ?? validateNotBeforeBirth(occurredAt, birth_date, zoneOf(sql))
  return issue === null ? null : new InvalidInput({ fieldErrors: [{ path: "occurredAt", issue }] })
}

const diaperFor = (sql: SqlStorage, id: string, version: number, state: "live" | "deleted"): Found => {
  const [row] = sql.exec<DiaperRow>(`SELECT ${COLUMNS} FROM diapers WHERE id = ?`, id).toArray()
  if (row === undefined) return { ok: false, error: new NotFound() }
  if (row.version !== version) {
    return { ok: false, error: new DiaperConflict({ code: "STALE_VERSION", current: diaperOf(row) }) }
  }
  if ((row.deleted_at === null ? "live" : "deleted") !== state) return { ok: false, error: new NotFound() }
  return { ok: true, row }
}

export const logDiaper =
  (stamp: Stamp, diaper: NewDiaper) =>
  (sql: SqlStorage): CoreResult<Diaper, InvalidInput> => {
    const invalid = invalidTime(sql, diaper.occurredAt, stamp.now)
    if (invalid !== null) return { ok: false, error: invalid }
    const row = sql
      .exec<DiaperRow>(
        `INSERT INTO diapers (id, occurred_at, wet, dirty, version, source, created_by, created_at, updated_by, updated_at)
         VALUES (?, ?, ?, ?, 1, 'app', ?, ?, ?, ?) RETURNING ${COLUMNS}`,
        crypto.randomUUID(),
        diaper.occurredAt,
        Number(diaper.wet),
        Number(diaper.dirty),
        stamp.caregiverId,
        stamp.now,
        stamp.caregiverId,
        stamp.now,
      )
      .one()
    return { ok: true, response: diaperOf(row), changed: changedKeys(sql, null, row.occurred_at) }
  }

export const editDiaper =
  (stamp: Stamp, id: string, edit: DiaperEdit) =>
  (sql: SqlStorage): CoreResult<Diaper, NotFound | InvalidInput | DiaperConflict> => {
    const found = diaperFor(sql, id, edit.version, "live")
    if (!found.ok) return found
    const invalid = invalidTime(sql, edit.occurredAt, stamp.now)
    if (invalid !== null) return { ok: false, error: invalid }
    const row = sql
      .exec<DiaperRow>(
        `UPDATE diapers SET occurred_at = ?, wet = ?, dirty = ?, version = version + 1, updated_by = ?, updated_at = ?
         WHERE id = ? RETURNING ${COLUMNS}`,
        edit.occurredAt,
        Number(edit.wet),
        Number(edit.dirty),
        stamp.caregiverId,
        stamp.now,
        id,
      )
      .one()
    return { ok: true, response: diaperOf(row), changed: changedKeys(sql, found.row.occurred_at, row.occurred_at) }
  }

const setDeletedAt =
  (stamp: Stamp, id: string, action: VersionedAction, deletedAt: Instant | null) =>
  (sql: SqlStorage): CoreResult<Diaper, NotFound | DiaperConflict> => {
    const found = diaperFor(sql, id, action.version, deletedAt === null ? "deleted" : "live")
    if (!found.ok) return found
    const row = sql
      .exec<DiaperRow>(
        `UPDATE diapers SET deleted_at = ?, version = version + 1, updated_by = ?, updated_at = ?
         WHERE id = ? RETURNING ${COLUMNS}`,
        deletedAt,
        stamp.caregiverId,
        stamp.now,
        id,
      )
      .one()
    return {
      ok: true,
      response: diaperOf(row),
      changed: [...changedKeys(sql, row.occurred_at, null), queryKeys.deleted],
    }
  }

export const deleteDiaper = (stamp: Stamp, id: string, action: VersionedAction) =>
  setDeletedAt(stamp, id, action, stamp.now)

export const restoreDiaper = (stamp: Stamp, id: string, action: VersionedAction) =>
  setDeletedAt(stamp, id, action, null)
```

import { type ActionId, type Changed, CurrentCaregiver, InvalidInput } from "@bt/contracts"
import { Effect, type Schema } from "effect"
import type { HttpServerRequest } from "effect/http"
import { type CoreResult, type Outcome, requestHash, type Stamp, withReceipt } from "./core/receipts.ts"

export interface Saved<A> {
  readonly record: A
  readonly changed: Changed
}

const settle = <A, E, C>(outcome: Outcome<A, E>, replayMismatch: (saved: A) => C) => {
  switch (outcome.kind) {
    case "applied":
    case "replayed":
      return Effect.succeed<Saved<A>>({ record: outcome.response, changed: outcome.changed })
    case "replay-mismatch":
      return Effect.fail(replayMismatch(outcome.saved))
    case "other-route":
      return Effect.fail(new InvalidInput({ fieldErrors: [{ path: "actionId", issue: "invalid" }] }))
    case "rejected":
      return Effect.fail(outcome.error)
  }
}

export const mutations =
  <A, C>(storage: DurableObjectStorage, record: Schema.Codec<A, Schema.Json>, replayMismatch: (saved: A) => C) =>
  <P extends { readonly actionId: ActionId }, E>(
    request: HttpServerRequest.HttpServerRequest,
    payload: Schema.Codec<P, Schema.Json>,
    value: P,
    core: (stamp: Stamp) => (sql: SqlStorage) => CoreResult<A, E>,
  ) =>
    Effect.gen(function* () {
      const caregiver = yield* Effect.service(CurrentCaregiver)
      const route = `${request.method} ${new URL(request.originalUrl).pathname}`
      const hash = yield* Effect.promise(() => requestHash(route, payload, value))
      const stamp = { caregiverId: caregiver.id, now: Date.now() }
      const mutation = { ...stamp, route, actionId: value.actionId, requestHash: hash }
      return yield* settle(withReceipt(storage, mutation, record, core(stamp)), replayMismatch)
    })
```

  Layer.succeed(Authorization, (handler) =>
    Effect.gen(function* () {
      const request = yield* HttpServerRequest.HttpServerRequest

      return yield* Effect.provideService(handler, CurrentCaregiver, caregiver)

  Effect.sync(() => HttpServerResponse.fromWeb(errorResponse(new NotFound()))),
