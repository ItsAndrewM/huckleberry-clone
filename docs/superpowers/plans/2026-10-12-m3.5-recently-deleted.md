# M3.5 Recently Deleted Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, as Andrew chose on 12 Oct 2026) to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a parent can bring back an entry deleted by mistake:
- **The list:** Settings › Recently deleted shows every feed, diaper and measurement deleted in the last 30 days, newest deletion first. Each reads as Today reads it, with when it happened, and who deleted it and when.
- **Restore:** one tap puts it back through the restore each kind already has. The household re-runs every check (D10), the birth date now included, and the row says why when it can't.
- **Undo:** a restored diaper or feed shows "Bottle restored" (or "Diaper restored", "Feed restored") with Undo for five seconds, as a save does.

**Architecture:**
- **`packages/contracts/src/deleted.ts` (new):** `Deleted`, which is `{feeds, diapers, measurements}`, `RECENTLY_DELETED_DAYS = 30`, and `DeletedGroup`'s one endpoint, `GET /api/deleted`.
- **The Worker:**
  - `deletedDiapersSince`, `deletedFeedsSince` and `deletedMeasurementsSince` sit beside each kind's live loaders
  - `core/deleted.ts`'s `deletedOf(sql, now)` reads all three, and `deleted-handlers.ts` serves them
  - `restoreDiaper`, `restoreFeed` and `restoreMeasurement` run the time check a new entry runs, so an entry from before the birth date stays deleted
- **The web:**
  - `api/deleted.ts`: `deletedQuery`; `api/hooks.ts`: `useDeleted`
  - `api/actions.ts` and `send.ts`: three `Action` kinds, `restoreDiaper`, `restoreFeed` and `restoreMeasurement`
  - `features/deleted/deleted-rows.ts`: the rows, pure
  - `features/deleted/restore.ts`: a row's restore, the reason to wait, the failure's sentence and `withoutEntry`, all pure
  - `sheets/undo.ts`: `restoredToast`; `sheets/sheets-state.ts`: `announcedState`; the frame's new `announce`
  - `features/deleted/use-restore.ts`: one mutation per row
  - `deleted-page.tsx`, `deleted-list.tsx`, `deleted-item.tsx` and `deleted-icons.ts`; Settings' `deleted-section.tsx`; the `/settings/deleted` route

## Decisions this plan makes (veto in review)

- **P1, one read, three lists.** `GET /api/deleted` answers `{feeds, diapers, measurements}`, each newest deletion first, as M3.6's periods hold their records. A later kind (M3.1's sleeps, M3.3's doses) joins as its own list, which an older app ignores, so the answer needs no skip-unknown decoder.
- **P2, the window.** 30 × 24 hours back from the household's clock, at each read. Nothing is purged: an older row stays in its table and the JSON export, and only leaves the list. There's no index on `deleted_at`, so the read scans the three tables; M5.5 times it.
- **P3, who deleted it.** A delete stamps `updatedBy` and `updatedAt`, so a deleted row's `updatedBy` is who deleted it. A caregiver the household no longer names reads "Deleted", with the time.
- **P4, the restore's check.** It's the `timeIssue` a new entry runs, "in the future" and "before the birth date", on `occurredAt`, a feed's `startedAt` (its earliest part) or `measuredAt`. Its future half can't fail on a restore, since an entry's time was within 5 minutes of its save. M4.3's edit-side note is left alone: with restores refusing, a live entry can only sit before the birth date after a zone change, and this household's logging began days after her birth.
- **P5, restores are `Action` kinds.** `restoreDiaper`, `restoreFeed` and `restoreMeasurement`, as M1.12's hand-off says, so M3.4's "Deleted · Undo" can later send one through the frame. Today they don't pass through it: each row has its own mutation, so a refusal stays under its row, as Settings' and Export's do, instead of opening a sheet. So the frame's table learns the kinds (they close nothing and aren't entries), the growth cache shows nothing early for one, and a measurement session ignores one.
- **P6, the Undo.** The toast is the frame's, through its new `announce`, so it's the toast a save shows, and it stays up as the parent moves on. Its Undo is the delete, sent through `sheets.send`, whose failure says "That wasn't undone." (`UNDOES`). The words: "Diaper restored", "Bottle restored" for a bottle-only feed, otherwise "Feed restored". A measurement's toast reads "Measurement restored" with no Undo, as a measurement save has none (M4.4): its card deletes it any time.
- **P7, the `actionId`.** Made when a row shows, and the row is keyed by its id and version. So a restore tried again after the household couldn't take it sends the same `actionId` and can't restore twice (AC 14), and a restore after Undo, whose version is new, gets a new one.
- **P8, no early restore.** The row says "Restoring…" until the household answers, then leaves the list at once, and every key in the answer's `changed` refetches: Today, the days and Growth. A restore is rare and deliberate, and showing it early would need the record the answer brings.
- **P9, how a row reads.**
  - Like Today's recent row: an icon tile, the title and its parts.
  - Then when it happened, "Fri, Oct 9 at 8:40 AM" in the phone's own wording, with the date, since the list spans 30 days.
  - Then "Deleted by Emily · Fri, Oct 9 at 9:25 AM".
  - A feed deleted while running or paused says "Running when deleted" or "Paused when deleted", its minutes counted up to the delete. Restoring it brings it back running from its start, as the server has done since M1.7.
  - A measurement lists its values in the household's units: "Weight 4.21 kg · Head 37.5 cm".
  - Each Restore's accessible name names its entry: "Restore Diaper, Fri, Oct 9 at 8:40 AM".
- **P10, what a refusal says.** "That's before Robin was born."; "Emily started a feed at 9:05 AM. Finish it, then restore this one."; "This overlaps the feed at 8:50 AM–9:05 AM."; "Emily restored this a moment ago." (or "changed", when it's still deleted); "No connection. Try again once you're back online."; "Your sign-in has expired. Sign in, then try again."; and "Not restored. Try again." for anything else. While offline or signed out every Restore waits, with "Restoring needs a connection." or "Sign in to restore." above the list.
- **P11, where.** A "Recently deleted" section after Export, inside the household's branch of Settings, whose "See deleted entries ›" leads to `/settings/deleted`. That page has a "‹ Settings" link above its title (`Page`'s new `back`), since the installed app has no browser back. The Settings tab stays lit there: the tab bar now matches exactly only for Today.

## Review Focus

The five inputs most likely to bite that the spec implies but doesn't spell out, each with the test that pins it:

1. **A restore tried again after the household couldn't take it** (one bar of signal, a 503): it must not restore twice, or blame the other phone for its own first try. Task 4, "tries a restore the household couldn't take again under the same actionId, so it can't restore twice".
2. **The other phone restored it, or changed it, a moment before:** the row must say who, then leave the list as it refreshes. Task 3, "says the other parent restored it already, or changed it, from the copy the household sent back".
3. **A feed deleted while running, restored later:** it comes back running from its start, or is refused while another runs, saying whose. Task 3, "says a feed was running or paused when it was deleted, and counts its time up to the delete", and Task 4, "says a running feed can't come back while another runs, and keeps it on the list to try again". M1.7's `restoreFeed` tests keep the server's side.
4. **The 30-day edge:** an entry deleted exactly 30 days ago is listed, and one a millisecond older isn't. Task 1, "reach back exactly 30 days from the household's clock".
5. **An entry dated before the birth date, after the birth date moved later:** refused, kept on the list, and the row says why. Task 2's three refusals and its 400, and Task 4, "refuses an entry from before her birth date, saying why".

interface Current {
  readonly updatedBy: string
  readonly deletedAt: number | null
}

const staleSentence = (household: Household, { updatedBy, deletedAt }: Current) =>
  `${nameOf(household, updatedBy)} ${deletedAt === null ? "restored" : "changed"} this a moment ago.`

const feedSentence = ({ code, current }: FeedConflict, household: Household): string => {
  switch (code) {
    case "FEED_ALREADY_ACTIVE": {
      const started = `${nameOf(household, current.createdBy)} started a feed at ${timeOf(household, current.startedAt)}.`
      return `${started} Finish it, then restore this one.`
    }
    case "SEGMENT_OVERLAP":
      return `This overlaps the feed at ${spanOf(household, current)}.`
    case "STALE_VERSION":
      return staleSentence(household, current)
    case "FEED_EMPTY":
    case "ACTION_REPLAY_MISMATCH":
      return NOT_RESTORED
  }
}

const conflictSentence = (error: Error, household: Household): string | null => {
  if (error instanceof FeedConflict) return feedSentence(error, household)
  if (!(error instanceof DiaperConflict) && !(error instanceof MeasurementConflict)) return null
  return error.code === "STALE_VERSION" ? staleSentence(household, error.current) : NOT_RESTORED
}

const invalidSentence = ({ fieldErrors }: InvalidInput, { childName }: Household) =>
  fieldErrors.some(({ issue }) => issue === "before_birth") ? `That's before ${childName} was born.` : NOT_RESTORED

export const restoreFailure = (error: Error, household: Household): string => {
  if (error instanceof Offline) return "No connection. Try again once you're back online."
  if (error instanceof AuthRequired || error instanceof Unauthorized) {
    return "Your sign-in has expired. Sign in, then try again."
  }
  if (error instanceof InvalidInput) return invalidSentence(error, household)
  return conflictSentence(error, household) ?? NOT_RESTORED
}

import { type Deleted, queryKeys } from "@bt/contracts"
import { useMutation, useQueryClient } from "@tanstack/react-query"
import { useState } from "react"
import { send } from "../../api/send.ts"
import { useApp } from "../../app-context.ts"
import { useSheets } from "../../sheets/sheets-context.ts"
import { restoredToast } from "../../sheets/undo.ts"
import type { DeletedRow } from "./deleted-rows.ts"
import { restoreOf, withoutEntry } from "./restore.ts"

export const useRestore = (row: DeletedRow) => {
  const { api } = useApp()
  const queryClient = useQueryClient()
  const { announce } = useSheets()
  const [actionId] = useState(() => crypto.randomUUID())
  const restoring = useMutation({
    mutationFn: () => send(api, restoreOf(row.record, actionId)),
    onSuccess: (saved) => {
      queryClient.setQueryData<Deleted>(queryKeys.deleted, (deleted) =>
        deleted === undefined ? deleted : withoutEntry(deleted, row.id),
      )
      for (const queryKey of saved.changed) void queryClient.invalidateQueries({ queryKey })
      announce(restoredToast(saved, Date.now(), crypto.randomUUID()))
    },
  })
  return {
    busy: restoring.isPending,
    error: restoring.isPending ? null : restoring.error,
    restore: () => restoring.mutate(),
  }
}
