# M5.5 Bundle and Performance Check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, as Andrew chose on 13 Oct 2026) to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** measure how the household's reads and writes hold up after two years of heavy logging, fix the two lookups that made Today grow with history, and stop the app's bundle from growing unnoticed:
- **Today:** its last-feed and last-side lookups walk the indexes they already have, so those two lookups stop growing with history (Today 11 ms → about 2 ms at two years). Today's 24-hour list still walks the feeds' time index from its start, about 1 ms at two years (P11).
- **A bench by hand:** `pnpm bench` times each read and a feed write over two years of synthetic data in a test household. CI never runs it.
- **A web size limit:** `pnpm bundle:check` also fails when the app's main script passes 350 kB gzip or its CSS passes 15 kB.
- **Two render fixes:** one clock formatter per zone, locale and format, and No connection's bar on the minute clock.

**Architecture:**
- **`apps/worker/src/core/feeds/reads.ts`:** `lastFeed` and `prefillOf`'s last-side query name their index with `INDEXED BY` and keep their `ORDER BY … rowid DESC`. SQLite then walks `feeds_by_time` and `nursing_segments_by_time` backwards and stops at the first live row, sorting only rows tied on the time, instead of sorting every row ever logged.
- **`apps/worker/test/rows-read.ts` (new, test only):** `countingRowsRead(sql)` wraps a `SqlStorage` and adds up each cursor's `rowsRead`, so a test pins "reads a handful of rows" without timing anything.
- **The bench (new):**
  - `apps/worker/test/two-years.ts` seeds 730 days by SQL.
  - `apps/worker/test/routes.bench.ts` times each route through the household's fetch and prints a table.
  - `apps/worker/vitest.bench.config.ts` runs only `test/**/*.bench.ts`. The Worker project's default pattern never matches `*.bench.ts`, so `pnpm test` skips it. `pnpm bench` runs `@bt/worker`'s `bench` script.
- **`scripts/bundle-size.ts`:** `entryAsset(dir, kind)` finds the one `index-*.js` or `index-*.css`, and `gzipKB(file)` gzips it with `node:zlib`. `check-bundle-size.ts` prints the Worker and both app sizes, and fails if any is over.
- **`apps/web/src/clock-time.ts`:** `formatterFor(format, timeZone, locale)` keeps each `Intl.DateTimeFormat` in a module `Map`. `clockTime`, `dayClockTime` and `dateClockTime` read from it, and `shell/updated.ts` reuses `clockTime`. `shell/connection-banner.tsx`'s `OfflineBanner` reads `useMinute()`.

## Decisions this plan makes (veto in review)

- **P1, `INDEXED BY` rather than new queries.** Each query keeps its `ORDER BY started_at DESC, rowid DESC`, so two feeds logged for the same minute still resolve as before. SQLite sorts only the rows tied on `started_at` (`USE TEMP B-TREE FOR LAST TERM OF ORDER BY`). The cost: renaming or dropping `feeds_by_time` or `nursing_segments_by_time` would make these two queries fail with "no such index", which Today's tests would catch at once. A two-step subquery for the last feed measured the same, but reads less plainly.
- **P2, rows read, not time, pins the fix.** `countingRowsRead` adds up each cursor's `rowsRead`, which workerd counts the same on every run. With 150 feeds the last feed read 309 rows before the fix, and 12 after; the prefill reads 7. A timing test would be flaky, and Andrew kept timings out of CI (D2).
- **P3, the bench's load is flat and heavy, not a realistic curve:**
  - 12 feeds a day, two hours apart, each with two 10-minute sides and a 60 mL bottle
  - 10 diapers a day, every third one dirty
  - a measurement every 7 days
  - every 50th feed deleted an hour after it started

  It's seeded by SQL, so no check runs on it, and seeding takes 0.3 s.
- **P4, the bench lives in `apps/worker/test/`,** as `*.bench.ts`, beside the fixtures it imports, under its own Vitest config. A new folder would add a lint-probe test.
- **P5, the bench asserts its own load.** `vitest/expect-expect` wants an assertion, so it checks the seeded row counts against `TWO_YEARS`. Each route also throws on a non-2xx answer.
- **P6, `node:zlib` sizes.** `bundle:check` gzips at zlib's default level: 303.12 kB for the script that Vite's report calls 306.48 kB, since Vite 8 gzips inside rolldown. The 350 kB limit leaves about 47 kB by this measure, or about 35 kB once M3.10 merges.
- **P7, exactly one entry file.** `entryAsset` refuses none ("run `pnpm build` first") and refuses two, so a build that renames or splits the entry fails the check instead of measuring the wrong file.
- **P8, the formatter cache never empties.** A phone meets one or two zones and one locale, so the `Map` holds a handful of formatters.
- **P9, `updated.ts` reuses `clockTime`.** Its `timeOf` built the same formatter as `clockTime` on every call. Its date formatter runs only when the day differs, so it stays as it is.
- **P10, the midnight E2E runs in Chromium only.** WebKit's `setOffline` lets the socket's next try open: Playwright's routed socket opens before the route closes it, and the app counts an open socket as back online. The bar's minute clock is the same code in both engines. `offline.spec.ts` and `sheets-offline.spec.ts` skip WebKit the same way.
- **P11, left as they are:**
  - a month's per-feed queries: 13 ms at two years (D3)
  - Today's `liveFeedsSince`, which still walks `feeds_by_time` from the start (about 1 ms): a paused feed can run past a day, so no lower bound on its start is safe
  - Recently deleted's unindexed `deleted_at` scan: 2 ms
  - the CSV export: 0.2 s
  - the JSON export at 15 MB: it reaches the admin export's 32 MiB RPC cap only after about four years of this load

## Review Focus

The five inputs most likely to bite a parent that the spec implies but doesn't spell out, each with the test that pins it:

1. **Two feeds logged for the same minute** (a past bottle and a past nursing feed, both at 2:15): Today's last feed must stay the one logged last, as before. Task 1, "takes the later-logged of two feeds that start at the same minute as the last feed".
2. **The newest feed or side deleted, or the latest side still running:** Today must take the latest live one, as before. Task 1 reruns the existing "leaves a deleted feed out of everything…", "leaves out a deleted segment, bottle or diaper…" and "counts a running side up to now…".
3. **A build with no entry script, or two:** `bundle:check` must fail loudly, not pass on nothing or measure one of them. Task 3, "refuses a build that isn't there…" and "refuses two entry scripts…".
4. **A household that changes zone while the app is open:** clock times must use the new zone at once, not a formatter kept for the old one. Task 4, "gives another zone, locale or format a formatter of its own".
5. **Midnight while the phone is offline:** No connection's line must gain its date once the household's day turns, now on the minute clock. Task 4's E2E, "gives No connection's last-updated time its date once the household's midnight passes", with a bite check.

export const countingRowsRead = (sql: SqlStorage) => {
  const cursors: Array<{ readonly rowsRead: number }> = []
  const counted: SqlStorage = {
    exec: <T extends Record<string, SqlStorageValue>>(query: string, ...bindings: SqlStorageValue[]) => {
      const cursor = sql.exec<T>(query, ...bindings)
      cursors.push(cursor)
      return cursor
    },
    get databaseSize() {
      return sql.databaseSize
    },
    Cursor: sql.Cursor,
    Statement: sql.Statement,
  }
  return { sql: counted, rowsRead: () => cursors.reduce((sum, cursor) => sum + cursor.rowsRead, 0) }
}
````

export type ClockFormat = "time" | "dayTime" | "dateTime"

const OPTIONS = {
  time: { hour: "numeric", minute: "2-digit" },
  dayTime: { weekday: "short", hour: "numeric", minute: "2-digit" },
  dateTime: { weekday: "short", month: "short", day: "numeric", hour: "numeric", minute: "2-digit" },
} satisfies Record<ClockFormat, Intl.DateTimeFormatOptions>

const formatters = new Map<string, Intl.DateTimeFormat>()

export const formatterFor = (format: ClockFormat, timeZone: string, locale?: string) => {
  const key = `${format} ${timeZone} ${locale ?? ""}`
  const kept = formatters.get(key)
  if (kept !== undefined) return kept
  const formatter = new Intl.DateTimeFormat(locale, { ...OPTIONS[format], timeZone })
  formatters.set(key, formatter)
  return formatter
}

export const clockTime = (instant: number, timeZone: string, locale?: string) =>
  formatterFor("time", timeZone, locale).format(instant)

export const dayClockTime = (instant: number, timeZone: string, locale?: string) =>
  formatterFor("dayTime", timeZone, locale).format(instant)

export const dateClockTime = (instant: number, timeZone: string, locale?: string) =>
  formatterFor("dateTime", timeZone, locale).format(instant)
````
