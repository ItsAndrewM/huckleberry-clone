# M4.3 Growth Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen by Andrew on 10 Oct 2026) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Parents can log, edit, delete and restore a growth measurement (a weight, a length, a head circumference, or any mix of them) through the household's API, and read every live measurement back. M4.4 builds the Growth screen on it.

**Architecture:**
- **The contract:** `packages/contracts/src/growth.ts` holds the measurement record, its payloads, `MeasurementConflict`, each metric's limits, and `GrowthGroup`: `GET /api/growth` and four mutations.
- **The table and core:** migration `0006-growth` adds `growth_measurements`. `apps/worker/src/core/growth.ts` holds `growthOf` and four synchronous mutations that take a `Stamp`, as `core/diapers.ts` does. `earliestRecordAt` counts measurements, so a birth date can't move after one.
- **The endpoints:** `growth-handlers.ts` runs each mutation through M1.6's `mutations` (caller, hash, clock, `withReceipt`), as `feed-handlers.ts` does. `householdApi` gains the group.
- **A domain rename:** `validateOunces` becomes `validateOuncePart` (the M1.2 handoff).

**Tech Stack:** TypeScript 5.9.3, `effect` 4.0.1 (Schema, `effect/http`, `effect/http-api`), `@bt/contracts`, `@bt/domain`, Workers and Durable Objects (`@cloudflare/workers-types` 5.20261006.1, wrangler 4.148.0), `@cloudflare/vitest-plugin` 1.3.7, Vitest 4.1.11, Playwright 1.64.0, oxlint 1.87.0 and oxfmt 0.72.0, Node 24.21.0. No new dependency.

## Decisions this plan makes (veto in review)

- **P1: A measurement is its time and up to three metrics, and nothing else** (Andrew, 10 Oct 2026; the spec's §8 isn't in the repo).
  - `measuredAt` is an instant, like a diaper's `occurredAt`. Percentiles (M4.2, M4.4) use its local date in the household's zone, at the child's chronological age (Andrew's M4.2 decision).
  - `weightG` is in grams, and `lengthCm` and `headCm` (head circumference) in centimetres. Each may be `null`, and at least one is set.
  - The record also carries `id`, `version`, `createdBy`, `createdAt`, `updatedBy`, `updatedAt` and `deletedAt`, as a diaper does. D4's `source` and `source_ref` stay in the table.
  - **Any number of measurements may share a day, or even a time, with no prompt** (Andrew, 10 Oct 2026). If both parents log the same visit, the other phone shows the second entry within seconds and either parent can delete it. So there's no duplicate check and no new conflict code.
- **P2: Values keep full precision** (§3.1). A weight entered as 7 lb 8.5 oz arrives as unrounded grams and reads back as the same pounds and ounces. Only the display rounds.
- **P3: Each metric has a minimum and a maximum, both allowed: weight 200 g to 40 kg, length 20 to 150 cm, head circumference 15 to 70 cm** (Andrew, 10 Oct 2026).
  - The minimums are below any baby born alive. They catch a weight in kilograms typed into a grams field, 3.5 g, which the household's `g` unit makes easy.
  - The maximums catch the reverse slip, 3,500 typed into a kilogram field. For scale, WHO's +4 SD for a girl at day 730 is 19.175 kg, 99.302 cm and 52.762 cm.
  - Both go into the table's `CHECK`, as a bottle's 0.05 to 500 mL does, so changing one later means rebuilding the table. They're loose enough not to need it.
  - Zero and negatives are refused before any core runs. That also keeps `poundsOuncesFromGrams` away from the negative grams it mishandles (the M1.2 handoff).
  - `MIN_WEIGHT_G`, `MAX_WEIGHT_G`, `MIN_LENGTH_CM`, `MAX_LENGTH_CM`, `MIN_HEAD_CM` and `MAX_HEAD_CM` are exported for M4.4's form.
- **P4: One schema check, shared by POST and PATCH, requires at least one metric.** It names all three fields when none is set, as the diaper's wet-or-dirty check names both. The table's `CHECK` stands behind it.
- **P5: An edit sends every field** (M1.6's P6).
  - `null` clears a metric, and the others keep the values sent.
  - **An edit that clears the last metric is refused** with 400 naming all three, and the measurement stays as it was (Andrew, 10 Oct 2026). M4.4's form asks "Delete this measurement?" instead, then sends `DELETE`.
  - No conflict code like `FEED_EMPTY` is added. The phone always knows when its form is empty, while a feed's emptiness can depend on the server (a finish corrected back to its start).
  - POST takes the same fields, so a metric not measured is sent as `null`, not left out. One shape serves both.
- **P6: `measuredAt` follows a diaper's rules** (M1.6's P7). It's required. It may be at most 5 minutes ahead of the server's clock (`in_future`, AC 21), and not before the birth date began in the household's zone (`before_birth`).
- **P7: PATCH, DELETE and restore refuse in a diaper's order** (M1.6's P8).
  - An unknown id gets 404.
  - A stale version gets 409 `STALE_VERSION` with the measurement as it is now, deleted or not.
  - The right version in the wrong state gets 404: editing or deleting a deleted measurement, or restoring a live one.
  - Then the time is checked (400).
  - A restore checks only the version and the state, as a diaper's does. It doesn't check the time against the birth date again: M1.15's P7 leaves "whether a restore refuses a record from before the birth date" to M3.5, for every record type. (Corrected in the final review: this line used to say measurements have no invariant across records, which `before_birth` makes untrue.)
- **P8: `changed` is `today`, `last24h`, the day, week and month keys of the old and new times, and `growth`. A delete or restore adds `deleted`.**
  - D7 invalidates `today` and `last24h` on every mutation.
  - The period keys serve M3.6's day records and M3.7's growth strip. A measurement is a point event, `{ start: t, end: t }`.
  - `growth` is the key of `GET /api/growth`.
- **P9: `GET /api/growth` answers `{ measurements }`:** every live measurement, newest first, and the later-logged first when two share a time (Andrew, 10 Oct 2026).
  - It's the read M4.4's screen builds on. The M4.3 row doesn't list it, but it's the server half of the record and the `growth` key needs a query.
  - **Percentiles never join it.** The phone works them out in M4.4 from `me` and the household's zone (Andrew, 10 Oct 2026, in M4.2's review). M4.5's charts need WHO's tables on the phone anyway.
- **P10: The endpoints.** Each mutation answers `{ measurement, changed }`.
  - `POST /api/growth` with `{ actionId, measuredAt, weightG, lengthCm, headCm }` → 201.
  - `PATCH /api/growth/:id` with `{ actionId, version, measuredAt, weightG, lengthCm, headCm }` → 200.
  - `DELETE /api/growth/:id` with the JSON body `{ actionId, version }` → 200.
  - `POST /api/growth/:id/restore` with `{ actionId, version }` → 200.
  - One `MeasurementConflict` serves all four, with the codes `STALE_VERSION` and `ACTION_REPLAY_MISMATCH` and `current: Measurement` (M1.6's P10).
- **P11: Migration `0006-growth` adds the `growth_measurements` table.**
  - It's `STRICT`. `CHECK`s keep each instant within `Instant`'s years, as `0004-feeds` does, and each metric within its minimum and maximum. They also require one metric, a `version` of 1 or more, and a `source` of `app` or `import`, with `source_ref` set exactly when imported.
  - The `CHECK`s mirror the contract, so a stored row always decodes (M1.6's deferred minor, and M1.7's bottle check).
  - D4's partial unique index on `(source, source_ref) WHERE source = 'import'`, and an index on `measured_at`.
- **P12: A birth date can't move after a live measurement.** `earliestRecordAt` counts measurements (the M1.15 handoff). A deleted one doesn't count.
- **P13: `validateOunces` becomes `validateOuncePart` and checks against `OUNCES_PER_POUND`** (the M1.2 handoff). Only its test calls it today; M4.4's pound-and-ounce entry will.
- **P14: Names.**
  - The contract: `Measurement`, `NewMeasurement`, `MeasurementEdit`, `SavedMeasurement`, `MeasurementConflict`, `Growth`, and `GrowthGroup` ("growth") with the endpoints `growth`, `logMeasurement`, `editMeasurement`, `deleteMeasurement` and `restoreMeasurement`.
  - The Worker: `core/growth.ts` and `growth-handlers.ts`.
  - The columns `weight_g`, `length_cm` and `head_cm`, as Andrew saw them when he chose P1.
- **P15: Sizes.** The Worker bundle grows from 254.25 to 255.35 KiB gzip. The app's JS grows from 190.70 to 191.02 kB gzip, since its client is built from the whole `Api`.

## Review Focus

1. **A save applied twice** (AC 14). A phone whose save went through, but whose answer was lost, sends it again. Expect the stored 201 again, and still one measurement. Tested in Task 4.
2. **Two parents editing one measurement at once** (AC 13). Expect one edit saved and the other answered 409 `STALE_VERSION` with the winner's measurement, never a silent overwrite. Tested in Tasks 3 and 4.
3. **A slipped unit or decimal:** 3.5 typed into a grams field (3.5 g), 3,500 typed into a kilogram field (3,500,000 g), a zero, a negative, a number sent as a string. Expect 400 naming the field, nothing saved, and a table that refuses what the contract can't decode. Tested in Tasks 2 and 3.
4. **An edit that clears the last metric.** Expect 400 naming all three fields, and the measurement unchanged, so M4.4 can offer to delete it instead. Tested in Tasks 2 and 4.
5. **A birth date after a measurement, or a measurement before the birth date.** Expect `before_birth` either way while the measurement is live, and the birth date free to move once it's deleted. Tested in Task 3.

import { Schema } from "effect"
import { HttpApiEndpoint, HttpApiGroup, HttpApiSchema } from "effect/http-api"
import { ActionId } from "./action-id.ts"
import { Conflict, InvalidInput, NotFound } from "./errors.ts"
import { Changed } from "./query-keys.ts"
import { Instant } from "./time.ts"
import { Version, VersionedAction } from "./version.ts"

export const MIN_WEIGHT_G = 200
export const MAX_WEIGHT_G = 40_000
export const MIN_LENGTH_CM = 20
export const MAX_LENGTH_CM = 150
export const MIN_HEAD_CM = 15
export const MAX_HEAD_CM = 70

const metricBetween = (minimum: number, maximum: number) =>
  Schema.NullOr(Schema.Finite.check(Schema.isBetween({ minimum, maximum })))

const metricFields = {
  weightG: metricBetween(MIN_WEIGHT_G, MAX_WEIGHT_G),
  lengthCm: metricBetween(MIN_LENGTH_CM, MAX_LENGTH_CM),
  headCm: metricBetween(MIN_HEAD_CM, MAX_HEAD_CM),
}

export const Measurement = Schema.Struct({
  id: Schema.String,
  measuredAt: Instant,
  ...metricFields,
  version: Version,
  createdBy: Schema.String,
  createdAt: Instant,
  updatedBy: Schema.String,
  updatedAt: Instant,
  deletedAt: Schema.NullOr(Instant),
})
export type Measurement = typeof Measurement.Type

const SOME_METRIC = "a weight, a length or a head circumference"

interface Metrics {
  readonly weightG: number | null
  readonly lengthCm: number | null
  readonly headCm: number | null
}

const someMetric = Schema.makeFilter(
  ({ weightG, lengthCm, headCm }: Metrics) =>
    weightG !== null ||
    lengthCm !== null ||
    headCm !== null || [
      { path: ["weightG"], issue: SOME_METRIC },
      { path: ["lengthCm"], issue: SOME_METRIC },
      { path: ["headCm"], issue: SOME_METRIC },
    ],
  { expected: SOME_METRIC },
)

const measurementFields = { measuredAt: Instant, ...metricFields }

export const NewMeasurement = Schema.Struct({ actionId: ActionId, ...measurementFields }).check(someMetric)
export type NewMeasurement = typeof NewMeasurement.Type

export const MeasurementEdit = Schema.Struct({ actionId: ActionId, version: Version, ...measurementFields }).check(
  someMetric,
)
export type MeasurementEdit = typeof MeasurementEdit.Type

export const SavedMeasurement = Schema.Struct({ measurement: Measurement, changed: Changed })
export type SavedMeasurement = typeof SavedMeasurement.Type

export const Growth = Schema.Struct({ measurements: Schema.Array(Measurement) })
export type Growth = typeof Growth.Type

export class MeasurementConflict extends Conflict<MeasurementConflict>()(
  "MeasurementConflict",
  ["STALE_VERSION", "ACTION_REPLAY_MISMATCH"],
  Measurement,
) {}

const byId = { id: Schema.String }

export class GrowthGroup extends HttpApiGroup.make("growth")
  .add(HttpApiEndpoint.get("growth", "/growth", { success: Growth }))
  .add(
    HttpApiEndpoint.post("logMeasurement", "/growth", {
      payload: NewMeasurement,
      success: SavedMeasurement.pipe(HttpApiSchema.status(201)),
      error: [InvalidInput, MeasurementConflict],
    }),
  )
  .add(
    HttpApiEndpoint.patch("editMeasurement", "/growth/:id", {
      params: byId,
      payload: MeasurementEdit,
      success: SavedMeasurement,
      error: [InvalidInput, NotFound, MeasurementConflict],
    }),
  )
  .add(
    HttpApiEndpoint.delete("deleteMeasurement", "/growth/:id", {
      params: byId,
      payload: VersionedAction,
      success: SavedMeasurement,
      error: [InvalidInput, NotFound, MeasurementConflict],
    }),
  )
  .add(
    HttpApiEndpoint.post("restoreMeasurement", "/growth/:id/restore", {
      params: byId,
      payload: VersionedAction,
      success: SavedMeasurement,
      error: [InvalidInput, NotFound, MeasurementConflict],
    }),
  ) {}

import {
  type Changed,
  type Growth,
  InvalidInput,
  type Measurement,
  MeasurementConflict,
  type MeasurementEdit,
  type NewMeasurement,
  NotFound,
  queryKeys,
  type VersionedAction,
} from "@bt/contracts"
import type { Instant } from "@bt/domain"
import { type Calendar, calendarOf, changedKeys, timeIssue } from "./calendar.ts"
import type { CoreResult, Stamp } from "./receipts.ts"

type MeasurementRow = {
  id: string
  measured_at: number
  weight_g: number | null
  length_cm: number | null
  head_cm: number | null
  version: number
  created_by: string
  created_at: number
  updated_by: string
  updated_at: number
  deleted_at: number | null
}

type Found =
  | { readonly ok: true; readonly row: MeasurementRow }
  | { readonly ok: false; readonly error: NotFound | MeasurementConflict }

const COLUMNS =
  "id, measured_at, weight_g, length_cm, head_cm, version, created_by, created_at, updated_by, updated_at, deleted_at"

const measurementOf = (row: MeasurementRow): Measurement => ({
  id: row.id,
  measuredAt: row.measured_at,
  weightG: row.weight_g,
  lengthCm: row.length_cm,
  headCm: row.head_cm,
  version: row.version,
  createdBy: row.created_by,
  createdAt: row.created_at,
  updatedBy: row.updated_by,
  updatedAt: row.updated_at,
  deletedAt: row.deleted_at,
})

export const growthOf = (sql: SqlStorage): Growth => ({
  measurements: sql
    .exec<MeasurementRow>(
      `SELECT ${COLUMNS} FROM growth_measurements WHERE deleted_at IS NULL ORDER BY measured_at DESC, rowid DESC`,
    )
    .toArray()
    .map(measurementOf),
})

const moment = (at: Instant | null) => (at === null ? null : { start: at, end: at })

const changedFrom = (calendar: Calendar, before: Instant | null, after: Instant | null): Changed => [
  ...changedKeys(calendar, moment(before), moment(after)),
  queryKeys.growth,
]

const invalidTime = (calendar: Calendar, measuredAt: Instant, now: Instant): InvalidInput | null => {
  const issue = timeIssue(calendar, measuredAt, now)
  return issue === null ? null : new InvalidInput({ fieldErrors: [{ path: "measuredAt", issue }] })
}

const measurementFor = (sql: SqlStorage, id: string, version: number, state: "live" | "deleted"): Found => {
  const [row] = sql.exec<MeasurementRow>(`SELECT ${COLUMNS} FROM growth_measurements WHERE id = ?`, id).toArray()
  if (row === undefined) return { ok: false, error: new NotFound() }
  if (row.version !== version) {
    return { ok: false, error: new MeasurementConflict({ code: "STALE_VERSION", current: measurementOf(row) }) }
  }
  if ((row.deleted_at === null ? "live" : "deleted") !== state) return { ok: false, error: new NotFound() }
  return { ok: true, row }
}

export const logMeasurement =
  (stamp: Stamp, measurement: NewMeasurement) =>
  (sql: SqlStorage): CoreResult<Measurement, InvalidInput> => {
    const calendar = calendarOf(sql)
    const invalid = invalidTime(calendar, measurement.measuredAt, stamp.now)
    if (invalid !== null) return { ok: false, error: invalid }
    const row = sql
      .exec<MeasurementRow>(
        `INSERT INTO growth_measurements
           (id, measured_at, weight_g, length_cm, head_cm, version, source, created_by, created_at, updated_by, updated_at)
         VALUES (?, ?, ?, ?, ?, 1, 'app', ?, ?, ?, ?) RETURNING ${COLUMNS}`,
        crypto.randomUUID(),
        measurement.measuredAt,
        measurement.weightG,
        measurement.lengthCm,
        measurement.headCm,
        stamp.caregiverId,
        stamp.now,
        stamp.caregiverId,
        stamp.now,
      )
      .one()
    return { ok: true, response: measurementOf(row), changed: changedFrom(calendar, null, row.measured_at) }
  }

export const editMeasurement =
  (stamp: Stamp, id: string, edit: MeasurementEdit) =>
  (sql: SqlStorage): CoreResult<Measurement, NotFound | InvalidInput | MeasurementConflict> => {
    const found = measurementFor(sql, id, edit.version, "live")
    if (!found.ok) return found
    const calendar = calendarOf(sql)
    const invalid = invalidTime(calendar, edit.measuredAt, stamp.now)
    if (invalid !== null) return { ok: false, error: invalid }
    const row = sql
      .exec<MeasurementRow>(
        `UPDATE growth_measurements
         SET measured_at = ?, weight_g = ?, length_cm = ?, head_cm = ?, version = version + 1, updated_by = ?, updated_at = ?
         WHERE id = ? RETURNING ${COLUMNS}`,
        edit.measuredAt,
        edit.weightG,
        edit.lengthCm,
        edit.headCm,
        stamp.caregiverId,
        stamp.now,
        id,
      )
      .one()
    return {
      ok: true,
      response: measurementOf(row),
      changed: changedFrom(calendar, found.row.measured_at, row.measured_at),
    }
  }

const setDeletedAt =
  (stamp: Stamp, id: string, action: VersionedAction, deletedAt: Instant | null) =>
  (sql: SqlStorage): CoreResult<Measurement, NotFound | MeasurementConflict> => {
    const found = measurementFor(sql, id, action.version, deletedAt === null ? "deleted" : "live")
    if (!found.ok) return found
    const row = sql
      .exec<MeasurementRow>(
        `UPDATE growth_measurements SET deleted_at = ?, version = version + 1, updated_by = ?, updated_at = ?
         WHERE id = ? RETURNING ${COLUMNS}`,
        deletedAt,
        stamp.caregiverId,
        stamp.now,
        id,
      )
      .one()
    return {
      ok: true,
      response: measurementOf(row),
      changed: [...changedFrom(calendarOf(sql), row.measured_at, null), queryKeys.deleted],
    }
  }

export const deleteMeasurement = (stamp: Stamp, id: string, action: VersionedAction) =>
  setDeletedAt(stamp, id, action, stamp.now)

export const restoreMeasurement = (stamp: Stamp, id: string, action: VersionedAction) =>
  setDeletedAt(stamp, id, action, null)
```

import { Api, Measurement, MeasurementConflict, MeasurementEdit, NewMeasurement, VersionedAction } from "@bt/contracts"
import { Effect } from "effect"
import { HttpApiBuilder } from "effect/http-api"
import { deleteMeasurement, editMeasurement, growthOf, logMeasurement, restoreMeasurement } from "./core/growth.ts"
import { mutations, type Saved } from "./mutations.ts"
import type { Broadcast } from "./sockets.ts"

const asSavedMeasurement = Effect.map(({ record, changed }: Saved<Measurement>) => ({ measurement: record, changed }))

export const growthHandlers = (storage: DurableObjectStorage, broadcast: Broadcast) => {
  const mutate = mutations(
    storage,
    broadcast,
    Measurement,
    (saved) => new MeasurementConflict({ code: "ACTION_REPLAY_MISMATCH", current: saved }),
  )
  return HttpApiBuilder.group(Api, "growth", (handlers) =>
    handlers
      .handle("growth", () => Effect.sync(() => growthOf(storage.sql)))
      .handle("logMeasurement", ({ payload, request }) =>
        mutate(request, NewMeasurement, payload, (stamp) => logMeasurement(stamp, payload)).pipe(asSavedMeasurement),
      )
      .handle("editMeasurement", ({ params, payload, request }) =>
        mutate(request, MeasurementEdit, payload, (stamp) => editMeasurement(stamp, params.id, payload)).pipe(
          asSavedMeasurement,
        ),
      )
      .handle("deleteMeasurement", ({ params, payload, request }) =>
        mutate(request, VersionedAction, payload, (stamp) => deleteMeasurement(stamp, params.id, payload)).pipe(
          asSavedMeasurement,
        ),
      )
      .handle("restoreMeasurement", ({ params, payload, request }) =>
        mutate(request, VersionedAction, payload, (stamp) => restoreMeasurement(stamp, params.id, payload)).pipe(
          asSavedMeasurement,
        ),
      ),
  )
}
```
