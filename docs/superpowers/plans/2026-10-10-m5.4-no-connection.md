# M5.4 "No connection" Refinements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen by Andrew on 10 Oct 2026) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On a weak signal the installed app opens within about 3 s. When it can't reach the household, it says how fresh its figures are, offers Try again wherever a load failed and says why logging waits. Today turns over at the household's midnight, and Settings shows whether the phone's offline copy is this version.

**Architecture:**
- **The worker:** `pageResponse` races the network against `NETWORK_GRACE_MS` (3 s), and opens the saved shell when the network is slower (P1).
- **Freshness:** the connectivity store remembers when the household last answered a request or spoke on the live connection (P3). The No connection bar says when that was (P4).
- **Loads:** `NotLoaded` shows "Loading…", or the failure with Try again. `retryOf` refetches the queries a message depends on (P5, P6).
- **Midnight:** `useToday` gets a `refetchInterval` that lands on the household's next midnight (P7).
- **Settings:** an Offline copy section compares the page's build stamp with the worker's caches (P9).
- **Quick actions:** a line saying why they wait for Today (P8), once M1.12 has merged.

**Tech Stack:** TypeScript 5.9.3, React 19.3, TanStack Query 5.104.1, Vite 8.3.3, Vitest 4.1.11, Playwright 1.64.0 (WebKit and Chromium), oxlint 1.87.0 and oxfmt 0.72.0, Node 24.21.0. No new dependency.

## Decisions this plan makes (veto in review)

- **P1: The race to the saved copy.**
  - Pages still try the network first. If it hasn't answered within `NETWORK_GRACE_MS`, 3,000 ms, the worker opens the saved shell. If the network fails sooner, the saved shell opens at once, as before.
  - **Nothing saved, or a saved copy that can't be read:** the page keeps waiting for the network, as it did before M5.4. The timer never fails a page.
  - **The network's late answer:** it's dropped, not aborted. Aborting would mean rebuilding the navigation request, which changes its redirect mode, and Access's 302 must pass through untouched (M1.14's P5).
  - **The cost Andrew accepted:** on a slow network with an expired session, the saved app opens and shows "Sign in to continue" instead of going straight to Access. Task 1 tests it.
  - **Testing:** `sw.ts` passes `wait`, a `setTimeout` promise, so Node tests can control the timer.
- **P2: A slow-page cookie for E2E.**
  - `apps/web/preview-slow-pages.ts` holds any request that accepts `text/html` for 15 s while the cookie `bt-preview-slow-pages=1` is set.
  - The worker's install fetches `/` with `Accept: */*`, so installs aren't held.
  - It's a preview-server plugin, like `preview-sign-out.ts`, so production never runs it. `hasCookie` moves to an export there.
- **P3: When the app last heard from the household.**
  - **Two new signals:** `answered`, when a request succeeds (`client.ts` reported `reached` before), and `heard`, when the live socket opens or speaks (it reported `online` before).
  - **The states don't change:** `answered` acts as `reached`. `heard` acts as `online`, so it keeps an expired session expired.
  - **`lastHeard()`** moves on those two signals only. An error answer (`reached`: a 409, a 500 or a 503), a 401 and the browser's `online` event don't count, since none of them refreshed anything.
  - **Why the socket counts:** while it's open, every change on either phone reaches the app. So nothing shown is older than the last time the household spoke, the 30 s pong included.
  - **Reading it:** any signal that moves `lastHeard` also takes the store out of offline, which notifies. So the bar reads it through `useSyncExternalStore` on the same subscription, and it can't change unseen while the bar shows.
- **P4: The Updated sentence.**
  - It follows the bar's sentence: "Entries can't be saved or refreshed until you're back online. Updated 9:42 PM." Before anything has been heard this session, such as on a cold start offline, it's left out.
  - The time is in the household's zone, from `me`, or the phone's before `me` loads.
  - Once the household's midnight has passed, it adds the date: "Updated Oct 9, 11:30 PM."
  - `now` comes from `useNow()` in the bar's offline variant only. So the date appears at midnight, and the bar redraws once a second only while it's showing. `Date.now()` in render fails lint.
- **P5: Try again.**
  - `NotLoaded` shows "Loading…" until a query fails. Then it shows the message and an outline "Try again" button, with the same label and look as M1.12's failed saves. Andrew's previews said Retry; Try again matches the sheets.
  - While a refetch runs, the button reads "Trying again…" and is disabled. That label is its reason.
  - `retryOf` refetches every query a message depends on: `me` and `today` for Today, `last24h` for the 24-hour totals and `me` for Settings.
- **P6: Settings while `me` loads.** It showed nothing below Theme. It now shows "Loading…", and on a failure "The household's settings couldn't be loaded." with Try again. Theme is a per-phone setting, so it stays usable.
- **P7: Midnight.**
  - `useToday` sets `refetchInterval` to the time left until the household's next midnight (`untilNextDay`), from Today's own `date` and `me`'s zone.
  - TanStack recomputes it after every fetch and render, so it always aims at the next midnight.
  - When the day is already over, because the phone's clock is ahead of the household's, it asks again a minute later (`NEXT_DAY_RETRY_MS`).
  - It runs only while Today is on screen and the page is visible, since `refetchIntervalInBackground` stays off. Unlocking the phone refetches anyway.
  - No `useEffect`: the timer is TanStack's.
  - **Zone data:** in tzdata 2026c, America/Vancouver doesn't fall back on 1 Nov 2026, so the 25-hour-day test uses America/Los_Angeles. See the handoffs.
- **P8: Why logging waits.**
  - While Today or `me` hasn't loaded, M1.12's bar shows "Logging opens once Today loads." above its buttons, and each button points at it with `aria-describedby`.
  - The line goes once Today loads.
  - It lands after M1.12 merges (Task 7).
- **P9: The offline copy.**
  - Settings gets an Offline copy section, hinted "What the app opens with when there's no connection." It reads one of these:
    - "Saved for this version."
    - "An older version. It updates while the app is open online."
    - "Not saved yet."
    - "Couldn't be checked on this phone.", when Cache Storage fails
    - "Checking…", before the first answer
  - **"This version"** is the page's `bt-build` stamp (M1.14's P4). The saved copy is the worker's `bt-shell-<version>` cache.
  - **Shared names:** the app can't import the worker's modules, so `offline-copy.ts` holds `BUILD_META_NAME` and `SHELL_CACHE_PREFIX` itself. A unit test ties both to `pageMark` and `cacheName`, so renaming either side fails it.
  - It checks again every 5 s until it reads "saved".
  - It's hidden when the page has no build stamp, as in `pnpm dev`.
  - **"Older"** assumes the running page is the newer build, the usual order after a deploy. A page left open while the worker saved the next build reads the same, though its copy is newer. Reopening the app fixes both (see the M5.5 handoff).
- **P10: The parked offline-banner flake.** connectivity.spec's offline test now refuses the household's socket before going offline, as `goOfflineLikeAPhone` does. M1.11's final review parked this race, about 1 run in 100 on WebKit, with two options, and this takes the test-only one.
- **P11: The Settings spec's `getByText("Saved")`** becomes exact, since "Not saved yet." and "Saved for this version." contain it.
- **P12: Sizes,** measured on the final branch against `main` at `f816f5f`, after M1.12 merged:

  - `sw.js` goes from 2.04 to 2.16 kB (1.08 to 1.14 kB gzip).
  - The Worker bundle is unchanged at 257.65 KiB gzip.

```ts
export const SHELL_URL = "/"
export const NETWORK_GRACE_MS = 3_000
const CACHE_PREFIX = "bt-shell-"
const SAME_FILE_FOR_EVERY_ORIGIN = { ignoreVary: true }

export type SavedCopy = Pick<Cache, "match">
export type Network = (request: Request) => Promise<Response>
export type Wait = (ms: number) => Promise<void>
export type Report = (failure: Error) => void

export const cacheName = (version: string) => `${CACHE_PREFIX}${version}`

export const staleCaches = (names: readonly string[], current: string) =>
  names.filter((name) => name.startsWith(CACHE_PREFIX) && name !== current)

const savedShell = (saved: SavedCopy) => saved.match(SHELL_URL, SAME_FILE_FOR_EVERY_ORIGIN)

export const pageResponse = (request: Request, network: Network, saved: SavedCopy, wait: Wait) => {
  const answer = network(request)
  const whenUnreachable = answer.catch(async (failure: Error) => {
    const shell = await savedShell(saved)
    if (shell === undefined) throw failure
    return shell
  })
  const whenSlow = wait(NETWORK_GRACE_MS)
    .then(() => savedShell(saved))
    .then(
      (shell) => shell ?? answer,
      () => answer,
    )
  return Promise.race([whenUnreachable, whenSlow])
}

export const assetResponse = async (request: Request, network: Network, saved: SavedCopy, report: Report) => {
  const copy = await saved.match(request, SAME_FILE_FOR_EVERY_ORIGIN).catch((failure: Error) => {
    report(failure)
    return undefined
  })
  return copy ?? network(request)
}
```

```ts
export const previewSlowPages = (): Plugin => ({

  configurePreviewServer(server) {

      const isPage = request.headers.accept?.includes("text/html") ?? false
```

```ts
export type Connectivity = "online" | "offline" | "auth-required"

export type Signal = "answered" | "heard" | "reached" | "unreachable" | "signed-out" | "online" | "offline"

interface State {
  readonly network: "online" | "offline"
  readonly session: "valid" | "expired"
}

const NEXT = {
  answered: () => ({ network: "online", session: "valid" }),
  heard: (state) => ({ ...state, network: "online" }),
  reached: () => ({ network: "online", session: "valid" }),
  unreachable: (state) => ({ ...state, network: "offline" }),
  "signed-out": () => ({ network: "online", session: "expired" }),
  online: (state) => ({ ...state, network: "online" }),
  offline: (state) => ({ ...state, network: "offline" }),
} satisfies Record<Signal, (state: State) => State>

const FROM_THE_HOUSEHOLD = new Set<Signal>(["answered", "heard"])

const connectivityOf = ({ network, session }: State): Connectivity => {
  if (network === "offline") return "offline"
  return session === "expired" ? "auth-required" : "online"
}

export interface ConnectivityStore {
  readonly current: () => Connectivity
  readonly lastHeard: () => number | null
  readonly subscribe: (listener: () => void) => () => void
  readonly report: (signal: Signal) => void
}

export const createConnectivity = (online: boolean, now: () => number = Date.now): ConnectivityStore => {
  let state: State = { network: online ? "online" : "offline", session: "valid" }
  let heardAt: number | null = null
  const listeners = new Set<() => void>()
  return {
    current: () => connectivityOf(state),
    lastHeard: () => heardAt,
    subscribe: (listener) => {
      listeners.add(listener)
      return () => {
        listeners.delete(listener)
      }
    },
    report: (signal) => {
      if (FROM_THE_HOUSEHOLD.has(signal)) heardAt = now()
      const before = connectivityOf(state)
      state = NEXT[signal](state)
      if (connectivityOf(state) === before) return
      for (const listener of listeners) listener()
    },
  }
}

export const followBrowser = (store: ConnectivityStore, target: EventTarget) => {
  target.addEventListener("online", () => store.report("online"))
  target.addEventListener("offline", () => store.report("offline"))
}
```

```ts
import { localDateOf } from "@bt/domain"

const timeOf = (instant: number, timeZone: string, locale: string | undefined) =>
  new Intl.DateTimeFormat(locale, { hour: "numeric", minute: "2-digit", timeZone }).format(instant)

const dayOf = (instant: number, timeZone: string, locale: string | undefined) =>
  new Intl.DateTimeFormat(locale, { month: "short", day: "numeric", timeZone }).format(instant)

export const phoneZone = () => Intl.DateTimeFormat().resolvedOptions().timeZone

export const updatedLine = (heardAt: number, now: number, timeZone: string, locale?: string) => {
  const time = timeOf(heardAt, timeZone, locale)
  if (localDateOf(heardAt, timeZone) === localDateOf(now, timeZone)) return `Updated ${time}.`
  return `Updated ${dayOf(heardAt, timeZone, locale)}, ${time}.`
}
```

```ts
type Refetchable = Pick<UseQueryResult, "isFetching" | "refetch">

export interface Retry {

  readonly run: () => void

export const retryOf = (...queries: ReadonlyArray<Refetchable>): Retry => ({
```
