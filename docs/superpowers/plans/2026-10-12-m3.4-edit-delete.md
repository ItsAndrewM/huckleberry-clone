# M3.4 Edit and Delete Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (subagents, as Andrew chose on 12 Oct 2026) to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a parent can fix any entry once its five-second Undo has gone:
- **Where:** a diaper or a finished feed opens its edit sheet, from Today's row or from History's details. A feed still running or paused opens the Nursing sheet.
- **A diaper:** its time and kind (Pee, Poo, Both), then Save, or Delete.
- **A feed:** every side and bottle in one form. Add a forgotten one, remove one, or move the whole feed with a preview, then one Save, all or nothing.
- **A feed still going:** a timer started late gets an earlier start, and the feed can be deleted.
- **Delete:** asks first, then "Bottle deleted" (or "Diaper deleted", "Feed deleted") with Undo for five seconds.
- **The other phone's change:** the sheet keeps the parent's values, says what changed, and offers "Save mine anyway" or "Use Emily's".
- **At once:** an edit or delete shows on Today and History before the household answers, and a failure takes back only that change.

**Architecture:**
- **Contracts:** `FeedEdit` (`NewFeed`'s parts with the feed's `version`) and `PUT /api/feeds/:id` (`editFeed`).
- **The Worker:**
  - `core/feeds/feed-edits.ts`'s `editFeed` checks the parts as `logFeed` does (`log.ts`'s `invalidParts`), runs D9 against every other feed, then `store.ts`'s `replaceParts` swaps them and `saveFeed` recomputes the bounds and bumps the version
  - `rules.ts`: a `"completed"` feed state, and `segmentErrors` and `portionErrors` skip the birth-date check for a time the record already holds (`timesOf`); `diapers.ts` and `growth.ts` do the same for an unchanged time
- **The web's data:**
  - `api/actions.ts` and `send.ts`: `editFeed` and `editSegment`
  - `api/swap.ts` (pure): what an edit or delete makes of an entry, and that swap applied to Today (`swappedToday`) and to a day (`swappedDay`)
  - `api/entry-cache.ts`: the swap on Today and every cached day, and its undoing; `api/optimistic.ts` routes the four swap kinds there
  - `api/today-change.ts`: `shiftedTotals` for any period; `api/today-cache.ts`: an answer only re-lists an entry Today already shows
- **The sheets frame:**
  - `sending.ts`: the sheet kinds `"editDiaper"`, `"editFeed"` and `"undo"`; edit sheets and real deletes close as they send
  - `held.ts`, `sheets-state.ts`, `sheets-context.ts`, `sheets-provider.tsx`: each opening carries `editing` and `at`; a held failure belongs to its record's opening; `dismiss(kind)`
  - `undo.ts`: an Undo is sent on the `"undo"` sheet; a delete's toast offers Undo, which restores
  - `delete-entry.tsx`: the ask-first Delete, shared with Growth; `failure.ts`: an edit sheet's "This was deleted since it opened."
- **The edit sheets (`features/edit/`, new):** the diaper's (`edit-diaper-*`, `diaper-*`), the feed's (`edit-feed-*`, `feed-*`, `side-editor`, `bottle-editor`, `part-group`, `added-parts`), the conflict note (`stale*`, `edit-failure`) and `use-cached-entry`
- **The Nursing sheet:** `feed-start.tsx` (Started · Change), and Delete feed in the running and paused views
- **Today:** a row opens its entry (`recent-rows.ts`'s `opens`, `recent-list.tsx`'s buttons)
- **History:** `details-sheet.tsx`'s Edit, and `day-view.tsx`'s dismissal as a day leaves
- **Recovery:** `redo.ts` ("Change it anyway", "Delete anyway", `mineAnyway`), `save-changes.ts` (`feedReplay`, `measurementReplay`), `recovery.ts` (measurement conflicts), and `bottle-entry.ts`'s held route

## Decisions this plan makes (veto in review)

- **P1, the PUT replaces parts.** `PUT /api/feeds/:id {actionId, version, segments, portions}` takes a finished feed's whole set of sides and bottles. It marks the live ones deleted and inserts the ones sent, so each saved part gets a new id, and the replaced rows stay in the JSON export as a record of what the feed held. `moveFeed`, `editSegment`, `editPortion` and the part deletes stay: Undo, the running feed's start and M1.13 still use them.
- **P2, finished feeds only.** A running or paused feed answers 404 to the PUT, as a lifecycle action answers a feed in the wrong state. The Nursing sheet changes a running feed's start through `editSegment`.
- **P3, a kept time skips the birth-date check.** A diaper's `occurredAt`, a measurement's `measuredAt`, and any feed part whose start or time the feed already holds, so an entry a zone change left before the birth date can still be edited (M4.3's and M3.5's hand-off). A moved time is checked as a new one. The zone itself is left alone (P15).
- **P4, openings and their failures.**
  - Three sheet kinds join `SheetKind`: `"editDiaper"`, `"editFeed"` and `"undo"`.
  - `SheetsState` now holds `editing` and `at` (M3.7's hand-off), set by `show(sheet, record?)` and `showAt(sheet, at)`. A reopen for a held failure takes that failure's record and no time.
  - An edit sheet shows only its own record's failure (`heldFor(held, sheet, editing)`), so a failed edit of one diaper never sits in another diaper's sheet. Closing it lets its record's failure go and opens the next held entry's sheet.
  - Logging sheets keep M5.6's behaviour. Scoping them to an opening is left (P15).
- **P5, the day under the details sheet.** DayView's wrapping `<div className="contents">` takes a stable ref callback whose cleanup calls `dismiss("details")` and `dismiss("logAt")`. `detailsLeftFromAnotherDay` stays (see Found while building).
- **P6, the diaper's form.** When, then a Pee / Poo / Both choice showing the diaper's kind, then Save. A tap on a kind only picks it, unlike logging's one-tap save, so changing just the time is a Save.
- **P7, the feed's form.**
  - **Feed started:** a time field showing the earliest part. Changing it moves every side and bottle by the same minutes, and "Moves every side and bottle 1 h earlier." says how far.
  - **Each side:** a group, "Side 1", with Left / Right, Started and Minutes. **Each bottle:** "Bottle 1", with Given, Breast milk and Formula.
  - **Exactness:** a field left alone keeps its exact value, seconds included. Changed minutes count from the minute the side's start shows, so a moved switch meets the side before it.
  - **Adding and removing:** "Add a side" starts the other side where the feed ended, for 5 minutes. "Add a bottle" is given where the feed ended, with no milk yet. Each part has a remove button; with nothing left, only "Nothing is left in this feed. Delete this feed?" remains.
  - **What it won't save:** an unreadable time ("Pick a time for each side and bottle."), minutes outside 1–240, a bottle with no milk, two sides at once ("Two sides overlap. Move one so they don't."), or an end in the future. The household's own checks (the birth date, other feeds) answer through the failure note.
  - **Title:** "Edit bottle" for a feed of one bottle, otherwise "Edit feed"; Delete is named the same way.
- **P8, what shows at once.**
  - An edit or delete of a diaper or feed swaps the entry on Today (its totals, list, running and last feed) and on every cached day (its totals and records, oldest first), worked out by `totalsIn`.
  - A failure swaps the entry back in each, then Today and the days refetch. The answer's `changed` keys refetch the rest; Trends' weeks and months follow the answer.
  - Two things wait for the household: the Nursing sheet's start change, as its other controls do, and an Undo's restore, whose record arrives with the answer.
- **P9, the other phone's change.**
  - **The note:** "{Name} changed this a moment ago. It now reads: {entry}." with "Save mine anyway", which resends the same `actionId` at their version, and "Use {Name}'s", which loads theirs into the form. A delete reads "… Delete it anyway?" with "Delete anyway" and "Keep it". "{Name} deleted this a moment ago." offers OK, which closes the sheet.
  - **The Nursing sheet:** M1.13's rule adds "Change it anyway" (while that side still ends after the new start) and "Delete anyway" (while the feed still runs).
  - **Growth:** a measurement's conflict offers "Save mine anyway" (or "Save my changes" after a replay) and OK. "Use Emily's" isn't added, since the measurement form has no reset path.
- **P10, "Save my changes".** After a replay mismatch, a bottle or past feed is saved over the first save through the PUT, but only while that feed is still at version 1. The conflict answers the feed as it is now, so a feed the other phone has changed since gets no offer, and the plain note stays. A bottle added to a running feed keeps "saved as first entered": the phone never had its first values, so it can't tell which bottle was its own.
- **P11, a held bottle's route.** A bottle held after a failure keeps the route its `actionId` may already hold on the household: its own feed stays its own, and a top-up stays on its feed. A renewed sign-in draft has no receipt, so it follows today's rule.
- **P12, delete and Undo.**
  - A delete from an edit sheet or the Nursing sheet closes its sheet as it leaves. Its save shows "Diaper deleted", "Bottle deleted" (a feed of bottles only) or "Feed deleted", with Undo, which restores at the version the delete answered.
  - Undo is sent on the `"undo"` sheet (P4), as every Undo now is. So a failed Undo says "That wasn't undone." in a toast and never holds a sheet (M3.5's hand-off), and an Undo's own save shows nothing.
  - A restored entry shows when the household answers, as M3.5's restores do.
- **P13, Today's rows.** Each row is a button, unless it's still saving: a diaper opens its edit sheet, a finished feed opens the feed sheet, and a running or paused feed opens the Nursing sheet. The row's text moves into spans, since a `<p>` can't sit in a button.
- **P14, History's details.** One entry: Edit beside Close. A gathered marker: an Edit under each entry, named "Edit Diaper at 2:20 AM: Poo".
- **P15, what M3.4 leaves.**
  - Recently deleted's rows don't open the details sheet (M3.9).
  - A zone change that puts a record before the birth date isn't refused (M4.3's hand-off).
  - Logging sheets still show the first held entry of their kind on any opening (M5.6's hand-off, narrowed).
  - Sleep and doses join with M3.1 and M3.3.

## Review Focus

The five inputs most likely to bite that the spec implies but doesn't spell out, each with the test that pins it:

1. **A side's seconds:** a parent changes one field and the form must not move what they left alone, or a switch at 2:24:37 reads as an overlap. Task 6, "keeps a side's exact start when only its minutes change, so it still meets the side before", and "moves the switch earlier in one edit, counting changed minutes from the minute a side shows".
2. **Both phones edit one entry:** the second save must show what changed and let the parent choose, never overwrite silently. Task 5's E2E, "says who changed the diaper first, and saves mine on top of theirs when asked", and its "Use Emily's" partner.
3. **An edit sent with no connection:** Today and every cached day must go back exactly, and the sheet must reopen on that record. Task 3, "shows the edit on Today and the cached day at once, and puts both back exactly when it fails", and Task 5's E2E, "puts the diaper back and reopens its sheet with the reason when the edit can't be sent".
4. **An entry older than the last 24 hours, edited from History:** the answer must not drop it into Today's list. Task 3, "leaves Today's list alone when the household answers an edit to an entry it doesn't show".
5. **The day changing under another entry's details while an edit fails:** the failed edit's sheet must reopen at once, not after the next sheet closes. Task 8's E2E, "reopens a failed edit's sheet as soon as the day changes under another entry's details", which fails without the dismissal.

**Interfaces:**
- Consumes: the frame as M3.7 left it (`show`, `showAt`, `failedFor`, `toastFor`, `restoredToast`, `undoLost`).
- Produces:
  - `SheetKind` gains `"editDiaper"`, `"editFeed"` and `"undo"`; `editsARecord(sheet)`, `isUndo(sending)`
  - `closesOnSend` is true for any send from an edit sheet and for `deleteDiaper` and `deleteFeed`, never for an Undo; `closesOnSave` is never true from an edit sheet
  - `held.ts`: `recordOf(sending): string | null`, `isOnOpening(failed, sheet, editing)`, `heldFor(held, sheet, editing = null)`
  - `SheetsState` gains `editing: string | null` and `at: number | null`; `shownState(state, sheet, editing = null, at = null)`; `dismissedKindState(state, sheet)`
  - `Sheets` gains `dismiss(sheet)`, stable for a component's life; `failedFor(sheets, sheet)` passes `sheets.editing`
  - `undo.ts`: every Undo is sent on the `"undo"` sheet; `undoOf` answers a delete with its restore; `toastFor` says "Diaper deleted", "Bottle deleted" or "Feed deleted", and nothing for an Undo's own save

export interface DiaperKind {
  readonly wet: boolean
  readonly dirty: boolean
}

export interface Target {
  readonly id: string
  readonly version: number
}

export interface DiaperEditSession {
  readonly actionId: string
  readonly target: Target
  readonly when: When
  readonly kind: DiaperKind
}

export const diaperEditSession = (failed: Failed | null, diaper: Diaper, zone: string): DiaperEditSession => {
  const action = failed?.sending.action
  if (action?.kind === "editDiaper") {
    const { actionId, version, occurredAt, wet, dirty } = action.payload
    return { actionId, target: { id: action.id, version }, when: whenAt(occurredAt, zone), kind: { wet, dirty } }
  }
  const { id, version, occurredAt, wet, dirty } = diaper
  return {
    actionId: crypto.randomUUID(),
    target: { id, version },
    when: whenAt(occurredAt, zone),
    kind: { wet, dirty },
  }
}

export const diaperEdit = (session: DiaperEditSession, kind: DiaperKind, occurredAt: number): DiaperAction => ({
  kind: "editDiaper",
  id: session.target.id,
  payload: { actionId: session.actionId, version: session.target.version, occurredAt, ...kind },
})

export const diaperDelete = ({ id, version }: Target): DiaperAction => ({
  kind: "deleteDiaper",
  id,
  payload: { actionId: crypto.randomUUID(), version },
})

import { MAX_SEGMENT_MS, type PortionEntry, type SegmentEntry } from "@bt/contracts"
import { FUTURE_TOLERANCE_MS } from "@bt/domain"
import { resolveWhen, type When, whenAt } from "../../sheets/when.ts"
import { type BottlePart, type FeedDraft, minutesOf, type Parts, type SidePart } from "./feed-draft.ts"

const MINUTE_MS = 60_000
const MAX_MINUTES = MAX_SEGMENT_MS / MINUTE_MS

export type DraftIssue = "nothing" | "time" | "minutes" | "milk" | "overlap" | "future"

export type Checked<T> = { readonly ok: true; readonly value: T } | { readonly ok: false; readonly issue: DraftIssue }

const timeAt = (when: When, zone: string, now: number): Checked<number> => {
  const resolved = resolveWhen(when, zone, now)
  if (resolved.ok) return { ok: true, value: resolved.instant }
  return { ok: false, issue: resolved.issue === "in_future" ? "future" : "time" }
}

const isMinutes = (minutes: number | null): minutes is number =>
  minutes !== null && Number.isInteger(minutes) && minutes >= 1 && minutes <= MAX_MINUTES

const sameWhen = (when: When, other: When) =>
  when.kind === "at" && other.kind === "at" && when.local === other.local && when.pick === other.pick

const keptOrPicked = (when: When, base: number | null, zone: string, now: number): Checked<number> =>
  base !== null && sameWhen(when, whenAt(base, zone)) ? { ok: true, value: base } : timeAt(when, zone, now)

const endOf = ({ base, fields }: SidePart, start: number): number | null => {
  if (base !== null && fields.minutes === minutesOf(base)) return start + (base.endedAt - base.startedAt)
  return isMinutes(fields.minutes) ? Math.floor(start / MINUTE_MS) * MINUTE_MS + fields.minutes * MINUTE_MS : null
}

const sideOf = (part: SidePart, zone: string, now: number): Checked<SegmentEntry> => {
  const start = keptOrPicked(part.fields.start, part.base?.startedAt ?? null, zone, now)
  if (!start.ok) return start
  const end = endOf(part, start.value)
  if (end === null) return { ok: false, issue: "minutes" }
  return { ok: true, value: { side: part.fields.side, startedAt: start.value, endedAt: end } }
}

const bottleOf = ({ base, fields }: BottlePart, zone: string, now: number): Checked<PortionEntry> => {
  const { breastMilkMl, formulaMl } = fields
  if (breastMilkMl === null || formulaMl === null || breastMilkMl + formulaMl <= 0) return { ok: false, issue: "milk" }
  const at = keptOrPicked(fields.at, base?.occurredAt ?? null, zone, now)
  return at.ok ? { ok: true, value: { occurredAt: at.value, breastMilkMl, formulaMl } } : at
}

const overlapping = (segments: ReadonlyArray<SegmentEntry>) =>
  segments
    .toSorted((a, b) => a.startedAt - b.startedAt)
    .some((segment, index, sorted) => index > 0 && segment.startedAt < (sorted[index - 1]?.endedAt ?? 0))

const valuesOf = <T>(checked: ReadonlyArray<Checked<T>>) => checked.flatMap((one) => (one.ok ? [one.value] : []))

const partsIssue = ({ segments, portions }: Parts, now: number): DraftIssue | null => {
  if (segments.length + portions.length === 0) return "nothing"
  if (overlapping(segments)) return "overlap"
  return segments.some(({ endedAt }) => endedAt > now + FUTURE_TOLERANCE_MS) ? "future" : null
}

export const checkedParts = (draft: FeedDraft, zone: string, now: number): Checked<Parts> => {
  const sides = draft.sides.map((part) => sideOf(part, zone, now))
  const bottles = draft.bottles.map((part) => bottleOf(part, zone, now))
  const failed = [...sides, ...bottles].find((one) => !one.ok)
  if (failed !== undefined && !failed.ok) return failed
  const parts = { segments: valuesOf(sides), portions: valuesOf(bottles) }
  const issue = partsIssue(parts, now)
  return issue === null ? { ok: true, value: parts } : { ok: false, issue }
}

export const ISSUES = {
  nothing: "",
  time: "Pick a time for each side and bottle.",
  minutes: "Give each side 1 to 240 minutes.",
  milk: "Give each bottle some breast milk or formula.",
  overlap: "Two sides overlap. Move one so they don't.",
  future: "That would end in the future.",
} as const satisfies Record<DraftIssue, string>

import { resolveWhen, type When, whenAt } from "../../sheets/when.ts"
import { formatMinutes } from "../today/format.ts"
import type { BottlePart, FeedDraft, SidePart } from "./feed-draft.ts"

const ANY_TIME = Number.POSITIVE_INFINITY
const MINUTE_MS = 60_000

const instantOf = (when: When, zone: string) => {
  const resolved = resolveWhen(when, zone, ANY_TIME)
  return resolved.ok && Number.isFinite(resolved.instant) ? resolved.instant : null
}

const shifted = (when: When, zone: string, offset: number): When => {
  const instant = instantOf(when, zone)
  return instant === null ? when : whenAt(instant + offset, zone)
}

const keptOrPicked = (when: When, base: number | undefined, zone: string) =>
  base !== undefined && instantOf(when, zone) === Math.floor(base / MINUTE_MS) * MINUTE_MS
    ? base
    : instantOf(when, zone)

const sideStart = ({ base, fields }: SidePart, zone: string) => keptOrPicked(fields.start, base?.startedAt, zone)

const bottleTime = ({ base, fields }: BottlePart, zone: string) => keptOrPicked(fields.at, base?.occurredAt, zone)

export const startOf = (draft: FeedDraft, zone: string): number | null => {
  const times = [
    ...draft.sides.map((part) => sideStart(part, zone)),
    ...draft.bottles.map((part) => bottleTime(part, zone)),
  ]
  const known = times.filter((time) => time !== null)
  return known.length === 0 ? null : Math.min(...known)
}

const movedSide = ({ key, base, fields }: SidePart, zone: string, offset: number): SidePart => ({
  key,
  base: base === null ? null : { ...base, startedAt: base.startedAt + offset, endedAt: base.endedAt + offset },
  fields: { ...fields, start: shifted(fields.start, zone, offset) },
})

const movedBottle = ({ key, base, fields }: BottlePart, zone: string, offset: number): BottlePart => ({
  key,
  base: base === null ? null : { ...base, occurredAt: base.occurredAt + offset },
  fields: { ...fields, at: shifted(fields.at, zone, offset) },
})

export const movedDraft = (draft: FeedDraft, zone: string, offset: number): FeedDraft => ({
  sides: draft.sides.map((part) => movedSide(part, zone, offset)),
  bottles: draft.bottles.map((part) => movedBottle(part, zone, offset)),
})

export const movedBy = (draft: FeedDraft, zone: string, when: When): number | null => {
  const start = startOf(draft, zone)
  const to = instantOf(when, zone)
  return start === null || to === null ? null : to - Math.floor(start / MINUTE_MS) * MINUTE_MS
}

export const moveText = (offset: number) => {
  if (offset === 0) return null
  const by = formatMinutes(Math.abs(offset) / 1000)
  return `Moves every side and bottle ${by} ${offset > 0 ? "later" : "earlier"}.`
}
