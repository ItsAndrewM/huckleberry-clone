# M3.10 Trends Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (chosen by Andrew on 12 Oct 2026) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Trends tab shows how much she eats and how many diapers she goes through. A week or a month is a bar a day, with each chart's average and the days it covers. A single day climbs hour by hour against her usual day.

**Architecture:**
- **The domain** (`packages/domain/src/trends/`, pure, held at 100 % coverage):
  - `dayStatus` says what a day is: it counts (finished, with a feed or a diaper), is today, has no entries, falls before her birth, or is still to come.
  - `averageDay` averages the days that count and says how many.
  - `runningTotals` climbs through a day, one series per chart, and ends exactly on `totalsIn`'s totals.
  - `time/calendar.ts`'s ISO weeks become plain UTC arithmetic, so a week reads right in any zone, Playwright's clock included (P2, corrected in the post-review notes).
- **The model** (`apps/web/src/features/trends/*.ts`, run in Node tests):
  - the period and its address, and the titles
  - the four metrics and the numbers beside each chart
  - the bars' rows and paint, and the table's rows
  - her usual day, and the Day view's hours
- **The charts** (TanStack Charts, M4.5's pin):
  - A week or a month is a bar a day, stacked for nursing and bottles, with a target for each day so every column picks its own day.
  - A day is a line that climbs through it, with a dashed rule at her usual day.
- **The screen** (`apps/web/src/features/trends/*.tsx`):
  - the Day, Week and Month switch, the period stepper, the picked day's line, a section per metric, and "Show as a table"
  - It reads M3.6's week and month answers through new `useWeek` and `useMonth`, and M3.7's `useDay` for the Day view.

## Decisions this plan makes (veto in review)

- **P1: Order.**
  - Tasks 1–5 build everything pure on `main` alone: the ISO-week fix, the domain, the model and the chart definitions.
  - Task 6 waits for M3.6's merge (gate A), and Tasks 6–7 build the Week and Month views and picking.
  - Task 8 waits for M3.7's merge (gate B), and adds the Day view and the links to History.
  - Task 9 writes the docs. One PR.
- **P2: ISO weeks in UTC arithmetic.**
  - `isoWeekOfDate` and the Monday lookup used date-fns' `getISOWeek`, `setISOWeek` and `startOfISOWeek` on an `@date-fns/tz` UTC `TZDate`. In the Vite browser bundle those ran in the phone's own zone; a probe showed `setISOWeek` drifting by the DST hour. So in Vancouver, `isoWeekOfDate("2026-10-05")` gave `2026-W40`, and `isIsoWeek("2026-W41")` was false.
  - Contracts' `IsoWeek` calls `isIsoWeek`, so a phone west of UTC refused every `WeekPeriod` answer and skipped `["week", …]` keys in `changed`. Node and workerd (UTC) were right, so nothing server-side was wrong, and nothing on the phone read a week before M3.10.
  - Task 1 replaces both with the Thursday rule and the Monday on or before 4 January, in `Date.UTC` arithmetic. `calendar.ts` drops its date-fns and `@date-fns/tz` imports. No other domain code ran date-fns on a `TZDate`: `zone.ts` calls `tzOffset` on a plain `Date`.
  - date-fns stays a domain dependency, as the oracle Task 1's test checks every date from 1999 to 2100 against.
  - **Corrected after review (13 Oct 2026):** the misread was never the browser bundle. Under Playwright's clock, the fake `Date` breaks `TZDate`, a `Date` subclass, so date-fns read the page's zone. With a phone's own `Date`, every week read right in every zone. See the post-review notes.
- **P3: What a day is** (Andrew, 12 Oct 2026, for the averages).
  - A day has entries when any of its totals is above zero: a feed started, nursing (a side carried past midnight included), a bottle or a diaper. A measurement alone doesn't count; Growth charts it.
  - Its status, in order: after today, today, before her birth, then counted or no entries. Her birth date can be today.
  - An average divides each total by the days that count, and says how many. `null` when none count.
- **P4: The numbers beside each chart.**
  - Worded as Today's card: "Feeds started", "Nursing" with "Left 52 min · Right 48 min", "Bottles" with "Breast milk … · Formula …", "Diapers" with "6 pee · 3 poo". A part that's zero is left out.
  - An average reads "8 a day, over 4 days"; counts keep one decimal ("7.5 a day"), minutes are floored as Today's are, and mL are whole (fl oz to one decimal).
  - With nothing to average, a period holding today says "No finished day yet", and an earlier one "No entries".
  - A picked day shows its own numbers: "1 h 20 min", "No entries", or "3 so far" for today.
- **P5: The bars.**
  - A bar a day, stacked in part order: Left then Right, Breast milk then Formula. Feeds and diapers are one bar.
  - The first part is `var(--primary)`, the second a 45 % mix with the background. Today's bars are mixed to 55 % of that and outlined with a dashed accent, so "so far" isn't colour alone.
  - With a day picked, every other day fades to 30 %, and the picked day's weekday or date label turns bold.
  - The y axis starts at 0, is niced, and is at least 4 feeds, 60 minutes, 100 mL (4 fl oz) or 4 diapers tall, so a quiet day still reads. Three y ticks; no y axis line.
  - x labels: a week's weekdays ("Mon"); a month's 1st, 8th, 15th, 22nd and 29th.
  - 150 px tall, like four rows of the Today card. Measured at 393 px: everything fits in one scroll per chart.
- **P6: Picking a day** (Andrew, 12 Oct 2026).
  - Each day up to today (counted, with no entries, or today) has a zero-size `day-target` dot at its column's foot, so a tap anywhere in the column reaches it. Its reach is 24 px, half a week's column: a tap over a day still to come does nothing.
  - `focus: "group-x"` gives one keyboard stop per day; Enter picks it. A crosshair band shows the focused day instead of a focus ring.
  - The picked day is page state, kept per period: stepping to another period lets it go.
  - Tapping it again, or ×, brings back the averages. Switching to Day opens the picked day.
  - The picked line, `<output>`, names the day, so a screen reader hears it; the bars themselves carry no names (TanStack's focus is virtual).
- **P7: The address.**
  - `/trends` is this week. `?view=month` or `?view=day` picks the view, and `?date=` any date in the period.
  - The period holding today leaves the date out, so it follows the household's midnight through the minute clock, as History does.
  - A date after today, or before her birth, is moved inside them. "‹" stops at the period holding her birth date, "›" at the current one.
  - Switching views keeps today in view from the current period, and otherwise lands on the period holding the shown one's first day.
- **P8: Titles.** "Oct 12 – 18" (`formatRange`), "October 2026", "Tue, Oct 13". Under it: "This week, so far" for the current period, or a "Back to this week" link.
- **P9: The Day view** (Andrew, 12 Oct 2026).
  - Its lines are worked out on the phone from the day's records, up to the minute clock, as M3.7 draws a running feed. Counts and bottles climb in steps; nursing climbs while a side runs. The last point equals what `totalsIn` gives for the day.

  - The x axis marks 12 AM, 6 AM, 12 PM, 6 PM and the next 12 AM on the household's clock, through `resolveLocal`, so the clocks changing moves no tick.
  - The lines take no focus; the numbers beside each chart carry the values.

## Review Focus

The five ways this is most likely to fail a parent, each with the test that pins it:

1. **A phone west of UTC opening a week** (in the specs, under Playwright's clock; see the post-review notes).
   - It must read the week, not say "This week couldn't be loaded".
   - Pinned by `calendar.test.ts` ("numbers every week as date-fns does in UTC…", Task 1) and every `trends.spec.ts` test, which runs in Vancouver (Task 6).
2. **Today pulling the average down.**
   - At 9 AM, the week's average must not count today's half-day, nor a day with nothing logged.
   - Pinned by `days.test.ts` ("averages only finished days with entries…", Task 2) and `trends.spec.ts` ("opens on this week, so far…", "leaves a day with nothing logged out…", Task 6).
3. **A tap landing on the wrong day.**
   - A tap on a day with no bar must pick that day, and a tap on a day still to come nothing.
   - Pinned by `trends-charts.test.ts` ("lets a day with nothing logged be picked…", "lets each day up to today be picked…", Task 5) and `trends.spec.ts` ("picks today, and a finished day with nothing logged…", Task 7).
4. **A feed running, or one carried past midnight, in the Day view.**
   - The line must count only the part inside the day, up to now, and end on the day's totals.
   - Pinned by `running.test.ts` ("starts with the nursing a feed from the day before carried past midnight…", "follows a side that's still running up to now", and the property over every zone, Task 2).
5. **The nights the clocks change.**
   - The Day view's ticks stay on their hours, and its line ends on the day's totals.
   - Pinned by `trends-rows.test.ts` ("keeps each tick at its hour on the day the clocks go back", Task 4) and `running.test.ts`'s property across clock changes (Task 2).

```ts
export type DayStatus = "before-birth" | "no-entries" | "counted" | "today" | "after-today"

export interface DatedTotals {
  readonly date: LocalDate
  readonly totals: Totals
}

export interface DayAverage {
  readonly totals: Totals
  readonly days: number
}

export const hasEntries = ({ feedsStarted, nursingSeconds, bottleMl, diapers }: Totals): boolean =>
  feedsStarted + nursingSeconds + bottleMl + diapers > 0

export const dayStatus = ({ date, totals }: DatedTotals, today: LocalDate, birthDate: LocalDate): DayStatus => {
  if (date > today) return "after-today"
  if (date === today) return "today"
  if (date < birthDate) return "before-birth"
  return hasEntries(totals) ? "counted" : "no-entries"
}

const meanOf = (all: ReadonlyArray<Totals>): Totals => {
  const mean = (pick: (totals: Totals) => number) => all.reduce((sum, totals) => sum + pick(totals), 0) / all.length
  return {
    feedsStarted: mean((totals) => totals.feedsStarted),
    leftSeconds: mean((totals) => totals.leftSeconds),
    rightSeconds: mean((totals) => totals.rightSeconds),
    nursingSeconds: mean((totals) => totals.nursingSeconds),
    breastMilkMl: mean((totals) => totals.breastMilkMl),
    formulaMl: mean((totals) => totals.formulaMl),
    bottleMl: mean((totals) => totals.bottleMl),
    diapers: mean((totals) => totals.diapers),
    wetDiapers: mean((totals) => totals.wetDiapers),
    dirtyDiapers: mean((totals) => totals.dirtyDiapers),
  }
}

export const averageDay = (
  days: ReadonlyArray<DatedTotals>,
  today: LocalDate,
  birthDate: LocalDate,
): DayAverage | null => {
  const counted = days.filter((day) => dayStatus(day, today, birthDate) === "counted")
  return counted.length === 0 ? null : { totals: meanOf(counted.map(({ totals }) => totals)), days: counted.length }
}
```

```ts
import type { DiaperChange, StartedFeed } from "../aggregate/totals.ts"
import type { Side } from "../feed/feed.ts"
import { clipTo, contains } from "../interval/interval.ts"
import { type Instant, type Interval, SECOND_MS } from "../time/instant.ts"

export interface RunningPoint {
  readonly at: Instant
  readonly value: number
}

export interface RunningTotals {
  readonly feedsStarted: ReadonlyArray<RunningPoint>
  readonly nursingSeconds: ReadonlyArray<RunningPoint>
  readonly bottleMl: ReadonlyArray<RunningPoint>
  readonly diapers: ReadonlyArray<RunningPoint>
}

interface Step {
  readonly at: Instant
  readonly amount: number
}

interface Nursed extends Interval {
  readonly side: Side
}

const endOf = (period: Interval, now: Instant, lastAt: Instant) => Math.max(Math.min(now, period.end), lastAt)

const tenths = (ml: number) => Math.round(ml * 10) / 10

const climb = (period: Interval, now: Instant, steps: ReadonlyArray<Step>, read: (sum: number) => number) => {
  const inPeriod = steps.filter(({ at }) => contains(period, at)).toSorted((a, b) => a.at - b.at)
  const points: RunningPoint[] = [{ at: period.start, value: 0 }]
  let sum = 0
  for (const { at, amount } of inPeriod) {
    points.push({ at, value: read(sum) })
    sum += amount
    points.push({ at, value: read(sum) })
  }
  points.push({ at: endOf(period, now, inPeriod.at(-1)?.at ?? period.start), value: read(sum) })
  return points
}

const nursedIn = (period: Interval, feeds: ReadonlyArray<StartedFeed>, now: Instant): Nursed[] =>
  feeds
    .flatMap((feed) =>
      feed.segments.flatMap(({ side, startedAt, endedAt }) => {
        const piece = clipTo({ start: startedAt, end: endedAt ?? now }, period)
        return piece === null ? [] : [{ side, ...piece }]
      }),
    )
    .toSorted((a, b) => a.start - b.start)

const nursing = (period: Interval, feeds: ReadonlyArray<StartedFeed>, now: Instant) => {
  const pieces = nursedIn(period, feeds, now)
  const elapsedMs = { left: 0, right: 0 }
  const seconds = () => Math.floor(elapsedMs.left / SECOND_MS) + Math.floor(elapsedMs.right / SECOND_MS)
  const points: RunningPoint[] = [{ at: period.start, value: 0 }]
  for (const { side, start, end } of pieces) {
    points.push({ at: start, value: seconds() })
    elapsedMs[side] += end - start
    points.push({ at: end, value: seconds() })
  }
  points.push({ at: endOf(period, now, pieces.at(-1)?.end ?? period.start), value: seconds() })
  return points
}

const counted = (sum: number) => sum

export const runningTotals = (
  period: Interval,
  feeds: ReadonlyArray<StartedFeed>,
  diapers: ReadonlyArray<DiaperChange>,
  now: Instant,
): RunningTotals => ({
  feedsStarted: climb(
    period,
    now,
    feeds.map(({ startedAt }) => ({ at: startedAt, amount: 1 })),
    counted,
  ),
  nursingSeconds: nursing(period, feeds, now),
  bottleMl: climb(
    period,
    now,
    feeds.flatMap(({ portions }) =>
      portions.map(({ occurredAt, breastMilkMl, formulaMl }) => ({ at: occurredAt, amount: breastMilkMl + formulaMl })),
    ),
    tenths,
  ),
  diapers: climb(
    period,
    now,
    diapers.map(({ occurredAt }) => ({ at: occurredAt, amount: 1 })),
    counted,
  ),
})
```

```ts
import type { IsoWeek, LocalDate, YearMonth } from "@bt/contracts"
import { addDaysToDate, isoWeekMonday, isoWeekOfDate, monthOfDate, nextMonth } from "@bt/domain"

export type TrendsView = "day" | "week" | "month"

export type TrendsPeriod =
  | { readonly view: "day"; readonly date: LocalDate }
  | { readonly view: "week"; readonly week: IsoWeek }
  | { readonly view: "month"; readonly month: YearMonth }

export const periodOf = (view: TrendsView, date: LocalDate): TrendsPeriod => {
  if (view === "day") return { view, date }
  return view === "week" ? { view, week: isoWeekOfDate(date) } : { view, month: monthOfDate(date) }
}

export const firstDateOf = (period: TrendsPeriod): LocalDate => {
  if (period.view === "day") return period.date
  return period.view === "week" ? isoWeekMonday(period.week) : `${period.month}-01`
}

export const lastDateOf = (period: TrendsPeriod): LocalDate => {
  if (period.view === "day") return period.date
  return period.view === "week"
    ? addDaysToDate(isoWeekMonday(period.week), 6)
    : addDaysToDate(`${nextMonth(period.month)}-01`, -1)
}

export const holds = (period: TrendsPeriod, date: LocalDate) =>
  firstDateOf(period) <= date && date <= lastDateOf(period)

export const periodBefore = (period: TrendsPeriod): TrendsPeriod =>
  periodOf(period.view, addDaysToDate(firstDateOf(period), -1))

export const periodAfter = (period: TrendsPeriod): TrendsPeriod =>
  periodOf(period.view, addDaysToDate(lastDateOf(period), 1))

export const periodId = (period: TrendsPeriod) => `${period.view}:${firstDateOf(period)}`
```

```ts
  const view = period.view === "week" ? {} : { view: period.view }

}

  period,
  isCurrent: holds(period, today),
  previous: firstDateOf(period) <= birthDate ? null : searchFor(periodBefore(period), today),
  next: holds(period, today) ? null : searchFor(periodAfter(period), today),
  current: searchFor(periodOf(period.view, today), today),
})

  const anchor = picked ?? (holds(from, today) ? today : firstDateOf(from))
```

```ts
import type { LocalDate, VolumeUnit } from "@bt/contracts"
import type { DayStatus } from "@bt/domain"
import type { TrendsMetric } from "./metrics.ts"
import type { TrendDay } from "./trends-numbers.ts"

export interface BarRow {
  readonly key: string
  readonly date: LocalDate
  readonly value: number
  readonly fill: string
  readonly soFar: boolean
}

export interface DayTarget {
  readonly date: LocalDate
}

const PART_SHADES = [100, 45] as const
const SO_FAR = 0.55
const FADED = 0.3

const DRAWN: ReadonlySet<DayStatus> = new Set(["counted", "today"])
const PICKABLE: ReadonlySet<DayStatus> = new Set(["counted", "no-entries", "today"])

export const dayTargets = (days: ReadonlyArray<TrendDay>): ReadonlyArray<DayTarget> =>
  days.flatMap(({ date, status }) => (PICKABLE.has(status) ? [{ date }] : []))

const shade = (percent: number) =>
  percent >= 100 ? "var(--primary)" : `color-mix(in oklab, var(--primary) ${Math.round(percent)}%, var(--background))`

const fillOf = (part: number, day: TrendDay, picked: LocalDate | null) => {
  const base = PART_SHADES[part] ?? PART_SHADES[1]
  if (picked !== null && picked !== day.date) return shade(base * FADED)
  return shade(day.status === "today" ? base * SO_FAR : base)
}

export const barRows = (
  metric: TrendsMetric,
  days: ReadonlyArray<TrendDay>,
  volume: VolumeUnit,
  picked: LocalDate | null,
): ReadonlyArray<BarRow> =>
  days.flatMap((day) =>
    DRAWN.has(day.status)
      ? metric.parts.flatMap((part, index) => {
          const value = metric.plotted(part.amount(day.totals), volume)
          const row = {
            key: `${day.date}:${part.key}`,
            date: day.date,
            value,
            fill: fillOf(index, day, picked),
            soFar: day.status === "today",
          }
          return value > 0 ? [row] : []
        })
      : [],
  )

export const tallestDay = (rows: ReadonlyArray<BarRow>) => {
  const byDate = new Map<LocalDate, number>()
  for (const { date, value } of rows) byDate.set(date, (byDate.get(date) ?? 0) + value)
  return Math.max(0, ...byDate.values())
}
```

```ts
  days.map((day) => ({ date: day.date, totals: day.totals, status: dayStatus(day, today, birthDate) }))

const overDays = (days: number) => `over ${days} ${days === 1 ? "day" : "days"}`

export const averageNumbers = (
  metric: TrendsMetric,
  average: DayAverage | null,
  volume: VolumeUnit,
  isCurrent: boolean,
): Numbers => {
  if (average === null) return { value: isCurrent ? "No finished day yet" : "No entries", detail: [] }
  const value = metric.format(metric.total(average.totals), volume)
  return { value: `${value} a day, ${overDays(average.days)}`, detail: metric.detail(average.totals, volume) }
}

export const usualText = (metric: TrendsMetric, usual: DayAverage | null | undefined, volume: VolumeUnit) => {
  if (usual === undefined) return null
  if (usual === null) return "No usual day yet"
  return `Usual ${metric.format(metric.total(usual.totals), volume)}, ${overDays(usual.days)}`
}

export const dayNumbers = (metric: TrendsMetric, day: TrendDay, volume: VolumeUnit): Numbers => {
  if (day.status === "no-entries") return { value: "No entries", detail: [] }
  const value = metric.format(metric.total(day.totals), volume)
  return { value: day.status === "today" ? `${value} so far` : value, detail: metric.detail(day.totals, volume) }
}
```

```ts
import type { IsoWeek, LocalDate } from "@bt/contracts"
import { addDaysToDate, averageDay, type DatedTotals, type DayAverage, isoWeekOfDate } from "@bt/domain"

const DAYS_BEFORE = 7

export const usualWeeks = (date: LocalDate): readonly [IsoWeek, IsoWeek] => [
  isoWeekOfDate(addDaysToDate(date, -DAYS_BEFORE)),
  isoWeekOfDate(addDaysToDate(date, -1)),
]

export const usualDay = (
  weeks: ReadonlyArray<ReadonlyArray<DatedTotals> | undefined>,
  date: LocalDate,
  today: LocalDate,
  birthDate: LocalDate,
): DayAverage | null | undefined => {
  const loaded = weeks.flatMap((days) => (days === undefined ? [] : [days]))
  if (loaded.length < weeks.length) return undefined
  const earliest = addDaysToDate(date, -DAYS_BEFORE)
  const before = loaded.flat().filter((day) => day.date >= earliest && day.date < date)
  const once = new Map(before.map((day) => [day.date, day] as const))
  return averageDay([...once.values()], today, birthDate)
}
```
