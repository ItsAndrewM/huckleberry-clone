# M1.8 Today and the Last 24 Hours Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (chosen by Andrew on 9 Oct 2026) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A parent who opens the app sees today at a glance. Today's totals (feeds started, nursing per side, bottles, diapers), the running or paused feed, the last feed, what to prefill for the next bottle and side, and every feed and diaper from the last 24 hours with who logged it. A second endpoint gives the same totals for the last 24 hours. Both read the household as it is at that moment.

**Architecture:** `packages/domain` gains `aggregate/totals.ts`. `totalsIn(period, feeds, diapers, now)` totals any period by M1.2's rules, and `last24hPeriod(now)` is the last 24 hours, with no end. `packages/contracts` gains the `Today` and `Last24h` responses and a `today` group in `Api`, and `/api/me` gains the household's caregiver names. In the Worker, `core/today.ts` loads with the lower bound only (`core/feeds/reads.ts`, `liveDiapersSince`) and lets the domain apply each period exactly. `http.ts` answers `GET /api/today` and `GET /api/last24h` from it. First, the Worker tests' shared clock and helpers move into shared modules, as M1.7's review asked.

**Tech Stack:** TypeScript 5.9.3, `effect` 4.0.1 (Schema, `effect/http`, `effect/http-api`), `@bt/contracts`, `@bt/domain`, Workers and Durable Objects (`@cloudflare/workers-types` 5.20261006.1, wrangler 4.148.0), `@cloudflare/vitest-plugin` 1.3.7, Vitest 4.1.11, fast-check 4.10.2, Playwright 1.64.0, oxlint 1.87.0 + oxfmt 0.72.0, Node 24.21.0. No new dependencies.

## Decisions this plan makes (veto in review)

- **P1: `GET /api/today` answers `{ date, totals, activeFeed, lastFeed, prefill, recent }`.**
  - `date` is the household's local date now, in its time zone, not UTC's or the phone's.
  - `totals` covers that local day (P3).
  - `activeFeed` is the live active feed, running or paused, or null. It's found by its status (the M1.7 handoff), so a feed paused long ago still shows.
  - `lastFeed` is the live feed that started last, which can be the active one, or null. M1.11's "Since last feed started" counts from its `startedAt`. A feed backdated after a newer one doesn't replace it.
  - `prefill` is D13's. `lastBottle` holds the breast milk and formula of the latest live bottle of a live feed, and `lastSide` is the side of the latest live segment of a live feed. Each is null when there's none, and the sheets decide what to offer from them.
  - `recent` is P4.
  - There's no active sleep and no last supplement yet. Their tables arrive in M3.1 and M3.3, which add them as new fields. An installed app running older code ignores a field it doesn't know (M1.5's P7).
- **P2: `GET /api/last24h` answers `{ from, totals }`: the same totals over the last 24 hours, and nothing else** (Andrew, 9 Oct 2026).
  - The last 24 hours start 24 hours before now and have no end (`last24hPeriod`). An entry a phone logged up to 5 minutes ahead of the household's clock (AC 21) then counts at once. A period ending at now would leave a diaper logged a moment ago out until the clock caught up, even with a phone that runs half a second fast.
  - `from` says when the 24 hours began, by the household's clock.
- **P3: The totals are `feedsStarted`, `leftSeconds`, `rightSeconds`, `nursingSeconds`, `breastMilkMl`, `formulaMl`, `bottleMl`, `diapers`, `wetDiapers` and `dirtyDiapers`** (§3.1, and the M1.2 and M1.7 handoffs).
  - A feed counts in the period its start falls in. The row's "Feeds started today" label is `feedsStarted`, so a feed across midnight counts once.
  - Nursing counts by each live segment's overlap with the period. A running side runs to now, and a side started ahead of the clock counts nothing yet.
  - A bottle counts by its own time, and a diaper by its time. A diaper that's wet and dirty counts once in `diapers` and once in each of the other two.
  - Only live parts of live feeds, and live diapers, count.
  - Seconds are whole: each side's time is summed across feeds, then rounded down. Amounts are rounded to 0.1 mL. These are `feedSummary`'s rules.
- **P4: Today's recent list is every live feed that started, and every live diaper, from 24 hours before now on (P2's period), newest first** (Andrew, 9 Oct 2026).
  - Each entry is `{ kind: "feed", feed }` or `{ kind: "diaper", diaper }`. A feed is placed by its start.
  - The list holds whole records, with `createdBy` and `updatedBy`. P5 names those caregivers.
- **P5: Caregiver names come once, in `/api/me`, as `household.caregivers`.**
  - Each is `{ id, displayName }`, for every caregiver in seed order, disabled ones included, so older entries keep a name.
  - Records keep naming caregivers by id (the M1.6 handoff). M3's day, week and history screens need the same names, and `/api/me` gives them once a session.
- **P6: The domain computes the totals.**
  - `aggregate/totals.ts` holds `totalsIn(period, feeds, diapers, now)` and `last24hPeriod(now)`, and `interval/` gains `contains`. They're pure, held to 100 % coverage, and the client can reuse them for optimistic previews (§3.4).
  - That's why diapers are counted there rather than with the M1.6 handoff's `SUM(wet)`.
  - A period is an interval, so one function serves today (`zonedDayBounds`) and the last 24 hours. A segment is clipped to the period with `clipTo`. For a day that's the piece `splitByDays` gives that date, and a property test holds the two together (the M1.2 handoff).
- **P7: The Worker loads with the lower bound only, and the domain applies each period exactly.**
  - `liveFeedsSince` loads, with all their live parts, the live feeds whose session reaches the earlier of today's start and 24 hours ago. A running feed always does.
  - `liveDiapersSince` loads the live diapers from then on.
  - Loading whole feeds keeps each feed's start and every part, so the domain can count a feed on its start and still give today the part of yesterday's feed after midnight.
  - The feeds query reads every feed's `ended_at`, as D9's query reads every segment. See the M5.5 handoff.
- **P8: The endpoints are `GET /api/today` and `GET /api/last24h`, in a `today` group added after `me`.**
  - They take no input and answer 200, no-store, like everything the household answers. The caller check answers a stranger 401.
  - Each reads the clock once, as the request comes in.
- **P9: The Worker tests' shared helpers move into shared modules before another endpoint test file lands** (M1.7's deferred minor).
  - `test/fixtures.ts` holds the clock, the shared keys and the core helpers.
  - `test/requests.ts` holds the HTTP helpers.
  - `test/feed-fixtures.ts` keeps what only the feed tests use.
- **P10: The runtime's time-zone data is pinned** (the M1.2 handoff).
  - workerd reports `GMT-07:00` for America/Vancouver on 2 November 2026, as tz 2026b says. Node 24.21.0 ships tz 2026c.
  - A Worker test now fails if a runtime puts 00:30 on 2 November back on the 1st.
- **P11: GET responses aren't receipts, so M1.5's 24-hour rule for stored responses doesn't apply to `Today` and `Last24h`.** An installed app running older code still decodes a response only while fields are added, never removed or renamed, and no union gains a member. A new kind in `recent` is a new member of `RecentEntry`, not an added field, so the app decodes `recent` one entry at a time (see the M1.10 handoff).
- **P12: The Worker bundle grows from 250.26 to 252.01 KiB gzip,** well under the 400 KiB budget.

## Review Focus

1. **A feed across midnight** (AC 4). Expect the new day to get only the nursing after midnight and the bottles given after it, and the feed to count on the day it started, once. Tested in Tasks 2 and 5.
2. **A running side.** Expect Today to count it up to now and keep counting as the clock moves, and to answer its feed as the active and the last feed. Tested in Tasks 2, 5 and 6.
3. **Something the other parent deleted:** a whole feed, a segment, a bottle or a diaper. Expect it left out of the totals, the recent list, the last feed and the prefill, which falls back to the bottle and side before it. Tested in Task 5.
4. **A phone whose clock runs a few minutes fast** (AC 21). Expect an entry it logged to show at once, in the recent list and in both totals. Tested in Tasks 2, 5 and 6.
5. **The household's day, not UTC's.** Expect 11:30 pm to still be today, 23- and 25-hour days to be totalled in full (AC 23), and Vancouver to stay on UTC−7 after 1 November 2026 (tz 2026b). Tested in Tasks 2 and 5.

Each protection above was mutation-checked while this plan was written, 13 mutations in all, and each was caught: the clipping to the period, the running side, counting a feed by its start, each deleted filter, ordering the last feed by its start, the open end of the last 24 hours, loading from the earlier of today's start and 24 hours ago, taking the day in the household's zone, and reading the clock per request.

import { clipTo, contains } from "../interval/interval.ts"
import { DAY_MS, type Instant, type Interval } from "../time/instant.ts"

export interface StartedFeed extends FeedComponents {
  readonly startedAt: Instant
}

export interface DiaperChange {
  readonly occurredAt: Instant
  readonly wet: boolean
  readonly dirty: boolean
}

export interface Totals extends FeedSummary {
  readonly feedsStarted: number
  readonly diapers: number
  readonly wetDiapers: number
  readonly dirtyDiapers: number
}

export const last24hPeriod = (now: Instant): Interval => ({ start: now - DAY_MS, end: Number.POSITIVE_INFINITY })

const nursedIn = (period: Interval, segment: NursingSegment, now: Instant): NursingSegment[] => {
  const piece = clipTo({ start: segment.startedAt, end: segment.endedAt ?? now }, period)
  return piece === null ? [] : [{ side: segment.side, startedAt: piece.start, endedAt: piece.end }]

  segments: feeds.flatMap((feed) => feed.segments.flatMap((segment) => nursedIn(period, segment, now))),

import type { Diaper, Feed, Last24h, RecentEntry, Today } from "@bt/contracts"
import { contains, type Instant, type Interval, last24hPeriod, localDateOf, totalsIn, zonedDayBounds } from "@bt/domain"
import { calendarOf } from "./calendar.ts"
import { liveDiapersSince } from "./diapers.ts"
import { lastFeed, liveFeedsSince, prefillOf } from "./feeds/reads.ts"
import { activeFeed } from "./feeds/rules.ts"

const timeOf = (entry: RecentEntry): Instant => (entry.kind === "feed" ? entry.feed.startedAt : entry.diaper.occurredAt)

const recentIn = (period: Interval, feeds: ReadonlyArray<Feed>, diapers: ReadonlyArray<Diaper>): RecentEntry[] =>
  [
    ...feeds.map((feed) => ({ kind: "feed" as const, feed })),
    ...diapers.map((diaper) => ({ kind: "diaper" as const, diaper })),
  ]
    .filter((entry) => contains(period, timeOf(entry)))
    .toSorted((a, b) => timeOf(b) - timeOf(a))

export const todayOf = (sql: SqlStorage, now: Instant): Today => {
  const { zone } = calendarOf(sql)
  const date = localDateOf(now, zone)
  const day = zonedDayBounds(date, zone)
  const last24h = last24hPeriod(now)
  const from = Math.min(day.start, last24h.start)
  const feeds = liveFeedsSince(sql, from)
  const diapers = liveDiapersSince(sql, from)
  return {
    date,
    totals: totalsIn(day, feeds, diapers, now),
    activeFeed: activeFeed(sql) ?? null,
    lastFeed: lastFeed(sql),
    prefill: prefillOf(sql),
    recent: recentIn(last24h, feeds, diapers),
  }
}

export const last24hOf = (sql: SqlStorage, now: Instant): Last24h => {
  const period = last24hPeriod(now)
  const totals = totalsIn(period, liveFeedsSince(sql, period.start), liveDiapersSince(sql, period.start), now)
  return { from: period.start, totals }
}
