# M1.4 Worker Entry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, chosen by Andrew on 8 Oct 2026) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** No `/api/*` request reaches the household Durable Object until Cloudflare Access has vouched for it. The Worker checks the Access JWT in production, or `ctx.access` locally, drops any client-sent `x-bt-*` header, and forwards the verified email as `x-bt-email`.

**Architecture:** A thin entry over three small modules. `access.ts` turns a request into a `Caller`: a user, a service token, unauthenticated, or keys-unavailable. It reads `ctx.access` first and otherwise verifies `Cf-Access-Jwt-Assertion` with `jose`. `api.ts` routes on the caller: a refusal, the `/api/login` redirect, the admin gate, or the household. `error-response.ts` encodes the contract's errors. `index.ts` wires them to `ctx.access`, `env` and a minimal `HouseholdDO` that M1.5 fills in. `access.dev` in `wrangler.jsonc` signs local runs in.

**Tech Stack:** TypeScript 5.9.3, `jose` 6.2.12, `effect` 4.0.1 (Schema), `@bt/contracts`, Workers and Durable Objects (`@cloudflare/workers-types` 5.20261006.1, wrangler 4.148.0, `@cloudflare/vite-plugin` 1.63.0), `@cloudflare/vitest-plugin` 1.3.7, Vitest 4.1.11, Playwright 1.64.0, oxlint 1.87.0 + oxfmt 0.72.0.

## Decisions this plan makes (veto in review)

- **P1: E2E stays on `vite preview`.** M1.1 (P6) asked M1.4 to check whether preview applies `access.dev`, and to switch to `wrangler dev` if it doesn't. It does: under both `vite preview` and `vite dev` the Worker gets `ctx.access` with the stub's `aud` and identity, and no JWT header. §6's E2E row changes to say so.
- **P2: Tests hand the Worker an Access context, not a whole `ExecutionContext`.** The M1.4 row says tests call `fetch` with a hand-built `ctx`. But `ExecutionContext` now also requires `exports`, `tracing` and `abort`, and lint bans the `as unknown as ExecutionContext` the spike used. So `fetch` passes only `ctx.access` to `callerOf`, and the tests build that two-member object. The entry itself is tested through `SELF`, whose real context has no `access`, because the test pool ignores `access.dev` (S5).
- **P3: The Worker reduces Access's answer to one of four callers:** `user` (a lowercased email), `service` (a service token's Client ID, from `common_name`), `unauthenticated` and `keys-unavailable`. Claims are decoded with an Effect schema, not `typeof` checks. A user is never the admin and a service token never acts as a caregiver, which is D6's "never a caregiver identity".
- **P4: Access settings are decoded before jose sees them.** jose skips its issuer or audience check when that option is `undefined`, and a var missing from `wrangler.jsonc` is `undefined`. So a missing or empty `ACCESS_AUD`, or an `ACCESS_TEAM_DOMAIN` that isn't an exact https origin, refuses every token. `Env` declares the three vars optional to say the same.
- **P5: When the Worker can't fetch Cloudflare's signing keys, the answer is 503 `ServiceUnavailable`, not 401.** A 401 tells the app to sign in again, which can't help while `<team>/cdn-cgi/access/certs` is unreachable, and would loop. Only "no key in the set matches this token" stays a token problem (401).
- **P6: `/api/login` redirects to an absolute URL on the request's own origin, built by the URL parser.** The parser reads the return path the way a browser will: it strips tabs and newlines and reads `\` as `/`. So `/\t/evil.test`, which passes the spike's string check and which a browser then reads as `//evil.test`, resolves to evil.test and is refused. An absolute `Location` also keeps `/.//evil.test` a path on this origin, instead of the scheme-relative `//evil.test`. Any verified caller may use it, as in the spike.
- **P7: The Worker answers only with contract errors** (the M1.3 handoff): 401 `Unauthorized`, 404 `NotFound` and 503 `ServiceUnavailable`, encoded from `@bt/contracts`. A caregiver on `/api/admin/*`, or a service token on a caregiver route, gets 401. The spike answered the first with 403 `Forbidden`, which the contract doesn't have.
- **P8: M1.4 adds a minimal `HouseholdDO`:** the `HOUSEHOLD` binding, the `v1` SQLite migration, and a `fetch` that answers 404 `NotFound` to everything until M1.5 gives it routes. That makes "forward to DO" real, and lets E2E prove the whole path: `access.dev`, the Worker, the DO. The admin service token also gets 404 once past the gate, until admin routes exist.
- **P9: The vars.** `ACCESS_TEAM_DOMAIN` is the real team domain, which survived the spike teardown. `ACCESS_AUD` and `ADMIN_SERVICE_TOKEN_CN` stay empty until M1.16 creates the production app and the admin token. Until then a deployed Worker would refuse every request, and only `access.dev` signs anyone in.
- **P10: The `access.dev` identity is `andrew@example.test`.** M1.5's local seed has to create that caregiver.

## Review Focus

1. **A missing var turning a check off.** jose skips its audience check when `audience` is `undefined`, and a var missing from `wrangler.jsonc` is `undefined`. A token for any other Access app in the same team would then sign its holder in. Expect every token refused while `ACCESS_AUD` or `ACCESS_TEAM_DOMAIN` is missing, empty or malformed. Tested in Task 1.
2. **A sign-in link that lands somewhere else.** A phishing link to `…/api/login?return=/%09/evil.test` gets past a string check, and after a real Google sign-in the browser drops the tab and opens evil.test. Expect every return path that leaves the origin to land on `/`, in a real browser too. Tested in Tasks 2 and 3.
3. **A sign-in loop during an Access outage.** If the Worker can't fetch Cloudflare's signing keys, a 401 tells the app to sign in again; Access says the parent already is, and the app lands back on the same 401. Expect a 503, which the app can retry. Tested in Tasks 1 and 2.
4. **A parent locked out by a capital letter.** Google can return `Andrew@Gmail.com` while the caregivers table (M1.5) holds lowercase. Expect the email forwarded in lowercase, whether it came from a JWT or from `ctx.access`. Tested in Task 1.
5. **One parent posing as the other.** A request that carries `X-BT-Email: emily@…`, in any case, repeated, or under another `x-bt-` name, must not reach the DO with it. Expect exactly one `x-bt-email`: the verified one. Tested in Task 2.

```ts
  type JWTPayload,

  UnsecuredJWT,

import { type AccessSettings, callerOf } from "../src/access.ts"

const TEAM = "https://bt-test.cloudflareaccess.com"
const AUD = "bt-test-aud"
const SETTINGS: AccessSettings = { ACCESS_TEAM_DOMAIN: TEAM, ACCESS_AUD: AUD }

let keys: JWTVerifyGetKey
let privateKey: CryptoKey

beforeAll(async () => {
  const pair = await generateKeyPair("RS256", { extractable: true })
  privateKey = pair.privateKey
  keys = createLocalJWKSet({ keys: [{ ...(await exportJWK(pair.publicKey)), kid: "k1", alg: "RS256" }] })

  readonly issuer?: string
  readonly audience?: string | string[]
  readonly expiresIn?: string
  readonly keyId?: string
}

const sign = (claims: JWTPayload, options: TokenOptions = {}) =>
  new SignJWT(claims)
    .setProtectedHeader({ alg: "RS256", kid: options.keyId ?? "k1" })
    .setIssuer(options.issuer ?? TEAM)
    .setAudience(options.audience ?? AUD)
    .setIssuedAt()
    .setExpirationTime(options.expiresIn ?? "1h")

  new Request("https://bt.example.test/api/me", { headers: { "cf-access-jwt-assertion": token } })

  aud: "bt-local",
  getIdentity: async () => identity,
```

```ts
import { Option, Schema } from "effect"
import { createRemoteJWKSet, errors, jwtVerify, type JWTPayload, type JWTVerifyGetKey } from "jose"

export type Caller =
  | { readonly kind: "user"; readonly email: string }
  | { readonly kind: "service"; readonly clientId: string }
  | { readonly kind: "unauthenticated" }
  | { readonly kind: "keys-unavailable" }

export interface AccessSettings {
  readonly ACCESS_TEAM_DOMAIN?: string
  readonly ACCESS_AUD?: string
}

export type AccessKeysFor = (teamDomain: string) => JWTVerifyGetKey

const UNAUTHENTICATED: Caller = { kind: "unauthenticated" }
const KEYS_UNAVAILABLE: Caller = { kind: "keys-unavailable" }

const Origin = Schema.String.check(
  Schema.makeFilter((value: string) => URL.parse(value)?.origin === value, {
    expected: "an origin like https://team.cloudflareaccess.com",
  }),
)

const JwtSettings = Schema.Struct({ ACCESS_TEAM_DOMAIN: Origin, ACCESS_AUD: Schema.NonEmptyString })
const jwtSettingsOf = Schema.decodeUnknownOption(JwtSettings)

const Claims = Schema.Struct({ email: Schema.optional(Schema.String), common_name: Schema.optional(Schema.String) })
const claimsOf = Schema.decodeUnknownOption(Claims)

const callerFrom = ({ email, common_name }: typeof Claims.Type): Caller => {
  if (email !== undefined && email !== "") return { kind: "user", email: email.toLowerCase() }
  if (common_name !== undefined && common_name !== "") return { kind: "service", clientId: common_name }
  return UNAUTHENTICATED
}

const callerFromClaims = (claims: JWTPayload | CloudflareAccessIdentity): Caller =>
  Option.match(claimsOf(claims), { onNone: () => UNAUTHENTICATED, onSome: callerFrom })

class AccessKeysUnavailable extends Error {}

const reportingOutages =
  (keys: JWTVerifyGetKey): JWTVerifyGetKey =>
  async (header, token) => {
    try {
      return await keys(header, token)
    } catch (error) {
      if (error instanceof errors.JWKSNoMatchingKey || error instanceof errors.JWKSMultipleMatchingKeys) throw error
      throw new AccessKeysUnavailable("Cloudflare Access signing keys are unavailable", { cause: error })
    }
  }

const verifiedCaller = async (
  token: string,
  settings: typeof JwtSettings.Type,
  keys: JWTVerifyGetKey,
): Promise<Caller> => {
  try {
    const { payload } = await jwtVerify(token, reportingOutages(keys), {
      issuer: settings.ACCESS_TEAM_DOMAIN,
      audience: settings.ACCESS_AUD,
      algorithms: ["RS256"],
    })
    return callerFromClaims(payload)
  } catch (error) {
    return error instanceof AccessKeysUnavailable ? KEYS_UNAVAILABLE : UNAUTHENTICATED
  }
}

export const callerOf = async (
  request: Request,
  access: CloudflareAccessContext | undefined,
  settings: AccessSettings,
  keysFor: AccessKeysFor,
): Promise<Caller> => {
  const identity = await access?.getIdentity()
  if (identity !== undefined) return callerFromClaims(identity)
  const token = request.headers.get("cf-access-jwt-assertion")
  const jwt = jwtSettingsOf(settings)
  if (token === null || Option.isNone(jwt)) return UNAUTHENTICATED
  return verifiedCaller(token, jwt.value, keysFor(jwt.value.ACCESS_TEAM_DOMAIN))
}

const remoteKeys = new Map<string, JWTVerifyGetKey>()

export const remoteAccessKeys: AccessKeysFor = (teamDomain) => {
```

Create `apps/worker/src/api.ts`:

```ts
import { NotFound, ServiceUnavailable, Unauthorized } from "@bt/contracts"
import type { Caller } from "./access.ts"
import { errorResponse } from "./error-response.ts"

export type Household = (request: Request) => Promise<Response>

const INTERNAL_HEADER_PREFIX = "x-bt-"

const forHousehold = (request: Request, email: string): Request => {
  const headers = new Headers([...request.headers].filter(([name]) => !name.startsWith(INTERNAL_HEADER_PREFIX)))
  headers.set("x-bt-email", email)
  return new Request(request, { headers })
}

const sameOriginTarget = (url: URL): string => {
  const requested = url.searchParams.get("return") ?? "/"
  const target = requested.startsWith("/") ? URL.parse(requested, url.origin) : null
  return target?.origin === url.origin ? target.href : `${url.origin}/`
}

const loginRedirect = (url: URL): Response =>
  new Response(null, { status: 302, headers: { location: sameOriginTarget(url), "cache-control": "no-store" } })

const isAdmin = (caller: Caller, adminClientId: string | undefined): boolean =>
  caller.kind === "service" && adminClientId !== undefined && adminClientId !== "" && caller.clientId === adminClientId

export const routeApi = (
  request: Request,
  caller: Caller,
  household: Household,
  adminClientId: string | undefined,
): Response | Promise<Response> => {
  if (caller.kind === "keys-unavailable") return errorResponse(new ServiceUnavailable())
  if (caller.kind === "unauthenticated") return errorResponse(new Unauthorized())
  const url = new URL(request.url)
  if (url.pathname === "/api/login") return loginRedirect(url)
  if (url.pathname.startsWith("/api/admin/")) {
    return errorResponse(isAdmin(caller, adminClientId) ? new NotFound() : new Unauthorized())
  }
  if (caller.kind === "service") return errorResponse(new Unauthorized())
  return household(forHousehold(request, caller.email))
}
```

- `forHousehold` builds the forwarded headers through a filter. Deleting from a `Headers` while iterating it can skip the entry after each one deleted: the Fetch spec allows it and Node does it, though workerd doesn't. `unicorn/no-useless-spread` also rejects the copy-first loop.
- `sameOriginTarget` resolves the return path with the URL parser and sends the absolute result (P6). `URL.parse` returns `null` where `new URL` would throw, as it does for `//`.
